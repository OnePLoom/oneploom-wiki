# 관측 기록의 범위와 날짜

## 기록 시각과 작업일

관측 문서의 파일명은 실제 기록 시각을 KST로 표시하며 `YYYY-MM-DD_HH-MM-SS` 형식을 쓴다. 본문은 날짜만 필요하면 `YYYY-MM-DD`, 시각이 필요하면 `YYYY-MM-DD HH:MM:SS KST`로 적는다. 공통 기준은 [문서 관리 — 「날짜와 시각 표기」](../development/documentation.md)가 소유한다.

실제 UTC 실행 식별자와 설계 작업일을 구분한다. 초기 묶음 개선은 11/21 구현/부분 검사가 시작됐고 11/22 실제 전후 비교가 진행됐다. 기록 시각을 한국 시각으로 표시하면서 날짜가 바뀌어도 작업일이나 사용자 실행 시점을 바꾸지 않는다. 뒤늦은 정정은 당시 파일을 과거와 다르게 고치는 대신 현재 설명에서 구분한다.

## 공개된 자료와 재현 한계

이 WIKI의 `evidence/experiments` 파일은 실험 조건, 결과와 한계를 설명하는 관측 문서다. 본문의 로그, JSON과 스크립트명은 관측에 사용한 자료를 식별하는 설명이다. 실제 파일이 제공되지 않은 이름에는 다운로드 링크를 붙이지 않는다. 관측 문서 사이의 링크는 조건/결과 설명으로, 제목 링크는 해당 절로 이동한다. 이 기록만으로 과거 실행 전체를 재현할 수는 없다. 제품 검증에는 독립 실행 가능한 fixture, 실제 명령/설정과 결과를 준비해야 한다.

수치와 오류, PASS/FAIL의 적용 범위를 변경하지 않는다. 같은 조건의 단건 비교는 그 한 쌍의 관측이며 보편적 성능/요금 절감률이 아니다. 설명용 예시와 실제 원본, 모의 중단과 자연 발생 장애, 정적 검사와 사용자 조작을 구분한다.

## 예제 식별자와 측정값

기준 구현의 모듈/패키지/테스트 이름과 검색 문자열 일부는 `sample-*`, `org.example`, `QUERY_A` 같은 설명용 식별자로 바꿨다. 원래 명령을 그대로 실행할 수 있는 공개 fixture를 제공한 것이 아니다. 테스트 개수, 바이트/행 수, 토큰/시간, 실패 및 판정은 원래 관측값을 보존한다. 식별자를 바꾼 공개 문장으로 같은 토큰 측정이 재현된다고 주장하지 않는다.

기존 구현의 원문 대신 관측 문서로 연결한 링크에는 그 역할을 표시한다. 실제 제품에는 해당 프로젝트의 코드/문서/테스트 이름을 기본값으로 넣지 않는다. 설치 시 탐지와 승인된 매핑을 통해 적용 프로젝트의 구조에 연결하는 설계는 별도 계약이다.
