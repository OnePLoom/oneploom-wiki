# 예비 검사의 방법과 한계

## SQLite 제약 검사

검토용 SQL을 메모리 DB에 적용해 정상 삽입, 식별자/외래키와 상태 제약, 재시도/인계/정리 순서의 실패 입력을 대조했다. 메모리 DDL의 PASS는 파일 내구성, 실제 Windows 잠금, 중단 후 복구나 제품 설치의 성공을 의미하지 않는다. [저장 규칙](../design/workflow/storage.md), [SQL 초안](../design/workflow/schema.sql), [수용 입력](../verification/acceptance.md)에 검증해야 할 계약을 연결한다.

## 시작 인자 검사

프로세스 인자와 종료 상태를 관측하는 예비 실행으로 전용 시작 명령의 실행 대상/권한 전달을 확인했다. 실제 TUI와 계정/모델 요청은 별도 관측이며 인자 파싱만으로 성공 처리하지 않았다. [실행 명세](../design/runtime/entry.md)와 [실제 관측](README.md)을 함께 본다.

현재 파일은 방법 설명이며 과거 스크립트의 대체 실행 파일이 아니다. 정식 제품 검증에는 독립 실행 가능한 fixture와 실제 명령을 준비해야 한다.
