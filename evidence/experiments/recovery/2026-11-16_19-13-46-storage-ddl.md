# SQLite DDL의 부분 검사

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 지정 작업일: 2026-11-16. 설계의 관계/제약을 시험하는 개인 근거다. 제품 설치기나 실제 Windows 복원의 성공 기록이 아니다.

## 입력과 수행

[현재 DDL](../../../design/workflow/schema.sql)과 [검사 도구](../../methods.md)를 사용했다. 당시 최종 원본은 SQL 사본 기록, 검사 소스 사본 기록에 고정했다. 입력은 작은 가상 작업/계획/시도이며 실제 사용자 코드, 문서, 자격증명과 모델을 사용하지 않았다.

첫 24개 사례는 최초 출력 기록의 OK다. 이후 의미 검토에서 완료에 사용한 결과에 근거를 뒤늦게 추가하지 못하도록 보강했다. 이에 맞춰 사례와 외래키 부모 키의 전체 대조를 추가한 29개는 두 번째 출력 기록의 OK다. 이어 이전 계획 누락 사례를 더 직접적으로 보강했다. 최신 계획만 복원한 상태에서 완료가 차단되고, 이전 계획까지 복원하면 통과하는 것을 최종 출력 기록의 29개 OK로 확인했다. 실패를 숨긴 재실행이 아니며 최초 소스/결과도 first에 보존했다.

```sh
python3 -B final/storage.py --schema final/schema.sql
```

위 명령은 이 기록 폴더에서 실행할 때의 재현 명령이다. DB는 메모리 안에만 만들고 기존 state.db를 읽거나 수정하지 않는다. 환경, 결과와 범위는 메타데이터 기록, 파일 보존 기준은 체크섬 기록에 있다.

## 확인한 범위

| 대상 | 관측 |
| --- | --- |
| 키/종류/소유 | NULL/빈 ID, 없는 부모, 다른 작업/계획, 다른 시도의 근거와 복원 참조를 거부 |
| 필수 의무와 관측 | 의무/선택 결과 누락, 미실행 PASS, fresh 정책의 재사용, 확정 실패 뒤집기를 차단 |
| 중복과 저장 경계 | 관측의 두 시작점/분기 거부. 오래된 revision에서 자식 변경까지 명시적 rollback. SQL 문장 실패만으로 전체 취소되지 않음을 확인 |
| 단위와 전체 복원 | 성공 기록 보존, 별도 복원 결과 연결. 이전 계획의 적용 누락, 준비 상태를 무반영으로 가정한 완료와 사용 검사 누락을 차단 |
| 자료 보존 | 사용한 계획/완료 근거 변경을 거부. 이름 변경은 두 위치를 요구. 인계 수신 식별/확인 없이 전환 기록을 만들지 못함 |

## 한계와 다음 검증

WSL Python 3.10.12, SQLite 3.37.2의 메모리 DB에서 실행했다. Python 3.12+ 연결 API나 Windows 지원 선언이 아니다. 파일 journal, 실제 강제 종료/복원/두 DB 인계, 동시 쓰기와 외부 사용자 편집, old-version 읽기/쓰기 호환을 검증하지 않았다. 시험 파일의 내용 비교나 실제 테스트 명령 실행도 하지 않았다.

JSON/보고서는 SQL 연결을 검사하기 위한 최소 가상 자료다. SQL이 허용한 기록이라고 제품의 JSON/의미 검사를 통과하거나 실제 실행 사실이 입증된 것은 아니다. [SQL 밖의 필수 검사 — 「SQL 밖에서 반드시 검사할 것」](../../../design/workflow/storage.md)와 [수용 기준 — 「SQL 저장 규칙의 검증 입력」](../../../verification/acceptance.md)을 별도로 유지한다.
