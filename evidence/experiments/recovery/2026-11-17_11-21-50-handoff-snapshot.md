# 최초 DB 위치 전환 B의 메모리 검사

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 지정 작업일: 2026-11-17. B 채택 후 인계 관계와 일반 쓰기 진입 조건을 설계 DDL/개인 probe에서 확인했다. 제품 설치기나 Windows 인계 구현은 아니다.

## 변경과 관측

초기 설치 DB의 같은 형식 사본을 새 후보에 만들고 논리 DB ID, 작업/시도, revision과 이력을 보존한다. `handoffs.side` 대신 단계 상태를 사용하며 실제 원본/대상은 공통 쓰기 진입의 별도 입력으로 대조한다. 초기 원본은 `prepared → released`, 대상은 `prepared → received → active` 순서다.

현재 인계 행만 고정 내용 지문에서 제외한다. 해당 인계의 시도 행과 나머지 스키마/기록은 포함하며, 마지막 대조 뒤 대상 활성화와 시도 종료를 같은 트랜잭션에서 저장한다. 후속 작업이 쌓인 뒤의 재요청은 초기 전체 지문으로 현재 DB를 되돌리지 않는다.

| 검사 | 통과 수 | 자료 |
| --- | --- | --- |
| 저장 제약 | 29 | 출력 기록, 소스 기록 |
| 유지 관리 제약 | 29 | 출력 기록, 소스 기록 |
| 유지 관리 관계/사본 회귀 | 7 | 출력 기록, 소스 기록 |
| B 인계 관계/공통 진입 예제 | 16 | 출력 기록, 소스 기록 |

총 81개 통과. 현재 검사 DDL 기록, 실행 인자/환경 기록, 체크섬 기록을 보존했다. WSL Python 3.10.12와 SQLite 3.37.2의 메모리 DB다.

B의 16개는 전체 사본/과거 전환 보존, 복사 중 예외, 단계 저장 실패 후 재개, 동일 요청 재사용, 다른 내용/단계 거부, 준비/수신/원본 확인 상태의 일반 쓰기 차단, 옛 초기 사본의 재시작 차단, 후속 업데이트 기록과 초기 사본 없이 계속하기를 포함한다. 현재 보호/정리 이력과 정상 변경 거부도 대조했다.

첫 15개 통과 뒤 지문에 현재 인계 시도까지 포함하도록 보강했다. 이전 소스 기록과 출력 기록은 그대로 보존하고 영향받은 인계 검사만 16개로 다시 실행했다. 다른 세 검사 입력은 변하지 않았다. 이 수정은 실패 은폐나 과거 결과 교체가 아니다.

## 범위와 남은 검증

- 원본/대상은 시험용 식별 값을 주입했다. 실제 경로/파일 ID, 실행 소유, Windows 잠금과 모든 제품 저장 호출부를 검증하지 않았다.
- 중단은 Backup API 진행 콜백 또는 저장 도중 예외로 주입했다. 실제 프로세스 종료, 연결/전원/디스크 장애나 내구성 시험과 구별한다.
- 유지 관리 고정 fixture를 현재 형식 2와 과거 1→2 전환 상태로 구성했다. 숫자는 합성 입력이며 실제 지원 형식 변환 코드가 아니다. 사본은 일반 제약을 유지한 연결로 검사했다.
- DB 밖의 실제 원문/후보/복원 파일은 복사하지 않았다. 필요한 파일 목록, 내용/위치/소유, 원본/대상 유실과 전체 설치/복원은 후속이다.
- 모델 호출, 원격 저장소 변경이나 토큰 비용 측정은 없다. 사용자 DB, 제품 추적 파일과 Git/index를 변경하지 않았다.

이전 행별 수신의 6개는 현재 B 결과에 더하지 않는다. 판단 이력은 [행별 수신안 — 「최초 기록의 행별 수신안」](../../../discussions/history/install.md)에 있고, 변경 직전 저장 설명 기록, 인계 설명 기록, DDL 기록을 보존했다. 현행 설계는 [인계 단계와 쓰기 허용](../../../design/workflow/storage.md)에 있다.
