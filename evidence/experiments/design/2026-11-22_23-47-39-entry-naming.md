# 제품명과 프로젝트 설치 위치 후보

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

## 범위와 상태

사용자 지정 2026-11-22 작업이다. 4단계 파일별 변경 명세에서 직접 접근 실행기의 제품/명령 이름과 프로젝트 설치 위치를 구체화했다. Condharness와 `tools/<제품명>/`를 추천하며 **사용자 선택 전**이다. 두 공식 Codex 설치 지원, 프로젝트 안 실행본, Git 릴리스 + Python, `.harness/` 로컬 상태 정책은 기존 결정을 유지한다.

소유 문서는 [명명 후보 — 「제품명과 명령 이름 후보」](../../../design/module.md)와 [설치 위치 후보 — 「프로젝트 설치 위치 후보」](../../../design/runtime/install.md)다. entry, 수용 입력, 변경 명세와 진행표를 연결했다. 구현, 설치/명령 등록, 저장소 생성, 새 AI/Windows 실행은 없다. 기존 제품/설정/실험 자료를 변경하지 않는다.

작업 전 백업은 2026-11-22 23:46:57 KST 생성 백업(식별자 `gva6ilro`)이며 체크섬 확인 뒤 수정했다. 직전 권한 재사용 설계의 CLOSED/STATIC_PASS는 반복 실행하지 않았다. 현재 검사는 아래 결과 파일을 따른다.

## 이름 조회와 한계

query_names.py 기록은 인증 없는 공개 GET 요청만 수행한다. name-check.json 기록에 실제 반환 상태와 관측 한계를 저장했다. 두 후보 `condharness`, `harnesslane` 모두 GitHub 공개 저장소 이름 검색 200/0건/incomplete_results=false, PyPI와 npm 패키지 조회 404였다.

웹 도구의 PyPI cache miss/npm 접근 불가와 샌드박스 DNS 실패를 먼저 관측했다. 이후 실행 도구의 네트워크 승인을 받아 같은 조회를 완료했다. 조회 실패를 이름 부재로 해석하지 않았으며 계정 인증, 패키지 설치, 이름 예약/등록은 없다.

이 조회는 비공개 저장소, 미색인 이름, 모든 코드 식별자, 사용자의 로컬 명령, 상표까지 확인하지 않는다. 404는 등록 가능성의 보증이 아니며 배포 전 재확인과 설치 시 실제 셸/경로 충돌 검사가 필요하다. 이름의 법적 사용 가능성을 확인한 자료가 아니다.

## 판단과 자료

- 추천 Condharness는 조건부 하네스라는 역할이 드러나며 AI 제공자나 WIKI 기능에 고정되지 않는다. Harnesslane은 발음/인상이 비교적 쉽지만 조건부라는 차이를 별도로 설명해야 한다. 두 의견은 명명 판단이며 외부 표준이 아니다.
- [Harness](https://www.harness.io/products/try/software-delivery-agent), [Gateweave](https://gateweave.com/), [ScopeWeave](https://scopeweave.com/)의 기존 사용을 확인했다. 해당 이름은 공개 제품/명령 후보에서 제외했다. 이들 제품 코드나 문구, 로고를 가져오지 않았다.
- [PowerShell 명령 우선순위](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_command_precedence): alias/function이 프로그램보다 먼저 선택될 수 있고 `Get-Command -All`로 같은 이름의 명령을 확인할 수 있다. 명시 경로 호출과 충돌 검사 설계의 근거다.
- [Codex skill 발견](https://learn.chatgpt.com/docs/build-skills#where-to-save-skills): 프로젝트 `.agents/skills` 탐색, 같은 이름의 비병합을 확인했다. 현재 설치 폴더 후보의 출처이며 실제 제품 발견 성공을 뜻하지 않는다.
- [Codex AGENTS 탐색](https://learn.chatgpt.com/docs/agent-configuration/agents-md): 프로젝트 경로에 따른 지침 탐색 때문에 tools에만 지침을 두는 것으로 전체 연결을 보장하지 않는다.
- [Codex hook 발견](https://learn.chatgpt.com/docs/hooks#where-codex-looks-for-hooks): 여러 출처의 일치 hook 실행, JSON/TOML 중복 등록의 비용을 확인했다. 실제 기존 등록과 신뢰를 보존해야 한다.

공식 문서의 plugin 권장과 우리 프로젝트 적용본 소유 정책을 구별했다. 이번 조사로 배포 수단을 변경하지 않는다. 로컬 Windows npm 메타데이터는 0.171.0/bin.codex=bin/codex.js/Apache-2.0이었고 패키지 README를 읽었다. 실행 파일이나 설정을 실행/수정하지 않았으며 현재 버전을 제품 고정값으로 사용하지 않는다.

## 검증과 다음 작업

check_documents.py 기록가 새 범위의 제목/링크/형식과 백업 밖 변경, 제품 382개 파일, Git HEAD/index/status, 닫힌 근거를 대조한다. entry의 JSON 예시가 바뀌지 않았다면 이전 정적 PASS만 재사용한다. 문서 결과 기록, 의미 검토 기록, 진행 상태 기록, 체크섬 기록이 판정 원본이다.

정적 검사와 사용자 환경의 명령 충돌/발견/권한 실행 검증은 다르다. 실제 Windows 제품 검증은 [수용 입력 — 「명명과 설치 위치의 검증 입력」](../../../verification/acceptance.md)으로 남긴다. 다음은 사용자가 이름과 기본 위치를 선택한 뒤 단축 명령 등록, 프로젝트별 설치본 탐색과 명시 경로 호출의 연결을 명세하고 5단계 개발 준비로 넘기는 것이다.
