# MCP 읽기 범위 보완의 내부 관측과 검증 기준 수정

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

## 결과와 적용 범위

사용자 지정 2026-11-18 작업이다. **배포 환경 동등성 검증 미완료이며 이번 시험은 배포 적합성의 근거로 채택하지 않는다.** 사용자는 문서 전체/지정 구간을 MCP로 읽어도 누락/범위 오해 없이 확보해야 한다고 확인했고, 모든 검증을 실제 배포 코드와 설정, 제한, 사용자 상호작용에 맞추라고 재확인했다.

별도 시험본에 임의의 응답/파일/검색 상한을 넣어 진행한 것은 이 목적에 맞지 않았다. 작은 값으로 코드 경계를 확인하는 내부 검사와 배포 사용 검증을 구별해야 한다. 사용자 지적 뒤 그 제한으로 추가 시험하는 작업은 중지했다. 다음은 [실제 사용 환경과 검증 조건](../../../design/workflow/verification.md)을 먼저 확인하는 것이다. 부족한 근거를 새로운 임시 숫자나 모델 없는 호출로 대체하지 않는다.

## 실행한 것

| 관측 | 결과와 한계 |
| --- | --- |
| 첫 Windows 읽기 검사 | 9개 검사 중 4개 오류. 원문이 그대로여도 stat/fstat의 ctime 차이를 변경으로 잘못 판정 |
| 파일 정보 진단 | 같은 파일의 경로/핸들 조회에서 st_ctime_ns가 달랐고 st_birthtime_ns는 일치. 생성 시각을 명시적으로 사용하도록 수정 |
| 같은 검사 재실행 | 9개 PASS. 전체/18행 읽기, UTF-8/줄바꿈, 끝/빈 파일, 예산 경계, 파일/연결 변경, 경로/junction, 121개 파일 검색, cursor 변화와 오류를 합성 자료로 확인. 배포 기능 PASS가 아님 |
| SDK STDIO 검사 | 96번째 호출에서 FAIL. SDK 클라이언트 반환 객체를 직렬화한 크기는 8,211바이트, 임의 시험 예산은 8,192바이트 |
| 실패 요청 한 건 진단 | 수기 구성한 결과는 8,187바이트, SDK 클라이언트 객체에는 resultType=complete가 추가돼 24바이트 차이. 측정 대상은 클라이언트 객체이며 원시 전송 크기나 Codex 수신 토큰으로 확대하지 않음 |
| 실제 Codex/AI 재검증 | 미실행. 모델 호출 0회. 이전 실제 비교의 두 답변 PARTIAL을 변경하지 않음 |

초기 실패와 당시 코드는 `initial/`, SDK 실패 당시 코드는 `sdk-first/`, 현재 별도 시험 코드는 `source/`에 있다. `unit.json`, `sdk.json`, 두 진단 JSON으로 실제 실행 범위와 실패를 확인한다. 합성 파일과 이전 시험 사본에서 복사한 자료만 사용했다. 기존 사본, 기존 MCP 시험 세션, 사용자 설정과 기존 시험 프로젝트 원문은 수정하지 않았다.

Windows Python 3.13.9와 이미 설치된 공식 MCP SDK 2.3.0을 사용했다. SDK/의존성 설치나 업데이트는 하지 않았다. 이전 [패키지/라이선스 확인](2026-11-18_15-21-34-mcp-read.md)을 재사용하며 SDK는 MIT, 이번 코드에 외부 구현 본문을 반입하지 않았다. 이는 최종 제품의 의존성/재배포 검토 완료가 아니다.

## 잘못 적용한 제한과 아직 정하지 않은 값

시험 코드의 응답 8/16/32 KiB, 파일 8 MiB, 검색 2,000개/32 MiB는 실제 제품 계약에서 가져온 값이 아니다. 배포 기본값으로 채택하지 않으며 해당 조건의 추가 시험도 중지했다. 이 값을 단순히 크게 올리거나 전부 없애는 것으로 실제 환경 검증을 대신하지 않는다. 배포 후보와 호스트의 유효 설정을 먼저 확인하고 각 제한의 주체/단위/출처를 구분해야 한다.

기존 실제 Codex 기록은 0.170.0, GPT-5.6-Sol low였다. 직접 접근에서도 상위 출력이 잘렸고 MCP에서도 합산 출력이 잘렸다. 그 기록만으로 모든 모델/버전의 고정 바이트 상한을 알 수 없다. 이번에 현재 Windows Codex 버전이나 개인 유효 출력 설정을 새로 조회한 것은 아니다.

[현재 공식 설정 문서](https://learn.chatgpt.com/docs/config-file/config-reference)는 MCP 도구별 output_token_limit이 모델의 기본 출력 예산을 덮는다고 설명한다. 이것은 토큰 단위이며 현재 문서가 이전 0.170.0의 실제 적용까지 증명하지 않는다. 모듈은 사용자 전역 설정을 바꾸지 않는다. [공식 MCP 도구 규격](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)은 구조화 결과와 호환 텍스트, 오류 구분을 설명하지만 이 시험의 임의 바이트 상한을 정하지 않는다.

[Python 3.13의 파일 정보 문서](https://docs.python.org/3.13/library/os.html)는 Windows ctime 대신 생성 시각의 birthtime 사용을 안내한다. 이번 진단은 그 시간 필드 차이에 대응한 것이며 동시 파일 교체를 완전히 격리한 제품 핸들 보호의 성공이 아니다.

## 남은 작업

1. 배포 후보의 코드/진입, 지원 버전과 실제 유효 설정을 확인하고 필요한 반환/자원 정책을 정한다. 미정 값은 임의로 채우지 않는다.
2. SDK의 원시 반환, 클라이언트 객체와 Codex 출력의 계수 대상을 구분해 크기 검사 실패를 수정한다. 현재 실패는 미해결이다.
3. 같은 배포 조건으로 전체 문서와 지정 구간, 검색, 오류 후 재요청을 실제 사용 경로에서 확인한다. 모든 페이지의 수신과 AI의 원문 활용은 별도로 관측한다.
4. 새 AI 실행의 대상/모델/반복/비용을 정하고 원본을 보존한 사본으로 진행한다. 첫 MCP 제공/쓰기/복원 지원은 아직 확정하지 않는다.

문서와 보존 검사는 이 기록의 형식/연결/변경 범위 확인이며 미해결 SDK 검사나 배포 사용 검증을 대신하지 않는다.
