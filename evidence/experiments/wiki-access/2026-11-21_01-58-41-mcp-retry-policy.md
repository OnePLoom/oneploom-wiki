# 잘림 뒤 재시도 정책 검토

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 지정 작업일은 2026-11-20이다. [앞선 수신 검토](2026-11-21_00-23-11-mcp-delivery-review.md) 다음으로 현재 후보의 입력과 지침을 읽어 자동 재시도의 적용 조건을 좁혔다. **문서와 정적 검토만 수행했으며 새 AI, MCP, Windows 시험과 후보/설정 변경은 없다.**

## 확인과 제안의 구분

- 현재 Reader는 같은 cursor의 작은 page_bytes 요청을 처리한다. 기존 읽기 테스트에는 재시도 위치와 작은 본문의 연속성 확인이 있고 검색 테스트에는 같은 cursor 재실행 확인이 있다. 검색의 축소까지 검증한 것으로 합산하지 않으며 이번에 변경 없는 테스트를 재실행하지 않았다.
- page_bytes 생략은 연결의 설정값을 사용한다. next에는 크기가 있지만 최종 결과에는 적용 크기를 따로 싣지 않는다. 따라서 첫 기본값 요청이 잘렸을 때 현재 메인 AI가 그 크기를 반드시 알 수 있다는 보장은 없다.
- page_too_small 안내는 크기를 늘리라고 한다. 호스트 잘림 때문에 축소하는 상황과 일반적으로 너무 작은 값을 입력한 상황을 구별해야 한다. 크기를 줄였다 키우는 반복은 정적 위험이며 실제 장애 발생으로 기록하지 않는다.

[설계 원본 — 「축소 재시도의 범위와 종료 조건」](../../../design/integration/mcp.md)에 A 즉시 중단, B 제한된 자동 축소, C 가능한 크기까지 축소를 비교했다. B의 문안은 같은 논리 요청에서 절반씩 최대 두 번 축소하고, 크기 미확인/진행 불가/다른 오류에서는 중단하는 초안이다. 2회와 절반은 실측 최적값이나 호스트 한도가 아니며 **사용자 선택 전**이다. 정리한 수용 입력도 실행 결과가 아니다.

## 외부 근거와 적용 한계

- [AWS 재시도 안내](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/): 재시도 책임과 여러 계층의 중복 실행, 부작용과 반복 비용을 구분하는 근거다.
- [Google Cloud 재시도 주의사항](https://docs.cloud.google.com/storage/docs/retry-strategy#retry_anti-patterns): 원인이 그대로인 오류의 반복과 무제한 재시도를 피해야 한다는 근거다.
- [MCP 오류 규격](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#error-handling): 도구 실행 오류를 원인/조치가 있는 결과로 전달하고 프로토콜 오류와 구분한다.

자료는 원리 참고와 링크로만 사용했고 외부 코드/문서 본문을 복제하지 않았다. 네트워크 대기 알고리즘, 서비스의 특정 횟수나 SDK 기본값을 우리 출력 크기 문제에 복사하지 않는다. 위 자료는 2회/절반 제안이나 현재 후보의 실제 복구 성공을 입증하지 않는다.

## 보존과 다음 순서

작업 전 기록 기록에 백업, 편집 범위와 보호 파일 해시가 있다. 검토 기록 기록은 확인한 소스와 미검증, 제안의 상태를 보존한다. 기존 시험 프로젝트 원문, 현재/이전 시험 사본, 사용자 설정과 Git은 변경 대상이 아니다. 백업은 2026-11-21 01:57:50 KST 생성 백업(식별자 `JY9nRE7I`)다.

B안 선택 뒤 기존 서버 instructions의 최소 보완과 영향 검사로 진행한다. 첫 크기 미확인까지 자동 해결하려면 연결 정보 전달 방법의 별도 검토가 필요하며, 새 조회 도구/필드를 이번에 확정하지 않았다. 실제 Windows AI 요청은 배포 후보 지침과 사용자 설정을 유지해 별도 실행 범위를 확인한 뒤 진행한다. 기존 시험은 반복하지 않는다.

문서/보존 검사 기록은 통과했다. Markdown 6개와 내부 링크 449개 중 제목 308개, 원문 86개와 후보/사본/설정 7개, 이전 체크섬 22개와 백업의 다른 파일 3,070개를 확인했다. 사용자 UI의 최근 열기 목록 변화는 보존했다. 이는 문서 정합성과 보존 확인이며 새 실행 기능의 통과가 아니다.
