사용자 작업일: 2026-11-18. [첫 읽기/검색 시험](2026-11-18_15-21-34-mcp-read.md)의 후속이다. 별도 Windows 합성 프로젝트 A/B와 WIKI만 사용했다. 제품 구현이나 MCP 첫 배포 포함 결정은 아니다.

## 실패와 보정 원리

기존 등록은 `../.venv/Scripts/python.exe`와 `server.py`를 실행했다. 프로젝트 루트에서는 맞지만 nested에서 같은 상대 경로를 해석하면 다른 위치가 된다. config 발견 성공은 실행 파일 발견 성공이 아니었다. [Codex 실행 설정](https://learn.chatgpt.com/docs/extend/mcp#stdio-servers)과 [0.169.1의 실행 코드](https://raw.githubusercontent.com/openai/codex/rust-v0.169.1/codex-rs/rmcp-client/src/stdio_server_launcher.rs)를 대조했다. 명시 cwd가 없으면 호출 측 작업 경로를 사용한다는 코드와 관측이 일치한다. 현재 실행 경로의 모든 내부 구성요소 버전이 같다는 증거는 아니다.

시험 등록은 Windows Python launcher로 짧은 준비 코드를 실행한다. 이 코드는 `git rev-parse --show-toplevel`로 현재 저장소 루트를 찾고, 그 안의 서버와 로컬 연결 파일을 확인한 다음 시험용 Python 환경으로 실행한다. [Git의 루트 조회 계약](https://git-scm.com/docs/git-rev-parse#Documentation/git-rev-parse.txt---show-toplevel)을 참고했다. 표준 입출력은 MCP에 전달하고 준비 과정에서 프로토콜 출력에 안내를 섞지 않는다.

A와 B의 등록 문자열은 동일하고 개인 절대 경로가 없다. 저장소 밖이거나 중간의 다른 저장소에 시험 파일이 없으면 실패하며 부모 프로젝트를 대신 선택하지 않는다. 기존 루트 상대 실행과 새 탐색을 여러 fallback으로 겹쳐 두지 않았다. 이전 설정 기록, 현재 시작 코드 기록, 후보 설정 기록을 보존한다.

이 보정은 시험 환경의 시작 위치 문제를 해결하는 후보이며, 부모 폴더의 `.venv` 배치를 제품 공통 설치 구조로 채택하지 않는다. Git과 Python launcher의 발견, 프로젝트 등록, 설치 형식, 프로세스 수명은 제품화 때 별도 명세/검증이 필요하다. 외부 코드를 복제하거나 새 패키지를 추가하지 않았으며 기존 SDK/의존성의 라이선스 근거는 첫 시험 기록에 유지한다.

## 모델 없는 검사와 실제 사용의 구분

Windows 시작 검사 기록은 **시험에 반영할 후보 명령/인자**를 SDK 클라이언트에 전달했다. A/B 루트, A/B nested, A의 한글/공백 하위 경로에서 5회 연결과 원문 읽기, 정상 통신 종료를 확인했다. 저장소 밖과 별도 중첩 저장소의 2개 거부 사례도 통과했다. 이전 SDK 검사에서 쓰던 서버 절대 경로로 대체하지 않았다. 모델 호출은 0회다.

SDK 연결 시간은 표본에서 약 0.785~0.814초였다. 준비 코드만의 추가 비용이나 실제 Codex 시작 시간, 직접 접근 대비 성능 차이를 뜻하지 않는다. 비정상 종료 때 남는 자식 프로세스까지 검사한 결과도 아니다.

호스트 설정 조회 기록은 A/B 루트와 nested 4곳에서 성공했다. 이후 사용자가 실패했던 A/nested의 실제 Codex를 다시 열어 원문 읽기까지 확인했다. 모델 없는 검사, config 조회와 실제 호스트 결과를 합산해 제품 수행률을 만들지 않는다. 읽기 구현은 바꾸지 않았으므로 기존 파일 검사 9개와 SDK 결과 형식 검증의 PASS는 재사용했다.

WSL 근거 수집기의 첫 해시 대조는 Windows 상대 경로의 역슬래시를 파일명으로 취급해 실패했다. Windows 경로의 각 부분을 분리해 같은 검사를 다시 수행했고 통과했다. WIKI나 서버 오류가 아니며 모델/통신 검사를 반복하지 않았다.

## 버전과 남은 확인

환경은 Windows Python 3.13.9와 MCP SDK 2.3.0이다. 설정 조회와 npm 패키지의 Codex 버전은 0.169.1이고, A/B/nested의 세션 메타데이터 기록은 모두 cli_version 0.170.0, source vscode로 기록돼 있다. 사용자는 Windows PowerShell에서 codex.cmd를 실행했다고 보고했다. 패키지 조회와 내부 세션 표기의 차이 원인은 미확인이다. 어느 하나를 전체 실행 경로의 단일 버전으로 단정하거나 이번 보정 중 버전이 바뀌었다고 추정하지 않는다. 모델은 세션 기록상 GPT-5.6-Sol, reasoning low다.

사용자는 업데이트 알림을 보고 Codex 갱신 가능 여부를 물었다. 현재 결과/소스를 먼저 보존하고, 시험 세션 종료 후 사용자가 갱신할 수 있다고 안내했다. 이 작업에서 설치 패키지나 전역 설정을 갱신하지 않았다. 갱신 뒤에는 새 버전과 실제 시작/연결을 별도 표본으로 확인하며 기존 결과를 새 버전의 PASS로 옮기지 않는다.

아직 남은 것은 같은 조건의 직접 접근/선택 MCP 비용 비교, 쓰기/충돌/중단, clone/worktree와 설치/갱신/제거, 일반 사용자 설정의 보존이다. 이번 읽기 표본으로 전체 WIKI 기능이나 영구 무승인 동작을 보장하지 않는다. [진행표](../../../development/roadmap.md)의 작은 비교 뒤 4단계 명세로 복귀한다.

현재 실행 소스와 로그의 해시는 `SHA256SUMS`에 남긴다. 명령 결과 기록, 보존 대조 기록을 함께 본다.
