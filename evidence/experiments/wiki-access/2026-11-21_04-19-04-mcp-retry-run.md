# 제한된 재시도 후보의 실제 Codex 관측

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 지정 작업일은 2026-11-20이다. [준비와 승인](2026-11-21_02-36-11-mcp-retry-instructions.md)에 따라 실제 읽기 한 요청과 검색 한 요청을 관측한다.

## 현재 확인과 다음 순서

user-status.json 기록은 사용자가 제공한 Windows Codex 0.171.0, GPT-5.6-Sol low, 시험 프로젝트와 wiki_reader connected/2 tools의 관측이다. 계정 식별자는 보존하지 않았다. 주간 잔량 9%는 사용자 화면의 보고이며 직접 계정 조회 결과가 아니다.

후보와 문서 사본 64개는 준비 해시와 같았다. 시작 상태 기록은 TUI를 연 뒤의 설정 해시를 보존한다. 사용자 신뢰 등록 가능성이 있는 시작 전 설정과 전체 바이트가 같다는 주장으로 사용하지 않는다.

첫 읽기 요청 기록과 같은 Windows 시험 창의 독립 검색 요청 기록을 각각 한 번 완료했다. 아래의 독립 원문 대조를 모두 통과했다. 사용자는 읽기와 검색 모두 추가 승인창이 없었다고 확인했다.

새 모델/권한 선택, 원본/사용자 설정 수정이나 추가 반복 실행은 하지 않는다. 실제 잘림이 없으면 축소 복구는 미관측으로 남긴다.

## 첫 읽기의 결과와 한계

실제 로그 대조 기록은 정상 읽기 5회의 본문을 독립 원문과 비교했다. 0~72,422바이트와 1~1,191행 전체가 일치했고 반환 구간의 틈이나 중복은 없었다. 같은 revision을 유지한 채 마지막 응답은 `eof`, 후속 요청 없음으로 끝났다. 사용자 보고 기록에서도 완료와 추가 승인창 없음을 확인했다. 파일명과 첫 제목의 단수형 차이는 원문에 있는 내용이며 이번에 수정하지 않았다.

호스트의 도구 설명 기록에서 새 재시도 지침의 노출을 확인했다. 첫 호출은 page_bytes를 생략했고 이후 네 호출은 반환된 다음 요청의 16,384바이트를 그대로 사용했다. 각 응답의 `output_limit`은 정상적인 다음 페이지 안내였다. 실제 호스트 잘림이나 축소 재시도는 관측되지 않았으므로 자동 축소 성공과 최대 두 번 준수는 검증 완료로 표시하지 않는다. 첫 적용 크기를 알 수 없는 잘림 처리와 최종 모델 입력 전체도 미확인으로 유지한다.

내부 모델 응답은 7회, 기록된 실행 시간은 43,261ms다. 토큰 기록은 read-check.json에 보존했다. 캐시 입력과 추론 출력은 각 합계의 부분이며 구독 한도 차감량이나 비용으로 환산하지 않는다. 정상 페이지 호출을 축소 재시도 횟수로 세지 않는다.

보존 확인 기록에서 원본 문서 86개, 시험 소스/사본과 현재 설정 67개, 제품 Git/index와 준비 run의 근거가 유지됐다. 전역 설정 비교는 사용자 TUI 시작 후의 before.json 기준이며 시작 전후 전체 불변 주장으로 확대하지 않는다. 실제 입력의 줄바꿈 차이는 별도 보존했고 모델 요청을 다시 실행하지 않았다.

## 검색의 결과와 한계

검색 로그 대조 기록은 사본 문서 60개를 직접 검색한 결과와 MCP 반환을 비교했다. 정상 3페이지에서 33줄, 36줄, 2줄을 받았으며 71개 일치 줄과 9개 파일의 순서, 줄 번호, 바이트 위치와 전체 줄 본문이 일치했다. 누락, 중복, 생략된 발췌는 없었고 마지막 응답은 `complete`, 후속 요청 없음이었다. 같은 파일의 revision도 일관됐다. 최종 답변의 파일 목록과 개수가 이 결과에 일치했다.

첫 검색은 page_bytes를 생략했고 이후 호출은 반환된 다음 요청의 16,384바이트를 그대로 사용했다. 호스트 잘림과 축소 재시도는 없었다. 내부 모델 응답은 4회, 기록된 실행 시간은 37,096ms다. 사용자 읽기/검색 두 요청을 합친 실제 사용량은 사용량 기록 기록에 보존하며 직접 파일 접근과의 비용 우위를 이 표본으로 결론내리지 않는다.

검색 뒤 최종 보존 확인 기록에서도 원본 86개, 시험 파일/설정 67개와 제품 Git이 유지됐다. 검사기가 기존 기록의 index 키를 잘못 참조한 초기 오류 기록을 남기고, 통과한 파일/HEAD/status 비교는 재사용한 채 해당 index 비교만 완료했다. 제품 코드나 모델 요청을 반복하지 않았다.

## 다음 순서

이 표본은 새 지침을 적용한 정상 읽기와 검색의 수신을 확인했다. 자동 축소, AI의 최대 두 번 준수, 첫 적용 크기 미확인과 최종 모델 입력 전체는 확인하지 못했다. 기존 내부 취소와 늦은 응답의 미관측도 유지한다. 이 항목들의 보완/검증 조건을 정리한 뒤 직접 접근과 MCP의 자유 탐색 품질/비용 비교, 첫 제공 판단으로 이어간다. 추가 AI 요청이나 장애 시험은 이번 두 요청 승인에 포함하지 않는다.
