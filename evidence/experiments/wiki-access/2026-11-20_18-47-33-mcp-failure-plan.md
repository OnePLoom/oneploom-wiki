자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 지정 작업일: 2026-11-20. 상태는 **준비, 미실행**이다. 새 Windows 시험 폴더, MCP 등록과 모델 호출은 아직 없으며 제품 설치나 새 지원 방식을 확정한 기록이 아니다.

## 목적과 기존 근거

사용자가 요구한 “MCP로 읽어도 원문이나 필요한 범위를 놓치지 않아야 한다”는 기준의 실패 상황을 확인한다. [11/19 수신 표본](2026-11-20_04-55-27-codex-receipt-run.md)은 재사용하고, [기존 수용 입력 — 「MCP 읽기 보완의 검증 입력」](../../../verification/acceptance.md)의 R-05/08/10/13 중 없는 파일과 원문 변경을 다음 단위로 좁혔다. 전체 순서는 [오류 후 사용의 검증 순서](../../../design/integration/mcp.md)가 소유한다.

예를 들어 첫 부분의 제목은 A인데 읽는 도중 제목과 마지막 내용이 B로 바뀌면, 옛 첫 부분과 새 마지막 부분을 합쳐 한 문서를 모두 읽었다고 해서는 안 된다. 서버가 변경을 감지하는지와 AI가 그 오류를 받아 새 원문을 확인하는지는 별도로 검증한다.

## 입력과 실행 순서

| 단계 | 구체 범위 | 완료를 판단할 자료 |
| --- | --- | --- |
| 준비 | 새 `failure-20261120` 아래 project, wiki, source. 이전 보존 사본의 `docs/REQUIREMENTS.md` 한 개와 검증된 후보 네 파일을 복사 | 계획 기록, 독립 기대값 기록, 배치 전후 해시. 현재는 미리보기만 수행 |
| 실제 시작 | Windows PowerShell에서 새 시험 project의 현재 Codex 실행. 사용자 모델/추론 설정 유지, 패키지 설치/업데이트 없음 | `/status`와 도구 연결. 기존 완료 세션을 재개할 필요 없음 |
| 첫 요청 | initial 기록: 첫 반환분만 읽고 기다리기, 없는 `docs/설치-안내.md` 읽기 | 본문과 실제 범위, 미완료와 이어 읽기 정보, 없는 파일의 오류 및 AI의 설명 |
| 사본 변경 | 변경 도구 기록으로 새 시험 사본의 첫 제목과 마지막 절만 변경 | 예상 전후 해시와 실제 바이트. 원본과 이전 시험본은 보존. Codex/MCP는 재시작하지 않음 |
| 둘째 요청 | continue 기록: 앞서 받은 정보로 계속 읽기, 첫 제목과 마지막 절 확인 | 옛 cursor가 실제 전달됐는지, 원문 변경 오류와 다음 행동, 재독했다면 새 원문 본문/범위 |

`cursor`는 서버가 다음 읽기를 위해 돌려주는 이어 읽기 정보다. 첫 요청에 남은 범위를 읽지 말라고 한 것은 변경 시점을 분리하기 위한 사용자 범위 지정이다. 제품의 기본 16,384 논리 바이트 페이지나 파일/검색/시간 한도를 시험용으로 바꾸지 않는다. 변경 요청은 원문을 한 번 다시 읽는 비용을 낼 수 있으며, 이를 실패나 낭비로 미리 단정하지 않는다.

배치 도구 기록은 이전 준비 코드를 그대로 재사용한다. 수집기 기록은 동일한 수집 함수를 유지하고 이번 사례 이름을 계획에서 읽도록 진입부만 조정했다. 모델에 기대 답이나 오류 후 해결책을 미리 주지 않는다. 시험 요청문은 조회 도구와 범위만 지정한다.

## 판정과 관측 한계

- 첫 읽기의 본문을 독립 원문과 대조하고 전체 완료가 아님을 확인한다. 없는 파일의 오류를 빈 정상 문서로 설명하면 실패다.
- 변경 뒤 옛 cursor를 실제 호출했는데 변경 오류 없이 다른 버전을 잇거나 성공으로 숨기면 실패다. 도구 오류와 최종 답변만 보지 않고 실제 호출/응답 본문을 함께 대조한다.
- 새 문서를 처음부터 다시 읽었다면 변경 후 독립 기대값과 대조한다. 재독 없이 옛 첫 부분과 새 끝을 합쳐 완료 처리하면 실패다. 같은 원문을 코드 안에서만 읽고 본문을 출력하지 않은 경우에도 완료로 보지 않는다.
- 오류를 설명하고 멈춘 경우에는 **잘못된 완료 방지는 확인, 전체 읽기는 미완료**로 나눠 기록한다. 오류 감지만으로 기능 전체 성공을 선언하지 않는다.
- 옛 cursor를 보내지 않았거나 두 요청 사이에 서버가 재시작됐으면 원문 변경 후 이어 읽기 사례는 미실행이다. 서버 재시작의 cursor 만료를 원문 변경 성공으로 세지 않는다.
- 실제 호스트 로그에 드러난 전달과 최종 모델 입력 전체를 구별한다. 취소/재연결, 출력 잘림, 자유 탐색의 의미 품질/비용, 쓰기/복원과 모든 환경의 안전성은 이 표본의 통과 대상이 아니다.

이 구분은 [MCP 도구 오류 규격](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#error-handling)과 현재 후보의 원문/진행 계약을 따른다. 규격 자체가 AI의 후속 행동을 보장하는 것은 아니다. 후속 취소 시험은 [취소 규격](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/cancellation)상 응답 없이 종료될 가능성까지 별도로 다룬다.

## 비용과 보호 범위

초기 사용자 AI 요청은 두 회다. 내부 모델 응답, 도구 호출과 재독 횟수는 실행 결과로 기록하며 두 회라고 가정하지 않는다. 현재 선택 모델을 따르고 토큰 수, 구독 잔량/차감과 지연은 추정하지 않는다. 새 모델 요청의 구체 범위/비용은 [진행표의 다음 한 단위](../../../development/roadmap.md)에 따라 실행 전에 확인한다. 실패 보완이 필요하면 기존 실패 기록을 남기고 영향받은 사례만 다룬다.

문서 원본, 과거 실험 자료와 전역 Codex 설정은 시험 대상이 아니다. 새 시험 폴더를 덮어 만들지 않으며 Git remote, 계정 설치와 자동 정리는 하지 않는다. 동일 OS 계정의 다른 자료가 운영체제 수준에서 완전히 차단된다는 의미는 아니다. 초기 프로젝트 신뢰 등록을 호스트가 기록할 수 있다는 과거 관측은 별도로 대조하며 설정을 자동 복원하지 않는다.
