# MCP 결과의 크기와 SDK 변환

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 작업일: 2026-11-19. [앞선 조회 한계 검토](2026-11-19_15-17-25-mcp-capabilities.md)에서 이어진 반환 정책 검토다. 보존된 문서 사본 3개를 설치된 Windows SDK로 변환하고 다시 읽었으며 본문이 유지됐다. 클라이언트가 변환한 객체의 크기와 규격에 맞춘 결과의 크기는 달랐다. **실제 서버 전송이나 Codex의 수신을 검증한 결과는 아니다.**

## 범위와 입력

- 실행 환경: 기존 시험 공간의 Windows Python 3.13.9, mcp/mcp-types 2.3.0, pydantic 2.14.3. 이번 관측값이며 배포 고정 버전이 아니다.
- 입력: [관측 기록 (이전 SDK 기록)](2026-11-18_18-45-45-mcp-read-fidelity.md)이 가리키는 사본 60개 중 파일 바이트 크기 순으로 가장 작은 파일, 중간 위치의 파일, 가장 큰 파일. 기존 시험 프로젝트 원본은 읽기/쓰기 입력으로 넘기지 않았다.
- 경로와 해시: 진단 출력 기록에 사본과 SDK 소스의 해시를 기록했다. Git, 원문 문서와 읽기 확인한 설정의 기준은 작업 전 기록 기록에 있다.
- 제외: 서버/호스트 기동, 모델 요청, MCP 도구 호출, 패키지 설치, 임의 크기 제한과 이전 실패 시험 재실행. 파일 처리, 페이지 분할, JSON-RPC 전체와 호스트의 추가 가공은 이번 진단 밖이다.

검사 코드는 probe.py 기록다. 문서 원문과 위치/진행 정보를 하나의 결과로 만들고, 같은 값에서 `structuredContent`와 호환용 텍스트를 구성했다. 설치된 SDK의 규격별 결과 변환과 공통 객체 읽기를 사용해 두 표현의 일치와 본문 바이트 보존을 확인했다. 과거 시험에서 사용한 2025-11-25 규격과 SDK가 지원하는 2026-07-28 규격을 대조했으며 실제 Codex가 어떤 규격을 협상하는지 확인한 시험은 아니다.

## 결과

serialization.json 기록의 상태는 `PASS`다. 사본 3개, 규격별 변환 6건에서 본문과 사본 파일이 보존됐다.

| 사본 | 원문 바이트 | 2025 규격 결과 | 공통 객체 | 2026 규격 결과 |
| --- | ---: | ---: | ---: | ---: |
| docs/decisions/000-adr-template.md | 281 | 1,117 | 1,141 | 1,141 |
| docs/discussions/2026-03-27-gateway-trusted-header-review.md | 3,356 | 7,544 | 7,568 | 7,568 |
| docs/REQUIREMENTS.md | 72,422 | 150,031 | 150,055 | 150,055 |

표의 결과 크기는 같은 방식으로 압축 표기한 JSON의 UTF-8 바이트다. 2025 규격 결과에는 없던 `resultType: complete`가 공통 객체에 생겨 24바이트 차이가 났다. 2026 규격은 두 단계에서 해당 필드를 유지했다. 이 숫자는 실제 STDIO 바이트, 전체 JSON-RPC 크기, 모델 토큰 수가 아니며 일반적인 여유분으로 더할 상수도 아니다.

앞선 검사 코드는 클라이언트 결과의 `model_dump`를 `wire`라고 부르고 직접 만든 응답 크기와 비교했다. 그러나 설치된 SDK는 규격별 변환을 하고 서버 정보를 추가할 수 있으며, STDIO 단계에서는 메시지 전체를 직렬화한다. 따라서 수기 JSON, 클라이언트 객체와 실제 전송을 같은 대상으로 계수할 수 없다. 이번 진단은 이 측정 문제를 확인한 것이며 기존 96번째 응답 FAIL을 PASS로 바꾸지 않는다.

## 실행과 실패 기록

기존 Windows 시험용 Python으로 아래 개인 진단만 실행했다. 재현 위치를 나타내는 명령이며 배포 사용 명령이 아니다.

```powershell
& '<WORKSPACE_PATH> -B '<WORKSPACE_PATH>
```

1. 기본 sandbox에서는 WSL interop 진입이 차단돼 Python 실행 전 종료됐다.
2. 허용된 실행에서는 검사 파일명 `inspect.py`가 Python 표준 모듈을 가려 import 단계에서 실패했다. SDK 변환에는 도달하지 않았다.
3. 원래 진단 소스를 초기 사본 기록에 보존하고 파일명을 `probe.py`로 수정했다. 동일한 Windows 진단을 다시 실행해 종료 코드 0과 위 PASS를 확인했다.

각 시도의 요약은 attempts.json 기록에 남겼다. 진단 파일의 이름 충돌이며 제품이나 SDK의 결함으로 분류하지 않는다. 새 서버/모델 실행으로 대체하거나 관련 없는 검사를 반복하지 않았다.

## 설계 반영과 남은 확인

[읽기 명세 — 「MCP 읽기의 남은 보완」](../../../design/runtime/entry.md)에서 논리 결과의 페이지 목표와 전체 요청 범위를 구별하고, SDK 전송과 실제 호스트 수신을 별도 검사 대상으로 연결했다. 논리 결과는 원문, 경로와 다음 위치를 담은 프로그램 내부 결과다. 이를 나눠 보낸다고 사용자가 요청한 마지막 구간을 생략할 수는 없다.

[R-04/07/09 — 「MCP 읽기 보완의 검증 입력」](../../../verification/acceptance.md)에 실제 페이지 설정, 긴 한 줄, 검색의 빈 중간 페이지와 각 단계의 크기/본문 대조를 연결했다. 숫자 기본값, 부분 줄의 정확한 이어 받기 형식과 실제 배포 경로 검증은 남아 있다. [실제 Codex 비교](2026-11-18_16-50-18-codex-wiki-usage.md)의 답변 PARTIAL도 유지한다. 상세 읽기의 성공이나 MCP 첫 제공을 확정하지 않는다.

다음은 보존된 실제 사본의 파일/줄/검색 분포를 근거로 배포 설정과 이어 받기 계약을 정하는 단위다. 임의 시험 상한을 넣어 성공시키거나 모델/버전에 고정 숫자를 대응시키지 않는다. 설명은 [페이지와 전송 크기 — 「페이지 크기와 전송 크기가 다른 이유」](../../../explanations/mcp.md), 순서는 [진행표](../../../development/roadmap.md)에 연결한다.

## 외부 근거와 이용 범위

- [MCP 2025 도구 규격](https://modelcontextprotocol.io/specification/2025-11-25/server/tools#structured-content)과 [2026 도구 규격](https://modelcontextprotocol.io/specification/2026-07-28/server/tools): 구조화 출력, 호환용 텍스트와 출력 schema 요구를 대조했다. 숫자 기본값이나 호스트의 실제 수신량을 정해 주는 자료는 아니다.
- [GitHub 공식 MCP 파일 처리](https://github.com/github/github-mcp-server/blob/main/pkg/github/repositories.go): 파일 크기에 따라 본문 또는 resource link를 반환하는 비교 사례다. 그 서비스의 상한을 우리 제품 기준으로 가져오지 않으며 링크만 반환했다고 원문 수신을 완료한 것으로 보지 않는다. [해당 저장소 허가문](https://github.com/github/github-mcp-server/blob/main/LICENSE)은 MIT다.
- [공식 Filesystem 참고 서버](https://github.com/modelcontextprotocol/servers/blob/main/src/filesystem/README.md): 전체/앞/뒤 읽기의 공개 인터페이스를 비교했다. 우리 구간/이어 받기 계약이 자동 제공되는 것은 아니다. [허가문](https://github.com/modelcontextprotocol/servers/blob/main/LICENSE)은 신규 코드와 규격의 Apache 2.0, 규격 외 문서의 CC BY 4.0 및 기존 기여의 잔존 MIT 조건을 구별한다. 저장소 전체를 단일 MIT로 간주하지 않는다.
- 설치된 SDK 두 패키지의 MIT 메타데이터와 허가문은 [관측 기록 (직전 조사)](2026-11-19_15-17-25-mcp-capabilities.md)에 기록했다. 이번에는 설치된 변환 함수를 호출하고 소스를 읽었으며 외부 구현이나 문서 본문을 복사해 배포물에 넣지 않았다.

웹의 변경 가능한 main 경로는 조사 출처다. 향후 코드를 도입할 때는 실제 채택 버전과 허가 조건을 다시 확인해야 하며, 이번 참고가 전체 배포물의 권리 검토를 대신하지 않는다.
