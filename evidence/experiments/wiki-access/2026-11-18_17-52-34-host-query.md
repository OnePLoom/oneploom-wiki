# Windows Codex의 설정과 세션 조회

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 지정 2026-11-18 작업. 기본 실행기의 준비 조건에 사용할 조회 수단을 Windows Codex 0.170.0에서 확인했다. 합성 설정과 합성 저장 기록만 사용했으며 실제 AI 요청, 사용자 대화의 재개나 제품 실행기 구현은 하지 않았다.

## 입력과 실행

작업 전 백업은 2026-11-18 17:52:14 KST 생성 백업(식별자 `64WGQYho`)다. 현재 npm 설치본의 공식 진입 파일을 Windows Node로 실행하고, 시험 자식 프로세스에만 별도 CODEX_HOME을 지정했다. `help.py`, `schema.py`, `probe.py`, `selected.py`가 실제 실행 입력이다. 실제 사용자 설정의 본문과 인증 자료는 복사하지 않았다.

- `schema.zip`: 해당 설치본의 `generate-json-schema --experimental` 출력 479개. `schema-record.json`은 파일별 해시와 버전이다. 실험적 필드의 포함이 제품 기본 채택을 뜻하지 않는다.
- `fixture/`: A/B 프로젝트, A의 하위 폴더, WIKI, 별도 설정과 합성 세션 한 개. 실제 Codex 대화/DB를 복사하지 않고 session_meta 입력을 작성했다. 이 입력의 읽기 성공은 실제 TUI 재개 성공과 다르다.
- `base.json`, `override.json`, `selected.json`, `responses.json`: 요청/응답과 종료 관측. 생성형 요청인 turn/start, thread/start와 thread/resume은 보내지 않았다.
- `check_observations.py`, `observations-check.json`: 이미 저장한 응답과 입력 보존의 대조. 검사 통과와 제품 호환 성공을 구분한다.

처음 WSL 샌드박스 안의 Windows 실행은 연결 오류로 시작하지 못했다. 실행 허용 뒤 Windows Python으로 진행했다. 이는 제품의 조회 기능 실패와 구분한다. PATH의 접근 불가 항목 하나도 실제 실행 파일 부재로 처리하지 않았다. 초기에 추정한 일반 npm 설치 위치에는 패키지가 없었으며 PATH의 현재 설치를 확인했다.

## 결과와 한계

| 항목 | 실제 관측과 의미 |
| --- | --- |
| config/read | cwd에 따라 A/B 설정을 구별했고 A 하위 폴더는 A 설정과 일치. 설정 계층 조회이며 실제 TUI의 최종 접근 성공 판정은 아님 |
| configRequirements/read | 이 합성 환경에서는 requirements가 null. 관리 제한이 있는 환경의 호환/강제 검증은 미실행 |
| permissionProfile/list | 페이지를 나눠 후보 이름, 설명, 선택 허용 여부를 반환. 파일 경로별 최종 읽기/쓰기 권한은 반환하지 않음 |
| read-only 명령 옵션 | config/read에 sandbox_mode가 보이지만 기존 default_permissions와 프로필 후보 목록도 남음. 목록의 allowed를 실제 WIKI 쓰기 가능으로 읽으면 안 됨 |
| thread/read | 합성 기록의 cwd, notLoaded와 빈 turns를 반환. 대화 본문이나 재개 없이 위치를 확인하는 후보. 실제 사용자 세션/이동/worktree 검증은 남음 |
| 없는 세션 ID | 조회 오류 반환. 새 세션이나 다른 기록으로 대체하지 않음 |
| thread/list의 useStateDbOnly | 합성 원시 기록은 thread/read로 읽혔지만 DB 전용 목록에는 없었음. 목록이 비었다고 전체 대화가 없다는 뜻이 아님 |
| --profile과 app-server | 도움말은 종료 0이었지만 실제 시작은 명시적으로 거부하고 종료 1. 도움말 파싱으로 선택 프로필 호환을 통과 처리할 수 없음 |

기본 조회 묶음은 1.532초, 명령 옵션을 추가한 조회 묶음은 0.691초였다. 두 프로세스의 요청 수가 다르고 각 한 번의 관측이므로 일반 시작 지연, 캐시 효과나 성능 우위를 계산하지 않는다. 조회 프로세스 둘과 거부된 프로세스는 EOF 뒤 종료됐다. 시험 입력과 실제 사용자 config의 해시는 보존됐다.

프로필 선택 거부는 재시도로 해결한 오류가 아니다. `selected.py`의 최초 관측은 응답 전 종료를 Python 오류로 보고했으며, 실제 원인은 저장한 Codex stderr의 지원 범위 제한이다. 이를 성공으로 보정하거나 같은 호출을 반복하지 않는다. 조회 후보의 한계로 명세와 수용 입력에 연결한다.

## 설계에 반영할 경계

[호스트 조회와 실행 인계](../../../design/runtime/entry.md)가 상세를 소유한다. Codex 자체의 설정 해석을 재사용하되 조회 서버와 실제 터미널의 적용 조건이 같은지 확인해야 한다. 선택 가능한 프로필, 디스크 설정과 실제 실행 권한을 합치지 않는다. `--profile` 등 지원되지 않는 조합을 임의 변환하거나 제거하지 않는다.

새 세션 시작에는 과거 대화 조회가 필요하지 않다. 명시적으로 재개할 때 필요한 메타데이터만 사용하고 preview/본문을 모델 입력이나 공개 기록으로 가져오지 않는다. 목록 조회의 원시 이력 스캔/보정 여부도 구별하며 사용자의 기록을 직접 수정하지 않는다.

현재 사용자 설정/관리 정책 전체, 실제 권한 적용, 옵션을 보존한 TUI 시작/종료와 새 세션/재개는 별도 수용 시험이다. 이번 결과를 제품 출시나 첫 실행기 구현 완료로 표시하지 않는다. 다음 설계 단위는 [MCP 읽기 보완 — 「MCP 읽기의 남은 보완」](../../../design/runtime/entry.md)이며 이 호환성 조건을 지우지 않는다.

## 공식 자료와 보존

[App Server 문서](https://learn.chatgpt.com/docs/app-server)는 설정/요구 조건 조회, 프로필 목록과 메타데이터 읽기를 설명한다. [설정 계층](https://learn.chatgpt.com/docs/config-file/config-basic)과 [권한](https://learn.chatgpt.com/docs/permissions)은 실제 시작 조건을 대조하는 근거다. 설치본에서 생성한 명세와 실행 결과를 최신 웹 설명과 별도로 보존한다.

설치된 npm 메타데이터는 Apache-2.0을 표기했고 [공식 저장소의 LICENSE](https://github.com/openai/codex/blob/main/LICENSE)도 확인했다. 생성 명세는 이 개인 검증 근거이며 제품에 동봉하지 않았다. 공개/배포 편입 시에는 해당 배포 버전의 라이선스/고지 확인을 별도로 완료해야 한다. 새 외부 SDK나 설치 패키지는 추가하지 않았다.
