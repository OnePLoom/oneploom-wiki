# 사용자 설치 환경의 읽기 점검

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 작업일은 2026-11-18이다. MCP의 임의 시험 한도를 배포 기준으로 사용하지 말라는 요청에 따라 실제 Windows 설치본과 관련 설정을 읽었다. 후속 질문에 따라 **관측값 기록과 사용자 환경 고정을 구분**했다. 모델 요청, 새 TUI 시작, MCP 호출은 모두 0회다. 이 기록은 배포 기능 검증이나 자동 한도 조회 구현의 성공 결과가 아니다.

## 확인한 내용

| 대상 | 관측과 해석 |
| --- | --- |
| Windows 설치본 | 패키지 메타데이터와 실제 `--version` 모두 Codex 0.170.0. 사용자 설치본을 읽었으며 버전을 고정하거나 설치/갱신하지 않음 |
| Python과 SDK | Windows Python 3.13.9, 시험 환경 SDK 2.3.0. 제품 의존성 채택이나 전체 사용자 지원 목록이 아님 |
| 관련 설정 | 사용자 설정과 usage-mcp 프로젝트 계층에서 허용한 키만 읽음. 이번 조회 범위에서 출력 예산의 명시적 덮어쓰기는 관측되지 않음. 선언된 설정이며 신뢰/관리 정책/CLI 옵션까지 합친 유효 TUI 설정은 아님 |
| 모델 캐시 | 기록된 세 모델의 truncation_policy는 tokens / 10000. 캐시의 client_version은 0.170.0. 조회 시점은 environment.json의 fetched_at. 모든 모델, 모든 사용자, 현재 세션의 최종 한도에 대한 보장이 아님 |
| SDK 결과 객체 | 최소 CallToolResult의 기본 직렬화에서 resultType=complete 관측. 실제 전송 캡처나 Codex 수신 토큰 측정이 아님 |
| 설정 보존 | 읽은 설정 파일의 실행 전후 SHA-256 일치. 비밀값과 전체 설정 본문은 저장하지 않음 |

여기서 10,000토큰은 캐시에 기록된 도구 출력 절단 정책이다. 구독 사용량 한도, 모델 문맥 전체 크기나 모듈의 반환 기본값으로 해석하지 않는다. 버전 번호에서 한도를 산출하거나 토큰과 UTF-8 바이트를 같다고 간주하지 않는다.

## 실행과 근거

- 점검 소스 기록: native Windows Python으로 패키지/버전, 허용한 설정 키, 모델 캐시 일부와 SDK 기본 필드를 읽음. 기존 시험 위치를 쓰는 일회성 점검이며 배포 탐색 코드가 아님.
- 관측 결과 기록: 실제 버전, 선언된 관련 값, 전후 설정 해시와 확인 범위. identity, 자격증명, 전체 config는 미수집.
- 원문 기준 기록: 기존 기존 시험 프로젝트 Markdown 86개, Git/HEAD/index와 설정 해시 기준을 연결함.
- 문서와 보존 검사 기록: 이번 문서 변경, 내부 링크/제목과 이전 자료/원문/설정 보존 확인. 기능 테스트 결과가 아님.
- 의미 검토 기록: 관측/고정 정책 구분과 남은 확인. 자동 링크 검사와 구별함.
- 체크섬 기록: 이 실행의 보존 파일 목록.

첫 백업은 실행 중 근거 폴더 생성이 겹쳐 tar의 파일 변경 오류로 실패했다. 실패 기록 기록을 남기고 생성 완료를 기다린 뒤 순차 재시도했다. 유효한 수정 전 백업은 2026-11-18 19:22:15 KST 생성 백업(식별자 `xNpapJM0`)이며 체크섬을 확인했다. 실패한 파일은 `.failed`로 구별하고 정상 복원 근거로 사용하지 않는다.

## 판단과 남은 확인

실제 제품은 [사용자 환경의 변경과 호환성](../../../design/workflow/verification.md)에 따라 현재 설치본과 사용자 선택을 따른다. 위 관측값을 제품 상수나 지원 가능한 유일 버전으로 옮기지 않는다. 설치본 업데이트와 모델/설정 변경, 조회 불가 사례를 수용 입력에 연결했다.

[공식 Codex 설정 문서](https://learn.chatgpt.com/docs/config-file/config-reference)는 개별 도구 출력 예산과 모델 기본값을 덮는 MCP 도구별 설정을 설명한다. 다만 현재 문서의 키가 관측한 설치본에서 모두 지원된다는 증거는 아니다. 캐시를 영구 공개 API처럼 사용하거나 모든 한도가 자동 조회된다고 주장하지 않는다. 공식 문서의 설명을 참고했으며 외부 구현 코드를 복제하지 않았다.

현재 미확인은 유효한 세션 설정의 조회/변경 감지, 합산 출력에서의 실제 수신, 배포할 반환 정책과 MCP 제공 범위다. [앞선 내부 시험](2026-11-18_18-45-45-mcp-read-fidelity.md)의 SDK 크기 검사 실패는 아직이며 임의 제한으로 재실행하지 않았다. 다음은 확인 수단과 조회 불가 시 처리를 구체화한 뒤 실제 연결 코드의 검증 조건으로 넘기는 것이다. 원문 읽기의 요청 범위를 줄이거나 실패를 성공으로 바꾸지 않는다.
