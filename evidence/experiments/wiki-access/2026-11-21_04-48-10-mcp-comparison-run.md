# 직접 접근과 MCP의 후속 비교 실행

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 지정 작업일은 2026-11-20이다. [준비한 질문과 판정](2026-11-21_04-39-32-mcp-comparison-plan.md)에 대해 사용자가 이어서 진행하도록 했다. 새 Windows 배치와 새 대화 두 개에서 각 한 요청의 범위를 approval.json 기록에 기록했다. 이전 전체 읽기/검색 두 요청과 별개의 승인이다.

## 배치와 현재 상태

`<WORKSPACE_PATH>`에 MCP와 직접 접근용 프로젝트, 문서 사본 두 벌과 MCP 소스를 배치했다. 배치 코드 기록은 검증한 후보 4개와 고정 문서 60개를 사용하며 모델을 호출하거나 Codex를 실행하지 않는다. 기존 대상이 있으면 덮지 않고, 원본을 연결하는 링크도 만들지 않는다. 새 두 Git은 원격 없이 초기화했으며 commit/stage는 하지 않았다.

Windows 실행 결과 기록과 독립 보존 검사 기록에서 문서 사본 120개와 코드 4개, 같은 프로젝트 지침, 각 WIKI의 분리 연결을 확인했다. 원본 문서 86개와 제품 Git/index, 사용자 전역 Codex 설정이 유지됐다. 새 MCP 프로젝트에만 시험용 등록을 두었고 직접 접근 프로젝트에는 MCP 설정을 만들지 않았다. Python 3.13.9와 기존 의존성 버전을 기록했으며 설치/업데이트하지 않았다.

외부 Windows 시험 폴더 쓰기는 현재 샌드박스 밖이므로 실행 도구의 승인을 받아 진행했다. 이 준비 권한과 후속 AI 요청에서 발생하는 추가 승인 여부는 구분해 기록한다. 시작 전 해시 기록은 새 TUI를 열기 전의 상태이며 이후 사용자의 프로젝트 신뢰 등록을 모듈의 설정 변경으로 혼동하지 않는다.

사용자의 실제 연결 보고 기록에서 Codex 0.171.0, GPT-5.6-Sol low, Workspace와 `wiki_reader` 두 도구 연결을 확인했다. 위치는 새 MCP 프로젝트이며 Session은 `<SESSION_ID>`다. 계정 식별자는 저장하지 않았고 주간 잔량 6%는 사용자 화면 보고로 기록했다.

같은 창의 MCP 요청 기록을 완료했고, 다른 새 대화에서 직접 요청 기록도 완료했다. 두 경우 모두 질문 처리 중 추가 승인창은 없었다는 사용자 보고를 보존했다. 직접 접근은 첫 시작에서 외부 폴더 권한이 거부돼 `--sandbox workspace-write`를 명시한 뒤 열렸다. 시작 시도 기록과 직접 접근 환경 기록은 AI 요청 중의 승인 여부와 구분한다. 두 세션 모두 0.171.0 / GPT-5.6-Sol low / Workspace였으며 모델과 질문, 사본을 중간에 바꾸지 않았다.

## 비교 결과

[관측 기록 (사전 기준)](2026-11-21_04-39-32-mcp-comparison-plan.md)에 따라 최종 답변과 실제 도구 반환을 각각 대조했다. 종합 결과 기록의 판정은 **MCP 부분 충족, 직접 접근은 정의한 세 사례 충족**이다. 전체 제품 품질의 합격 판정은 아니다.

| 항목 | MCP | 직접 파일 접근 |
| --- | --- | --- |
| 초기 content와 과거/현재 계약 | 필수 사실 반영 | 필수 사실 반영 |
| 블록/문서 복구와 예외 | 영구 삭제된 문서의 복구 제외 조건 누락 | 해당 예외까지 반영 |
| p99 성능 목표 | 확정 수치 미확인으로 설명. 추가 debounce 예시의 출처 표시는 부족 | 확정 수치 미확인으로 설명하고 정성 기준과 구별 |
| 질문 처리 시간 | 90.969초 | 58.014초 |
| 내부 모델 응답 | 21회 | 4회 |
| 입력 토큰 | 718,598 | 136,432 |
| 위 입력 중 캐시 | 680,448 | 100,096 |
| 출력 토큰 | 3,489 | 2,543 |
| 질문 처리 중 추가 승인 | 없음 | 없음 |

캐시 입력은 입력 토큰에 포함돼 있으므로 다시 더하지 않는다. 원시 총토큰은 각각 722,087과 138,975로 약 5.20배지만, 반복된 캐시 입력의 비중이 크다. 캐시를 제외한 입력과 출력을 합치면 41,639와 38,879로 약 1.07배다. 어느 값도 구독 잔량이나 실제 청구액으로 환산하지 않는다. 시작 실패와 사람의 대기 시간은 위 질문 처리 시간에 포함되지 않는다. MCP 사용량 기록과 직접 사용량 기록은 모든 내부 응답을 합산하고 마지막 누적값과 대조했다.

## 실패와 결과의 해석

- **MCP 원문 전달과 답변 누락:** 본문 대조 기록에서 읽기 7회와 정상 검색 17회의 반환 본문/위치가 사본과 일치했다. 영구 삭제 후 복구 불가를 설명한 문서도 실제 받았지만 최종 답에 반영하지 않았다. 원문 전달 성공과 답변 완전성은 별개이며 의미 검토 기록은 부분 충족으로 남긴다.
- **이어 검색 값의 변경:** cursor 대조 기록에서 도구가 반환한 472자 값과 다음 호출의 476자 값이 달랐다. 검증용 서명은 그대로이고 본문 바이트가 달라 `expired_cursor`로 거부됐다. 서버 재시작이나 시간 만료로 단정하지 않는다. AI는 오류를 알리고 별도 문서를 읽었지만 그 검색의 전체 수집은 끝내지 않았다. 잘림에 대한 축소 재시도가 발생한 사례도 아니다.
- **직접 접근의 실패와 재읽기:** 첫 광역 검색은 출력이 잘렸고, UTF-8을 명시하지 않은 첫 파일 읽기에서 한글과 일부 줄 위치가 원문과 달랐다. 같은 사용자 요청 안에서 UTF-8을 명시해 주요 문서 4개와 요구사항 구간을 다시 읽었다. 원문 대조 기록과 의미 검토 기록은 마지막 수신과 답변을 확인하며 앞선 실패를 없애지 않는다. 평가자가 추가 모델 요청으로 고친 결과는 아니다.

MCP의 `QUERY_A` 검색은 33/71줄 뒤 실패했고 `soft delete` 검색은 37/51줄까지만 받았다. 자료 탐색 질문이므로 모든 검색의 전수 수집 자체를 필수로 하지는 않지만, 이를 전체 검색 완료로 보고하지 않는다. 직접 접근의 첫 광역 검색도 전수 수신으로 인정하지 않는다.

이번에는 직접 접근이 더 적은 내부 응답으로 필수 조건을 충족했다. 다만 MCP는 단일 문자열 검색, 직접 방식은 정규식 검색과 여러 파일 읽기를 사용했다. 서로 다른 품질의 한 쌍이므로 순수 MCP 통신 비용, 모든 작업의 우위나 개선율을 확정할 수 없다. 과거의 8줄 답변 제한을 제거한 차이도 있고, 기존 실패 사례의 회귀 비교이지 새로운 독립 평가가 아니다.

## 보존과 다음 작업

보존 검사 기록에서 원본 86개, 시험 파일/설정 131개, 제품 Git HEAD/index/status와 닫힌 근거 30개의 체크섬이 유지됐다. 전역 Codex 설정 해시는 TUI 시작 전과 달라졌다. 시험 코드나 평가 도구가 그 파일을 수정하지는 않았지만, 사전 본문이 없으므로 달라진 항목 전체를 신뢰 등록 하나로 확정하지 않는다. 기존 설정을 임의 복원하지 않는다.

기본 전용 시작 명령과 직접 접근 방향은 유지한다. MCP는 이어 받기 정보를 정확히 전달하는 방법, 오류의 구분과 필수 예외 검토를 보완할 대상으로 남긴다. 직접 시작의 권한 확인과 Windows 문자 인코딩도 기존 준비/검증 범위에 연결한다. 이번 두 요청을 반복하거나 후보를 중간에 바꾸지 않으며, 새 모델 시험과 첫 MCP 제공 결정은 별도 판단이다. 자동 축소, 내부 취소/늦은 응답, 쓰기/복원의 미검증도 유지한다.

cursor를 분석하는 과정의 두 파서 가정 오류는 분석 시도 기록에 보존했다. 받은 호출 값이 JSON/UTF-8일 것이라는 가정을 제거하고 실제 문자열/바이트를 대조했다. 후보와 시험 모델을 다시 실행하지 않았다.

## 실행 순서와 보존

1. MCP 새 대화의 현재 설치본, 모델/추론 수준, 경로, 권한과 두 도구 연결을 확인했다.
2. MCP 요청 기록을 한 번 실행하고 실제 로그/답변/추가 승인과 근거 반영을 대조했다.
3. 직접 접근 프로젝트의 새 대화를 열고 외부 사본 권한을 확인한 뒤 직접 요청 기록을 한 번 실행했다. 첫 시작 실패는 별도로 보존했다.
4. 두 결과의 사실/예외/인용과 도구 수신을 먼저 평가하고, 실패를 포함한 시간/사용량과 사람 개입을 구분해 비교했다. 모델/질문/사본은 같았고 첫 시작 인자와 탐색 방법의 차이는 분리해 기록했다.

공통 질문은 같고 정답표/이전 답변은 시험 입력 밖에 있다. 이번 두 요청 안에서 여러 모델 응답/도구 호출이 발생할 수 있다. 실패한 요청을 임의로 재실행하거나 출력 한도/지연을 조작하지 않는다. 실제 잘림이 없다면 자동 축소는 미관측으로 유지하며 이번 품질 비교가 오류 복구 전체나 MCP 첫 제공의 검증을 대신하지 않는다.
