# WIKI 수신 경계와 사용자 환경 변경의 검토

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 지정 작업일은 2026-11-20이다. 실제 화면 중단과 후속 읽기를 마친 뒤, 남은 수신/환경 검증을 구체화했다. 이번에는 **기존 기록과 공식 소스만 읽었고 새 AI 요청, MCP 실행, 모델/설정 변경은 하지 않았다.** 원시 관측과 출처, 해시는 검토 기록 기록에 있다.

## 확인한 사실과 남은 차이

11/18 실제 비교에는 직접 접근 한 출력과 MCP 두 출력에 호스트의 잘림 경고가 있다. 각각의 call ID와 경고를 기존 자료에서 확인했으며 당시 후보/환경의 근거로 유지한다. 새 후보에서 복구까지 성공한 것으로 바꾸지 않는다.

| 구분 | 확인한 것 | 확인하지 못한 것 |
| --- | --- | --- |
| 도구의 페이지 분할 | 현재 후보의 전체/구간/검색 표본에서 본문과 진행 정보 대조 | 모든 환경의 최종 모델 입력 전체 |
| 호스트 출력 잘림 | 이전 실제 비교의 경고와 빠진 출력, 현재 공식 소스의 출력 처리 계층 | 현재 후보에서 잘림을 알아채고 작은 단위로 재요청하는 실제 행동 |
| 사용자 환경 변화 | 과거의 버전별 일부 관측, 현재 디스크 패키지 0.171.0과 공식 소스의 모델/도구별 출력 정책 | 동일 설치의 갱신 전후 호환성, 모든 모델 변경의 자동 감지 |

현재 후보의 서버 지침은 본문/진행 정보를 한 응답씩 출력하고 중복 표현을 피하도록 안내한다. 이는 여러 페이지를 한 출력에 합치는 위험에 대한 보완이다. 서버는 호스트가 모델에게 실제로 전달한 내용 전체를 알 수 없으며, 출력 전에 길이나 해시를 확인했다고 그 뒤의 수신까지 보장하지 않는다.

현재 설치본에 대응하는 공식 소스에서는 일반 MCP 처리의 출력 정책 선택, 코드 실행 결과의 이미 잘린 본문, 대화 이력 준비의 별도 처리를 확인했다. 구조화 결과를 텍스트 미리보기로 바꾸는 잘림 함수도 있다. 각 코드 경로의 존재를 이번 요청에서 그 분기가 실행됐다는 증거로 취급하지 않는다. [공식 설정 설명](https://learn.chatgpt.com/docs/config-file/config-reference)은 MCP 도구별 출력 예산과 이력 저장 예산을 구분한다. 이 값들은 설정의 뜻이며 현재 대화의 적용값이나 WIKI 서버에 자동 전달되는 정보가 아니다.

## 다음 검증의 입력

1. 정상 페이지와 호스트 잘림을 구별한다. 정상 `output_limit`은 이어 읽기가 필요하다는 뜻이다. 호스트가 본문을 잘랐다면 그 응답을 만든 입력을 유지하고 더 작은 전달량으로 다시 받아야 한다.
2. 재요청에서 같은 원문과 빠진 구간을 확인한다. 두 번째 페이지가 잘렸는데 세 번째 페이지로 넘어가거나, 길이/끝 표식만으로 전체를 읽었다고 판단하면 실패다. 원문 식별이나 진행을 확인할 수 없으면 미완료로 알린다.
3. 원문에 적힌 경고 문자열과 실제 호스트 경고를 구별한다. 표시 없는 누락까지 서버만으로 감지할 수 있다고 가정하지 않는다.
4. 사용자가 설치본, 모델이나 관련 설정을 바꿨을 때 확인할 경계를 구분한다. 현재 선택을 보존하고 관련 연결/반환만 다시 확인하며, 이전 숫자표나 디스크 버전으로 실행 중 조건을 대신하지 않는다.

상세 동작은 [잘림 후 읽기 — 「잘림을 구별하고 다시 읽는 순서」](../../../design/integration/mcp.md), 변경 시점은 [환경 확인 경계 — 「환경 변경을 확인할 경계」](../../../design/runtime/entry.md), 판정은 [수용 입력 — 「MCP 읽기 보완의 검증 입력」](../../../verification/acceptance.md)이 소유한다. 현재는 시험 입력의 구체화이며 새 기능의 실행 결과가 아니다.

바로 모델 요청을 반복하기 전에 현재 후보 지침에 없는 대응, 재시도 종료 조건과 확인 수단을 먼저 정한다. 실제 잘림이 발생하지 않았으면 그 사실대로 기록한다. 작은 호스트 상한, 임의 모델 변경이나 부풀린 입력으로 실제 사용 검증을 만들지 않는다. 별도 진단이 필요하면 제품 적합성 근거와 구별하고 범위를 정한다.

## 보호와 조사 범위

백업은 2026-11-21 00:21:42 KST 생성 백업(식별자 `hqqOz84s`)이며 변경 범위 기록에 네 문서와 비교 기준을 기록했다. 앞선 시험 근거, 후보 소스, 기존 시험 프로젝트 원문과 Git/index, 사용자 설정은 보호 대상이다. 실제 모델, 서버, 패키지 설치나 업데이트를 실행하지 않았다.

공식 Codex 소스 네 개는 정확한 commit에서 임시 폴더로 읽었다. 동일 revision의 Apache-2.0 확인을 재사용했으며 소스를 제품이나 이 근거에 복제하지 않았다. 브라우저의 한 페이지 조회 실패와 샌드박스 DNS 차단은 조사 도구의 문제였고, 승인된 읽기 전용 재시도로 자료를 확보했다. WIKI 읽기 실패나 제품 시험 실패로 세지 않는다.

이번 정리로 첫 MCP 제공을 확정하거나 수신/환경 검증 전체를 통과 처리하지 않는다. 현재 관측과 미확인을 유지하며 진행표의 다음 보완 단위로 돌아간다.

문서/보존 검사 기록을 통과했다. Markdown 6개와 내부 링크/제목 443개, 원문 86개, 후보 네 파일/설정 세 개, 이전 근거 46개와 백업의 다른 파일 3,066개를 대조했다. 기존 제목과 제품 Git/index는 보존됐고 Obsidian의 최근 열기 목록은 사용자 화면 상태로 유지했다. 보고서 생성 뒤 이 링크도 확인했다. 현재 근거의 체크섬은 `SHA256SUMS`에 보존한다.
