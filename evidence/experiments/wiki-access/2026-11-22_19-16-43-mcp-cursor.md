# 짧은 이어 읽기 값과 요청 보관 후보

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 작업일 2026-11-21, 실제 실행일 UTC 2026-11-22. 사용자는 충분한 대안 조사를 확인한 뒤 출력 안내 기준을 반영하고 이어서 진행하도록 요청했다. 직전 [입력 안내 후보](2026-11-22_18-26-09-mcp-inputs.md)를 보존한 새 사본에서 최소 요청 정보 보관을 구현/검사했다. 제품 첫 MCP 제공이나 추가 AI 시험의 승인이 아니다.

## 문제와 변경

이전 실제 AI 비교에서는 긴 이어 읽기 값이 두 번 변형됐다. 이번 후보는 원래 경로/검색 조건을 서버에 한 번 보관하고, 임시 요청 식별자와 위치를 서명한 88자 값으로 이어 받는다. 동일한 입력은 동일한 위치를 뜻하며 완료 후 재시도에서도 읽는 위치를 소비하지 않는다. 클라이언트는 값을 해석하거나 다시 생성하지 않고 그대로 전달한다.

`continuation.py`는 요청 정보의 보관/수명과 값 발급을, `reader.py`는 원문 읽기/검색과 마지막 검사를, `server.py`는 MCP 연결과 실행 옵션을 맡는다. Windows 경로 보호 `files.py`, 입력/출력 계약 `contract.py`와 검사 전송부 `transport.py`는 그대로 유지했다. 새 패키지, DB, 색인, 문서 본문 캐시와 상시 서비스를 추가하지 않았다. 원문 검사를 매 페이지 수행하는 비용은 그대로다.

검색 위치는 정렬된 파일 번호와 줄의 바이트 위치로 표현한다. 파일 목록/원문 집계가 바뀌면 이전 페이지와 섞지 않는다. 페이지 크기 탐색 중 임시 응답은 저장하지 않고 실제 반환 결과에 next가 있을 때만 요청을 보관한다. 최종 원문/연결 검사 전에 취소되거나 오류로 끝난 초기 호출은 다른 요청을 밀어내지 않는다. 등록 뒤 전송 중 취소/응답 유실이 생기면 기록이 남을 수 있으며, 등록 성공 자체를 클라이언트의 본문 수신 증거로 쓰지 않는다.

## 보관 한도와 재시도

현재 후보의 실제 기본값은 요청 128개와 직렬화 요청 정보 합계 1MiB다. 서버 실행 인자 `--request-limit`, `--request-bytes`로 조정할 수 있다. 모델 토큰, 원문 전체 크기나 전체 Python RAM 한도가 아니며 사용자 환경 전체에서 측정한 최적값도 아니다. 별도 시간 TTL은 두지 않는다.

한도에 도달하면 사용하지 않은 지 가장 오래된 요청부터 정리한다. 해당 순간 서버가 처리 중인 호출은 보호하고 파일 I/O 동안 전체 저장소를 잠그지 않는다. 반환 후 다음 호출을 기다리는 논리적 작업은 정리 대상이 될 수 있다. 본문 페이지마다 보관량이 증가하지 않지만 서로 다른 초기 요청은 별개로 센다.

자리가 부족하거나 요청 하나가 한도를 넘으면 `cursor_capacity`로 거부한다. 실패를 예상하면서 기존 기록부터 삭제하지 않는다. 정리/재시작/다른 연결/변형으로 사용할 수 없는 이어 값은 `expired_cursor`로 알린다. 시간이 지났다는 뜻으로 단정하지 않고, 기존 본문과 섞지 않은 새 요청으로 처리해야 한다. 같은 값의 정상 재시도와 작은 페이지 재시도는 같은 시작 위치를 유지한다.

## 확인 결과

최종 검증 기록: Windows 코드/STDIO SDK **63개 조건 최종 PASS**, 총 실행 64개. 처음 62개 중 이전 상한 안내를 반영하지 않은 묶음 SDK 검사 1개가 실패했다. 실제 maximum/default/description을 검증하도록 고친 뒤 해당 메서드만 재실행했고, 나머지 61개는 재사용했다. 실제 SDK의 기본 보관 한도/정리 검사 1개를 추가했다. 실패와 source 사본 구성의 줄바꿈 오류는 이력 기록에 보존했다.

## 한계와 다음 순서

짧은 값도 모델이 잘못 입력할 수 있다. 도구 설명/서명/요청 보관이 늘거나 페이지당 본문이 달라진 효과를 포함해 실제 모델의 원문 수신, 오류 설명, 호출/토큰/시간을 비교해야 한다. 기존 길이 528~1052자 사례와 새 형식 88자를 실제 토큰 절감률로 바꾸지 않는다. 본문을 요약/생략해 전체 읽기를 완료로 처리하지 않는다.

다음은 직접 접근/긴 값 MCP/짧은 값 MCP의 실제 비교 기록 범위와 비용 합의다. 각 방식에 같은 문서 60개를 복사했고 총 196개 파일과 Windows 설정/경로를 사전 확인 기록했다. 새 AI 요청은 한 번씩 총 3회로 제안하며 아직 실행하지 않았다. 현재 설치본과 사용자 선택 모델을 따르고 앞선 두 요청의 승인을 재사용하지 않는다. 결과로 첫 MCP 제공 여부를 판단한 뒤 부모 4단계 파일별 변경 명세로 복귀한다. 기본 직접 접근과 쓰기/복원/실제 잘림의 미검증 경계를 유지한다.

설계 원칙의 근거는 [관측 기록 (직전 조사)](2026-11-22_18-26-09-mcp-inputs.md)에 있다. 외부 코드를 복제하지 않고 기존 Python 표준 기능으로 작성했다. 기존 의존성의 최종 배포 라이선스 검토가 완료됐다는 뜻은 아니다. 검사기 임시 위치, 개발 작업 경로와 운영 규칙은 배포물에 포함하지 않는다.
