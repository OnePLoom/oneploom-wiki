# MCP 입력 안내 보완

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 작업일은 2026-11-21이며 실제 실행일은 UTC 2026-11-22다. [통합 비교](2026-11-21_22-27-02-mcp-batch.md)에서 등록 상한을 알리지 않은 입력 오류가 발생해, 기존 후보를 보존한 새 사본에서 보완했다. 목적은 현재 설정값을 추측하지 않아도 되는 입력 계약이다. 긴 cursor 전달 방식은 [별도 선택 — 「이어 읽기 전달 방식의 선택」](../../../design/integration/mcp.md)으로 남긴다.

## 변경과 범위

- 도구 목록 조회 시 현재 프로젝트 연결의 페이지 상한/기본값을 모든 초기/이어 입력 분기에 표시한다. 논리 JSON의 UTF-8 바이트 수이며 모델 토큰이나 Codex의 출력 상한을 뜻하지 않는다.
- 실제 실행도 현재 연결 설정으로 검사하고 초과 입력에 허용값과 수정 방법을 알린다. 설정이 바뀌어 예전 도구 선언이 남아 있어도 현재 값을 기준으로 거부한다.
- 잘못된 연결 설정으로 목록 조회가 실패하면 예전 값을 대신 제공하지 않는다. 설정을 바로잡은 뒤 같은 프로세스에서 다시 조회할 수 있다.
- 두 도구, 기본 페이지 설정과 출력 계약은 유지한다. 파일 접근 보호, 검색/읽기/서명 처리와 원문은 변경하지 않았다. 모델 호출, 설치/업데이트, 기존 시험 연결/전역 설정 변경은 없다.

계획 기록, 시작 기준선 기록, 실패와 수정 이력 기록을 보존했다. 새 제품 배포나 전체 사용자 흐름의 완료가 아니다.

## 검사와 한계

최종 검사 연결 기록: Windows에서 서로 다른 9개 조건의 최종 PASS. 최초 9개 실행 중 검사기 기대값 2개가 실패해 해당 2개만 보정 후 재실행했다. 총 실행 11개이며, 검사 전 기본 Python의 import 실패 1회는 별도로 기록했다. 기존 가상환경을 사용했고 의존성을 새로 설치하지 않았다.

| 확인 범위 | 관측 |
| --- | --- |
| 두 MCP 규격의 목록 선언 | 단일/묶음/이어 입력에 현재 설정의 최대/기본값 표시 |
| 입력 경계와 실행 | 생략, null, 정수/동일 값 실수, 작은 값, 초과/잘못된 타입의 허용/거부 일치 |
| 설정 변경 | 캐시된 예전 상한의 요청 거부, 현재 값 안내, 목록 재조회와 실행에 새 값 반영 |
| 잘못된 설정 | 목록 오류와 호출 오류 구별, 잘못된 기본값 대체 없음, 설정 복구 후 재조회 |
| 프로젝트 분리 | 두 프로젝트의 서로 다른 등록 상한을 각각 유지 |
| 이어 읽기 | 작은 크기로 이어도 UTF-8/CRLF 원문 전체와 byte 위치 일치 |
| 기존 영향 검사 | 전체/구간/검색/오류의 이전 SDK 검사와 다른 규격, 실행 중 취소 보호 유지 |

작은 설정값과 합성 문서는 경계 검사 입력이며 배포 기본값이나 실제 Codex 성능 시험이 아니다. 실제 호스트가 바뀐 선언을 모델에 전달하는지, 입력 오류가 줄어드는지, 선언의 추가 입력 비용까지 포함해 이득인지 아직 측정하지 않았다. 자동 schema 변경 알림이나 새 AI 비교를 실행하지 않았다.

초기 실패 중 Windows 줄바꿈은 원문 보존이 올바르게 작동한 결과였다. 단일 읽기 완료도 기존 `stop_reason=eof`와 `next=null` 계약을 그대로 사용했다. 기대값을 바꿔 실패를 숨긴 것이 아니라, 틀린 검사 가정을 실제 원문/기존 계약에 대조해 바로잡았다. 각 시도의 원시 로그와 해시를 `checks/`에 남겼다.

## 근거와 후속 순서

[JSON Schema numeric](https://json-schema.org/understanding-json-schema/reference/numeric#range)의 maximum과 [MCP tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)의 도구 선언/오류 구분을 참고했다. 외부 구현 코드를 가져오거나 새 의존성을 추가하지 않았다. 기존 SDK의 배포 라이선스 확인 완료로 확대하지 않는다.

이어 읽기 방식 조사 기록은 사용자가 선택 전에 충분한 비교를 요청해 확장한 판단 근거다. 공식 규격과 SDK, 실제 구현 사례를 대조하고 기존 로그의 문자/바이트 집계 기록을 보존했다. 요청 정보만 한 번 보관하는 후보로 추천을 좁혔지만, 새 저장 방식의 구현과 AI 실행을 승인받은 것으로 해석하지 않는다.

설계 동기화와 입력 안내 검사 뒤에는 이어 읽기 값의 저장/전달 방식 선택, 해당 코드 검사, 별도 합의한 실제 비교, 첫 MCP 제공 여부 판단 순서로 진행한다. 기본 직접 접근은 유지한다.
