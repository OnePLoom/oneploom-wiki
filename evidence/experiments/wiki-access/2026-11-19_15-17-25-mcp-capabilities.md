# MCP 실행 조건의 확인 범위

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 작업일은 2026-11-19다. 사용자 버전/모델을 고정하지 않고 현재 실행 조건을 확인하려는 [진입 명세 — 「실행 조건의 확인과 미확인 처리」](../../../design/runtime/entry.md)의 근거다. **정적 확인이며 실제 MCP 통신이나 제품 사용 시험이 아니다.**

## 입력과 방법

WSL Python의 표준 라이브러리로 Windows 시험 공간에 설치된 MCP 타입 선언과 기존 Codex 스키마를 읽었다. 소스 기록은 패키지 버전/라이선스, 관련 타입의 필드/줄 번호, 입력 해시만 관측 결과 기록에 저장한다. SDK를 import하거나 Codex/MCP 서버, TUI, 모델을 실행하지 않았다.

- 현재 읽은 패키지: `mcp`와 `mcp-types` 2.3.0. 공통 타입과 2025-11-25/2026-07-28별 타입을 대조했다. 실제 Codex가 어느 프로토콜로 통신하는지는 이번에 관측하지 않았다.
- Codex 자료: [11/18 조회 근거](2026-11-18_17-52-34-host-query.md)에 보존된 0.170.0의 `schema.zip`. 새 사용자 설치본을 조회한 결과나 모든 버전의 고정 API가 아니다.
- 원본 보존: 작업 전 기록 기록의 문서 86개, Git/index와 앞서 읽었던 설정의 해시를 작업 전후 대조한다. 설정 내용, 인증값, 사용자 대화는 복사하지 않는다.
- 외부 자료 이용: 설치된 두 패키지의 메타데이터와 LICENSE에서 MIT 표기/허가문을 확인했다. 외부 구현을 복사하거나 배포물에 포함하지 않았으며, 제품 의존성 채택과 전체 라이선스 검토 완료는 아니다.

실행 명령은 이 폴더에서 `python3 -B source/inspect.py`다. Windows 설치본의 파일을 WSL에서 읽은 것이므로 Windows 실제 실행 적합성으로 해석하지 않는다.

## 확인한 사실과 한계

| 관측 | 해석의 범위 |
| --- | --- |
| MCP의 초기화 또는 요청 메타데이터에는 프로토콜과 지원 기능 정보가 있음 | 확인한 표준 필드에 현재 주 모델의 유효 출력 한도는 없음. `_meta`/확장으로 추가 정보가 올 가능성까지 부정하지 않음 |
| Codex의 `Model` 스키마는 모델 선택과 기능 관련 필드를 제공 | 이 목록만으로 개별/합산 도구 출력의 유효 한도를 결정할 수 없음 |
| `Config` 스키마는 추가 속성을 허용 | 선언된 필드 목록에 없다는 이유로 설정 키가 지원되지 않는다고 단정하지 않음. 설정값과 현재 대화 적용값도 구별 |
| `Thread.model`의 설명은 현재 설정 또는 마지막 저장 모델이며 턴 계측이 아니라고 명시 | 저장된 기록을 현재 실행의 실제 모델/출력 예산으로 확정하지 않음 |
| SDK 공통 `CallToolResult`에는 기본 `result_type="complete"`가 있고 프로토콜별 타입은 다름 | 수기 JSON, 정규화 객체와 실제 전송이 같다는 전제는 부적절. 앞선 크기 실패를 고정 24바이트 추가로 해결할 근거가 아님 |

제품 설계에는 확인 가능한 정보만 활용하고, 모르는 한도는 미확인으로 남기는 방향을 반영했다. 한도 정보가 없어도 범위 보존/실제 수신을 확인해야 하며, 필수 통신 기능 부재와 선택적 정보 부재는 다르게 다룬다. 구체 반환/자원 정책과 실제 호스트의 수신 확인 방법은 아직 완성되지 않았다. 원문을 표시 없이 잘라 전달하는 경우를 서버만으로 모두 감지한다고 보장하지 않는다.

앞선 [SDK 크기 실패](2026-11-18_18-45-45-mcp-read-fidelity.md)와 [실제 Codex 답변 누락](2026-11-18_16-50-18-codex-wiki-usage.md)은 미해결 상태 그대로다. 이번 확인으로 재검증/성공 처리하지 않는다.

## 공식 자료와 검증 기록

[2025-11-25 MCP 스키마](https://modelcontextprotocol.io/specification/2025-11-25/schema)와 [2026-07-28 MCP 스키마](https://modelcontextprotocol.io/specification/2026-07-28/schema)의 관련 요청/반환을 대조했다. 후자의 clientInfo는 진단용 자기 신고 정보이고 기능 판단의 근거로 삼지 않도록 명시돼 있다. 현재 SDK 지원 목록이 호스트의 실제 협상 결과를 증명하지는 않는다. [Codex App Server 안내](https://learn.chatgpt.com/docs/app-server)와 보존된 설치본 스키마도 구별한다.

문서/보존 검사 기록은 링크, 제목, 변경 범위와 보존 결과다. 의미 검토 기록은 설정/실행과 전송/수신의 혼동 여부를 확인한다. 체크섬 기록은 이 폴더 산출물의 저장 후 무결성만 증명한다. 정적 관측과 문서 PASS를 제품 기능의 PASS로 확대하지 않는다.
