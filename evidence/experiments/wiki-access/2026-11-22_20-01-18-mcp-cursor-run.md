# 직접 접근과 긴 값, 짧은 값 MCP의 실제 비교

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 작업일: **2026-11-22**. 승인한 세 사용자 요청을 모두 수집했다. 짧은 값 후보는 필요한 사실 일부와 검색 미완료 보고가 빠져 **동등 품질의 비용 절감이나 제품 수용으로 판정하지 않는다.** 원문 반환 검사의 PASS와 실제 작업의 수용 실패를 구분한다.

## 목적과 실행 조건

긴 이어 읽기 값(cursor)을 짧게 만들면 실제 입력 오류, 반복 호출과 시간이 줄어드는지 확인했다. 직접 파일 접근을 별도 기준으로 두고, 같은 문서 60개와 질문 본문으로 직접 → 긴 값 → 짧은 값 순서의 새 대화를 각각 한 번 실행했다. 긴 값 후보에도 복수 검색, 묶음 읽기와 현재 입력 상한 안내가 들어 있다. 과거 단일 검색 MCP와 비교한 결과가 아니다.

- Windows PowerShell/Codex 0.171.0, GPT-5.6-Sol, 추론 low, Workspace였다. 실행 당시 사용자 화면과 각 로그를 대조했으며 배포 버전을 고정하지 않았다.
- 직접 접근에는 해당 WIKI 사본의 추가 작업 경로를 연결했고, 두 MCP 경로에는 읽기/검색 도구 두 개를 등록했다. 세 요청 모두 사용자가 추가 승인창이 없었다고 확인했다.
- [관측 기록 (비교 준비와 조건)](2026-11-22_19-16-43-mcp-cursor.md), [관측 기록 (실행 승인)](../runtime/2026-11-22_19-53-47-workday-boundary.md)을 따른다. 원본 수정, 새 설치나 추가 AI 요청 없이 기존 로그를 분석했다.
- 실제 질문의 공백/줄바꿈 차이는 보존했다. 직접/긴 값은 공백을 제외한 준비 본문이 같고 짧은 값은 준비 요청과 정확히 일치했다. 이전 답변과 독립 평가 기준을 시험 모델에게 주지 않았다.

토큰은 각 모델 응답의 사용량을 합산했다. 캐시를 포함한 합계와 제외한 합계를 모두 남기며, 어느 값도 구독 잔량이나 청구 금액으로 환산하지 않는다. MCP의 호스트 호출에는 도구 발견 1회가 포함된다. 직접 접근의 4회 호출 안에는 여러 셸 동작이 있어 MCP 16/11회와 일대일 작업 수로 비교하지 않는다. 시간은 질문 시작부터 완료까지이며 준비, 인증과 사람 대기는 제외한다.

원시 수치는 comparison.json 기록, 답변 의미 검토는 직접 기록, 긴 값 기록, 짧은 값 기록에 있다. 수집한 반환문과 원문을 별도로 대조했으며 프로그램 검사만으로 의미 판단을 대체하지 않았다.

## 짧은 값에서 확인한 문제

1. **짧은 값의 전달은 이번 표본에서 성공했다.** 88자 값 5개를 반환 그대로 재사용했다. 긴 값도 이번에는 496~608자 값 10개를 모두 그대로 전달했다. 따라서 이번 두 결과만으로 값 단축이 오류를 줄였다고 증명할 수 없다.
2. **현재 상한을 안내해도 잘못된 입력이 발생했다.** 16,384바이트 상한에 30,000을 요청해 `invalid_arguments`로 거부됐고 16,000으로 수정했다. 이 오류는 최종 답에 알렸다. 실제 호스트 출력 잘림이나 자동 축소 복구 성공이 아니다.
3. **첫 검색을 끝내지 않았으나 남은 범위를 알리지 않았다.** 첫 복수 검색의 실제 일치 283줄 중 193줄을 받았고, 90줄이 남은 next를 사용하지 않았다. 다른 좁은 검색 두 개는 완료했다. 넓은 탐색을 충분한 근거 확보 후 중단하는 선택 자체와, 미완료 상태를 숨기고 검색/읽기가 완료됐다고 보고하는 문제를 구별한다. 90줄 모두가 정답 필수 자료이거나 다른 읽기에서도 전혀 보지 못한 내용이라고 단정하지 않는다.
4. **받은 내용도 답변에서 일부 빠졌다.** 성능에 관한 사전 기준 중 “일반 문서 조회는 빠르게 응답해야 한다”는 항목이 빠졌다. 같은 기준의 자동 저장 빈도와 일관된 응답 시간은 포함했다. 해당 원문 690행은 실제 반환됐으므로 전송 누락이 아니다. 없는 수치 목표를 만들거나 핵심 정책을 뒤집은 주장은 관측하지 않았다.

검색 완료 대조 기록, 원문/위치 대조 기록, 인용 대조 기록에 분리해 기록했다. 정상 반환된 검색 205줄과 읽기 7구간은 원문에 일치했고 호스트 잘림은 관측되지 않았다. 첫 검색의 정상 페이지 구분 `output_limit`을 도구 오류로 세지 않는다.

## 직접 접근과 긴 값의 한계

직접 접근은 첫 광역 검색의 출력 잘림과 잘못된 구간/인코딩 읽기 뒤 같은 요청 안에서 재조회했다. 필수 사실은 모두 반영했지만 인용 범위 하나의 두 줄은 실제 반환에서 확인되지 않았다. 평가자가 나중에 읽은 원문을 모델이 받은 내용으로 세지 않는다. 따라서 직접 접근도 무누락 기준선이나 제품 전체 검증 완료가 아니다.

긴 값은 검색 3개를 모두 끝냈고 검색 결과 368줄과 읽기 9구간, 인용 10범위를 원문과 대조했다. 입력 오류나 값 변형은 관측하지 않았지만 단건 결과로 일반 무오류를 보장하지 않는다.

짧은 값은 긴 값보다 검색 결과를 적게 받았지만 읽기 본문은 더 많았다(20,050/15,186바이트). 질의와 근거 선택이 달라 cursor 길이 하나의 효과를 분리할 수 없다. 호스트 로그의 원문 일치는 숨겨진 최종 모델 입력 전체의 수신 증명이 아니다.

## 해석과 다음 판단

짧은 값은 긴 값보다 누적 토큰이 51.6%, 캐시 제외 합계가 37.2%, 시간이 45.7% 적었다. 그러나 검색 처리량과 답변 품질이 달라 **같은 일을 완수한 최적화 성과로 인정하지 않는다.** 직접 접근과 비교하면 캐시 제외 합계는 62.2%, 시간은 37.4% 많았다. 서로 다른 방식의 단건 수치이며 일반적인 MCP 성능/요금 비율이 아니다.

기본 전용 시작 명령과 직접 접근은 유지한다. 현재 결과와 핵심 제품의 일정 제약을 함께 고려하면 **첫 배포의 MCP 제공을 미루고 부모 4단계 명세로 복귀하는 안을 추천**한다. 이는 사용자 선택 전인 추천이며 MCP 연구/코드/실패 근거 삭제나 향후 다중 AI 연계 포기를 뜻하지 않는다. 다른 호스트가 문서 도구를 재사용하는 이점은 아직 실제 사용자 편익으로 검증하지 않았다.

계속 보완한다면 값 길이보다 요청별 미완료 범위의 전달과 최종 답변 검토, 상한 입력 처리까지 호출 흐름에서 연결할 필요가 있다. 지침 추가만으로 해결됐다고 선언하지 않고 실제 선택된 호스트에서 확인해야 한다. 추가 AI 실험은 이번 승인 세 요청에 포함되지 않는다. 쓰기/복원, 큰 자료, 실제 자동 축소와 내부 취소/늦은 응답의 미검증도 그대로 남는다.

## 보존과 검증의 범위

준비된 시험 파일과 원본 문서, 기존 시험 프로젝트 추적 파일, 이전에 닫힌 근거와 Git 상태를 비교한다. 전역 Codex 설정 파일의 해시는 최초 TUI 전과 이후가 달랐다. 사전 본문이 없어 변경 항목과 원인을 확정하지 못하며, 전체 설정이 동일했다고 주장하거나 임의 복원하지 않는다. 수집/검토 도구는 해당 설정을 쓰지 않았다. 화면/로그상 버전, 모델, 추론과 승인 정책은 대조했다.

현재 run에는 계정 식별자와 숨겨진 추론/시스템 지침을 복사하지 않았다. raw 답변/도구 출력, 집계기 소스, 의미 검토와 한계를 보존한다. 보존 검사는 preservation.json 기록, 문서 검사와 범위는 document-check.json 기록, 완료 상태는 progress.json 기록, 최종 파일 해시는 SHA256SUMS 기록에서 확인한다. 문서/보존 PASS를 후보의 사용자 작업 PASS로 바꾸지 않는다.
