# Windows 로컬 MCP 읽기와 검색 시험

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 작업일: 2026-11-18. ADR 0022의 선택 MCP 비교 준비다. 실제 제품 설치와 구분한다.

## 범위와 준비

- Windows Python 3.13.9, 공식 MCP SDK 2.3.0. 독립 가상환경에 다운로드한 wheel 29개를 설치했고 `pip check`가 통과했다.
- SDK와 의존성의 패키지 메타데이터, 해시, 포함된 라이선스/고지를 `packages.json`과 `licenses/`에 보존했다. SDK의 MIT 조건을 확인했다. 이는 이번 격리 사용의 검토이며 제품 전체의 재배포 권리 검증 완료가 아니다.
- `mcp-20261118` 안의 project-a/b, wiki-a/b만 사용한다. A는 14일, B는 7일이라는 합성 반품 정책이다. 실제 제품과 개인 WIKI를 입력으로 사용하지 않는다.
- 코드의 읽기와 검색을 같은 `Wiki` 객체로 구현하고 MCP 연결부는 요청/응답 변환을 맡는다. 쓰기, Git, 임의 shell 실행 도구를 제공하지 않는다.
- 백업: 2026-11-18 15:15:13 KST 생성 백업(식별자 `PkjbH1I7`). 원본 프로젝트의 Git/index는 변경하지 않는다.

## 자동 검사와 첫 실패

| 실행 | 관측 | 근거 |
| --- | --- | --- |
| 격리 설치와 의존성 검사 | 종료 코드 0, 의존성 충돌 보고 없음 | `initial/install.*`, `initial/dependencies.*` |
| Windows 파일 검사 | 9개 통과. 한글/원문, 경계, 링크/junction 거부와 프로젝트 구분 | `initial/unit.stderr` |
| 첫 SDK 통신 검사 | 구조화된 결과가 None이라 실패 | `initial/protocol.stderr`, 당시 `initial/source/` |
| 보완 뒤 같은 통신 검사 | A/B 각각 auto/legacy 연결, 총 4회 통과 | `protocol.json`, `protocol.stdout`, `protocol.stderr` |

SDK 2.3.0의 반환 타입 자동 판별에서 bare `dict`는 출력 스키마를 만들지 않았다. 명시적 `dict[str, Any]`와 구조화 출력 설정을 사용하고, 응답 오류/출력 스키마/결과 부재를 검사하도록 보완했다. 실패를 정상 텍스트 응답으로 덮지 않았다. 변경하지 않은 파일 처리 코드의 9개 PASS는 재사용했다.

auto 연결은 프로토콜 2026-07-28, legacy 연결은 2025-11-25로 관측됐다. 두 프로젝트 모두 자기 원문과 검색 결과를 반환했고, 범위 밖/절대/숨김 경로 요청은 도구 오류였다. WIKI 파일의 전후 해시가 같았다. 4회 연결의 측정치는 원시 JSON에 있지만 Codex UI 지연이나 모델 비용의 비교값이 아니다. 모델 호출은 0회다.

## 실제 Codex 연결

시험 프로젝트 두 곳에 같은 MCP 설정을 만들었다. 전역 Codex 설정의 바이트가 그대로인 것을 준비 전후 확인했다. 초기 모델 없는 설정 조회는 서버를 찾지 못했다. 이후 실제 TUI에서 프로젝트 설정이 발견됐으며, 사용자 신뢰 선택의 정확한 화면은 아직 수집하지 않았다. [공식 신뢰 조건](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)은 설정 발견과 실행을 구분하는 근거다.

첫 TUI의 `/mcp`는 `wiki_probe: failed (0 tools)`였다. 관련 Windows 로그의 시작 오류는 `지정된 경로를 찾을 수 없습니다. (os error 3)`다. 설정 조회에서 `cwd`가 `..` 그대로인 것도 확인했다. 최초 설정과 사용자 관측은 `host-first/`에 보존했다.

잘못 지정한 상대 `cwd`를 제거했다. 같은 버전의 [공식 실행 코드](https://github.com/openai/codex/blob/rust-v0.169.1/codex-rs/rmcp-client/src/stdio_server_launcher.rs)는 명시한 cwd가 없을 때 호출 측 작업 위치를 사용한다. 루트에서 다시 연 실제 Windows Codex에서 사용자가 `wiki_probe: connected (2 tools)`를 확인했다. 전역 설정/권한을 바꾸거나 개인 경로를 공유 설정에 고정하지 않았다.

설정 조회는 A 루트/하위 폴더에서 종료 코드 0, 아직 TUI를 열지 않은 B는 서버 미발견이었다. **하위 폴더에서 설정이 조회되는 것과 상대 실행 경로로 실제 서버가 뜨는 것은 다르다.** 하위 폴더 실제 진입, B의 TUI와 재개는 후속 관측으로 확인한다. SDK 시험의 절대 실행 경로를 일반 Codex 진입 성공으로 대신하지 않는다.

이어서 사용자가 실제 Codex에 검색/읽기 요청을 입력했다. 답변은 A, 14일, 미사용, `정책/반품.md`로 원문과 일치했으며 추가 승인창이 없었다고 보고했다. 해당 합성 세션의 도구 기록에서도 목록 조회 뒤 `mcp__wiki_probe__search_notes`, `mcp__wiki_probe__read_note` 호출과 결과를 확인했다. 다른 파일 도구로 대신 읽은 호출은 없었다. 모델은 GPT-5.6-Sol, reasoning low였고 시험 WIKI 4개 파일의 해시는 최초와 같았다. 사용자 보고는 `tui.json`, 필요한 세션 기록만 추출한 근거는 `tui-trace.json`이다. 전체 대화나 계정/인증 자료는 복사하지 않았다.

실제 Codex 연결 로그의 프로토콜은 2025-06-18이었다. SDK 클라이언트의 auto/legacy 관측과 다르며 어느 한 버전으로 통일해 기록하지 않는다. 토큰 사용 이벤트도 해당 세션의 표본으로 보존했지만, 같은 입력/문맥의 직접 접근 대조군이 없어 비용 우위는 판단하지 않는다.

## 한계와 다음 확인

- 현재 일반 Codex는 A 루트 진입의 연결, 실제 검색/읽기와 추가 승인 없음 표본을 확인했다. 다른 초기 설정, 반복 승인 재사용과 모든 사용자 환경으로 확대하지 않는다.
- 읽기 전용 시험이다. 편집, 동시 파일 교체 보호, 중단/재개와 제품 복구/DB 기능을 검증한 것이 아니다.
- 64 KiB 파일과 100개 검색 파일 제한은 작은 시험의 한도다. 제품의 대규모 문서 정책으로 채택하지 않았다.
- SDK 프로세스 시작과 읽기는 모델 없는 코드지만 실제 AI의 도구 선택, 설명/반환 본문에는 토큰이 쓰인다. 이전 시작 명령 시험과 입력/문맥이 달라 직접 비용 우위를 비교할 수 없다.
- 패키지 다운로드의 전체 콘솔 로그는 보존하지 못했다. wheel 메타데이터/해시와 이후 설치 출력은 보존했다. 의존성별 최종 제품 고지, 지원 Python과 패키징 정책은 후속이다.
- 기본 시작 명령 채택과 MCP 첫 배포 포함 미확정 상태를 유지한다. 다음은 B/재개/하위 경로의 실제 연결과 같은 조건의 비교 입력을 준비하는 것이다. 읽기 검증만으로 쓰기 기능까지 확대하지 않는다.

## 자료 안내

`source/`는 최신 자체 시험 코드, `initial/`은 최초 실패와 당시 소스, `host-first/`는 첫 Codex 경로 실패다. 현재 설정/조회 결과는 `host/`, SDK 통신 결과는 `protocol.json`이다. `SHA256SUMS`는 이 기록의 자료 대조용이며 제품 release 검증 결과가 아니다. 개념 설명은 [로컬 MCP 학습](../../../explanations/mcp.md)에 연결한다.
