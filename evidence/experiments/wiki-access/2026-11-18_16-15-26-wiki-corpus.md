# 실제 문서 비교 입력의 사전 확인

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 작업일: 2026-11-18. [두 경로 비교 계획 — 「실제 문서를 이용한 읽기와 검색 비교」](../../../verification/acceptance.md)을 준비하기 위한 읽기 전용 목록이다. 성능 측정이나 자료 사본 생성, 모델 실행 결과가 아니다.

## 확인 범위

Git이 추적하는 `docs` Markdown만 경로, 크기와 SHA-256으로 조사했다. HEAD와 목록은 inventory.json 기록에 있다. 실행 상태, 무추적 기록과 다른 디렉토리를 포함한 모든 문서 개수를 뜻하지 않으며 각 파일의 내용을 안전/공개 가능한 입력으로 승인한 것도 아니다.

| 항목 | 관측 |
| --- | --- |
| 추적 Markdown | 86개 |
| 전체 크기 | 580,507바이트, 약 567 KiB |
| 64 KiB 초과 | docs/REQUIREMENTS.md, 72,422바이트 |
| 현재 MCP 시험 제한 | 검색 100개 파일, 파일 읽기 64 KiB. 문자열 casefold 검색이며 별도 색인 없음 |
| 원본/구현 변경 | 없음. 목록의 바이트 해시와 개발 Git 상태를 작업 뒤 다시 대조 |
| 모델 호출/복사/측정 | 없음 |

현재 search는 검색 범위 안 Markdown마다 read를 호출하므로 위 큰 문서를 그대로 포함하면 크기 제한에서 실패할 것으로 코드상 판단한다. 전체 문서 검색을 실제 실행한 결과는 아니다. 파일 수 제한 안에 있다는 사실만으로 전체 호환을 통과 처리하지 않는다. 이는 MCP 규격의 제한이 아니라 작은 자체 시험 구현의 제한이다. 한도를 임의로 올리거나 큰 파일을 몰래 제외해 좋은 점수만 얻지 않으며 부분 읽기/검색 범위와 결과 잘림을 다음 시험 입력에 명시한다.

## 실행 명령 확인

현재 설치된 codex.ps1과 codex.cmd는 같은 npm 패키지의 bin/codex.js를 실행한다. 두 시작 파일의 해시만 inventory에 남겼고 외부 코드를 배포물에 복제하지 않았다. PowerShell에서 ps1이 먼저 선택되고 Restricted 정책으로 차단된 기존 관측은 [Windows 준비 기록](../runtime/2026-11-11_07-36-47-windows-readiness.md)에 있다. 현재 실행 정책을 다시 실행하거나 변경한 것은 아니다.

사용자가 명령 이름을 입력하는 경우 확장자를 지정해 의도한 실행 파일을 고를 수 있다. 이 점은 [Microsoft의 명령 우선순위](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_command_precedence?view=powershell-5.1), 스크립트 차단은 [실행 정책](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_execution_policies?view=powershell-5.1)을 참고했다. cmd를 택하는 것만으로 프로그램의 임의 인자 전달/보안이 모두 해결된다는 판단은 하지 않는다.

## 다음 입력의 추천

필요 문서의 내용/민감 정보와 이용 범위, 내부 링크를 확인한 뒤 고정된 일반 파일 사본을 Windows 시험 공간에 둔다. 모델 없는 동일 코드 비교를 먼저 하고, 실제 Codex의 동일 질문/근거 정확성/누락/시간/토큰 비교로 이어간다. 이 86개를 전부 시험에 쓰거나 공개/배포하는 승인은 별개다. 세부 절차와 판정은 위 비교 계획이 소유하며 원본 파일 이동/수정이나 Git 조작은 하지 않는다.

쓰기/충돌/복구는 아직 없는 MCP 쓰기 기능과 기존 보호 계약을 구현/검증한 뒤 별도 사본에서 다룬다. 사본 사용 자체를 파일 보호나 완전한 OS 접근 격리로 대신하지 않는다. 현재는 대규모 수행률, 검색 우위나 토큰 절감 수치를 제시할 근거가 없다.
