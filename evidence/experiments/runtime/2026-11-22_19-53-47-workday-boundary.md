# 11월 21일과 22일 작업일 경계 정정

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 작업일 2026-11-22. 사용자가 이전 재개 요청의 처리까지를 11/21로, 그 이후를 11/22로 나누도록 사후 지정했다. 경계 원본 대조 기록에서 해당 사용자 요청, 후보 검사 완료 안내, 비교 승인 질문과 다음 사용자 답변을 확인했다. 시스템 자정으로 임의 분리하지 않았다.

## 확인한 경계

| 단계 | 실제 UTC 시각 | 정정한 사용자 작업일 |
| --- | --- | --- |
| 중단 콘솔을 붙인 재개 요청 | 11/22 05:32:33 | 11/21 |
| Windows 후보 검사 완료 및 비교 준비 안내 | 11/22 05:54:11 | 11/21 |
| 실제 비교 2회 승인 질문과 사용자 답변 전 처리 | 11/22 05:54:14 이후 | 11/21 |
| 사용자 “2회 비교 진행 (추천)” 답변 | 11/22 05:54:31 | 11/22 시작 |

따라서 묶음 후보의 구현/코드 검사와 질문 준비는 11/21에, 실제 AI 비교 승인/배치/측정과 후속 보완은 11/22에 배정한다. 정정 기준은 [작업일 경계](../../recording.md)가 소유한다.

## 기록에 적용한 방식

현재 README, 진행표, 설계/수용 기준, 검토, 문제/사례 기록과 active의 작업일을 맞췄다. 수정 목록 기록에 날짜만 바꾼 곳과 두 날짜로 나눈 곳을 구분한다. 기존 구현, 판단, 수치와 원문의 내용은 바꾸지 않았다.

| 닫힌 근거 | 현재 해석 |
| --- | --- |
| `2026-11-21_22-27-02-mcp-batch` | 11/21 후보 구현/Windows 코드 검사와 11/22 실제 AI 비교를 함께 포함 |
| `2026-11-22_18-26-09-mcp-inputs` | 입력 안내 구현/검사, 확장 조사와 로그 재집계는 11/22 |
| `2026-11-22_19-16-43-mcp-cursor` | 짧은 값/요청 보관 후보, 출력 안내 기준, 비교 준비는 11/22 |

위 근거의 당시 11/21 표기와 원시 시각, 폴더명, 파일/체크섬은 보존한다. 이 정정 기록으로 작업일 해석을 보완하고 과거 측정의 원본을 다시 쓰지 않는다. 비교 폴더명 `cursor-20261121`도 이미 준비한 식별 경로이므로 날짜 정정을 이유로 옮기지 않는다.

11/21 TIL은 최근 세 날짜와 중복을 대조한 뒤 [보관본](../../recording.md)에 저장했다. 11/22의 실제 측정 수치와 후속 후보를 포함하지 않았다. 기존 규칙에 따라 최근 3개를 유지하며 11/18 보관본만 정리하고 원시 근거와 이전 TIL 본문은 수정하지 않았다.

## 다음 실행

[관측 기록 (실제 비교 3회 계획)](../wiki-access/2026-11-22_19-16-43-mcp-cursor.md)은 사용자 승인 기록을 받았다. 이번 날짜 정정과 TIL을 먼저 마친 뒤 직접 접근, 긴 값 MCP, 짧은 값 MCP를 현재 설치본/선택 모델로 각각 한 요청씩 진행한다. 이전 질문을 다시 승인받지 않는다. 이번 기록 정리 중 모델 호출과 코드/SDK 검사 재실행은 없다.

직전 후보와 비교 사본은 그대로 두며, 새 대화의 시작 상태와 결과는 별도 실행 기록에 남긴다. 날짜 정정을 실제 비교 실행으로 세거나 기존 측정값을 새 후보의 성과로 옮기지 않는다.
