자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 지정 작업일: 2026-11-18. [최초 시작 시험](2026-11-18_14-23-43-terminal-start.md)과 [인증 관측](2026-11-18_14-38-50-terminal-auth.md)의 후속이다. 명시적 workspace-write를 선택한 같은 시험 세션에서 작은 WIKI 파일을 읽고 수정한 뒤 재개를 확인한다.

## 현재 결과

**이번 환경의 읽기, 상태 한 줄 수정과 같은 세션 재개 표본을 확인했다.** 사용자가 보낸 최종 답변의 표식/상태 두 줄이 실제 파일과 일치했다. 읽기 직후에는 파일이 초기 사본과 같았고, 수정 뒤에는 요청한 상태 한 줄 외의 바이트가 모두 보존됐다. 도구 호출 전체 로그는 제공받지 않았으므로 정확한 호출 횟수, 토큰과 다른 파일 접근 범위까지 검증했다고 하지 않는다.

| 항목 | 확인한 값 또는 범위 |
| --- | --- |
| 사용자 `/status` | Windows Codex 0.169.1, Local background server, GPT-5.6-Sol / reasoning low, openai |
| 프로젝트 | `<WORKSPACE_PATH>` |
| 권한 표시 | Workspace에 옆의 `wiki`가 포함되고 Ask for approval 유지 |
| 시험 세션 | `<SESSION_ID>`. 제품에 고정할 값이 아니라 이번 재개 대조용 |
| 읽기 | `.harness/local.json`의 상대 WIKI를 해석해 note.md를 읽는 요청. 예상 표식을 프롬프트에 넣지 않음 |
| 대조 | 읽기 시 read.json 기록, 수정 뒤 write.json 기록에 사용자 출력과 실제 파일 비교를 구분해 보관. 같은 표식과 다른 본문, CRLF 줄바꿈 보존 |
| 재개 | resume.json 기록에 같은 Session ID, 모델/프로젝트/WIKI 권한, 직전 변경 설명과 재읽기 응답을 기록. 실제 파일도 수정 직후 바이트와 일치 |

계정 주소, 계정 작업 공간 ID와 사용량 잔량은 이 기능의 검증에 필요하지 않아 복제하지 않았다. 사용자가 선택한 모델을 바꾸지 않았으며 이 한 표본을 모델 품질 비교로 사용하지 않는다.

## 변경 전 원본과 다음 시험

initial-note.md 기록은 최초 합성 시험 사본이다. 읽기 결과를 받은 뒤 실제 WIKI가 이 사본과 같은 것을 확인했다. 설계 세션의 WSL 파일 대조와 사용자의 Windows AI 관측은 서로 다른 근거로 구분한다.

같은 시험 세션에 `확인 상태: pending` 한 줄만 `확인 상태: ok`로 변경하고, 저장한 파일을 다시 읽도록 요청했다. 문서 표식과 다른 내용은 보존해야 한다. 현재 상태가 예상과 다르면 수정하지 않고 보고하도록 했다. 사용자는 같은 표식과 `확인 상태: ok`를 반환했다. 실제 파일도 최초 사본에서 이 한 줄을 바꾼 기대값과 정확히 일치했다. after-note.md 기록에 결과 바이트를 보존했다. 이때의 답변에는 추가 승인 여부가 없었다. 후속 재개 보고의 추가 요청 여부는 아래에서 별도 기록한다.

사용자는 같은 PowerShell에서 종료 뒤 `py -3 -B .\start.py resume --sandbox workspace-write`로 시험 대화를 선택하는 순서를 진행했다. 후속 /status의 Session ID가 같았고 모델, 프로젝트와 WIKI 권한도 유지됐다. 직전 pending→ok 변경을 설명한 답변과 재읽기 두 줄이 실제 파일에 일치했다. 실제 파일은 수정 뒤 사본과 바이트 단위로 같았다.

사용자 보고는 “resume 세션을 고르는 선택지 외 나한테 요청하는 건 없었어”다. 재개와 후속 확인에서 추가 요청이 없었던 관측으로 기록한다. 종료 코드와 Ctrl+C 신호 처리의 내부 동작, 모든 도구 호출을 직접 수집한 것은 아니며 작업 중 취소/강제 종료 성공으로 확대하지 않는다.

독립 시험이며 제품의 skill/hook, active/DB, compact 복구를 통과시킨 시험이 아니다. 최초 권한 선택의 저장/재사용, 다른 설정/설치 형식과 전체 옵션은 후속 검증 범위다. 다음은 같은 기능의 직접 파일 접근과 선택 MCP 읽기/검색을 비교하는 준비이며, 이 표본만으로 비용 우위나 MCP의 첫 배포 포함을 확정하지 않는다.
