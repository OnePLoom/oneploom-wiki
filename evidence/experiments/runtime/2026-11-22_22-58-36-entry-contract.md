> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 작업일: **2026-11-22**. 부모는 4단계 파일별 변경 명세다. 직접 접근 우선 채택 뒤 연결 설정, 준비 결과와 지원 설치 형태를 구체화했다. [이전 결정 기록](2026-11-22_21-26-32-direct-entry.md)은 닫힌 상태로 보존한다.

## 작성한 범위

[연결 설정 — 「연결 설정의 필드와 읽기 규칙」](../../../design/runtime/entry.md)에 공유/로컬 필드, 잘못된 설정 보존과 선택 재사용의 비교 근거를 연결했다. [반환 형식 — 「명령 결과의 형식」](../../../design/runtime/entry.md)은 등록, 준비와 실제 자식 실행을 구별하며 준비 단계의 종료 코드를 자식 종료 원인으로 해석하지 않는다. 최종 제품명/경로와 반복 선택의 호스트 조회/정규화는 남아 있다.

[설치 형태 — 「Codex 설치 형태와 실행 파일 선택」](../../../design/runtime/entry.md)는 npm 및 공식 Windows 설치본을 함께 지원하는 추천안과 npm부터 시작하는 대안을 비교한다. **사용자 선택 전**이며 새 지원 완료/구현 승인으로 표시하지 않는다. 우리 모듈의 Git 릴리스 + Python 제공은 유지한다.

## 조사와 제한

공식 근거 기록과 현재 npm 디스크 관측 기록을 대조했다. 0.171.0의 bin 선언과 JS 진입의 역할을 읽었고 프로그램을 실행하지 않았다. PowerShell 정책/전역 설정/Node/Codex를 변경하지 않았다. 공식 설치기와 코드/의존성을 배포물로 복제하지 않았으며 향후 라이선스 점검을 대체하지 않는다.

[후속 Windows 검증 입력 — 「진입 설정과 반환의 검증 입력」](../../../verification/acceptance.md)은 실제 사용자 설치, 옵션, 저장과 입출력/종료를 요구한다. 이번 문서/JSON 예시 검사는 그 실행 결과가 아니다. 제품 구현, 실제 Windows 실행, 모델 호출, 설치와 Git/원격 작업은 0회다.

설치 지원 범위를 선택하면 해당 실행 경로를 기준으로 이름/설치 위치와 권한 조회 조건을 구체화하고 기존 5단계 개발/Git 준비로 인계한다. 이전 MCP 시험은 반복하지 않는다.
