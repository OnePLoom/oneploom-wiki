# 두 프로젝트의 plugin 버전 유지 시험

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 작업일: 2026-11-09. Codex CLI 0.167.0, WSL2 Ubuntu의 Linux 임시 폴더에서 확인했다. [첫 설치 시험](2026-11-09_14-30-52-plugin-install.md)의 후속이며 제품 구현, 실사용 설치는 아니다.

## 질문과 입력

같은 Codex 상태를 공유하는 두 프로젝트에서 서로 다른 고정 plugin 버전을 선택했을 때, 한쪽의 설치, 갱신, 제거가 다른 쪽을 바꾸지 않는지 확인한다. 계획 기록, 실행기 기록, 입력 기록을 보존했다.

- 임시 프로젝트: `alpha`, `beta`. Git 저장소 초기화만 했고 원격, 커밋은 없다.
- 같은 식별자: `harness-probe@harness-trial`. 프로젝트별 신뢰된 `.codex/config.toml`이 서로 다른 로컬 catalog 출처를 선택한다.
- 배포 출처: 0.1.0, 0.2.0, 0.3.0 폴더를 따로 만들고 시험 중 내용은 바꾸지 않았다. 첫 시험에서 확인한 루트/호환 manifest를 함께 사용했다.
- 자식 명령에만 별도 `CODEX_HOME`을 적용했다. 개인 인증을 복사하거나 모델 세션을 시작하지 않았다. 개인 설정, 실제 프로젝트 파일과 시험의 보호 대상은 해시로 대조했다.

[공식 설정 참조](https://learn.chatgpt.com/docs/config-file/config-reference)의 프로젝트별 marketplace 출처, plugin 활성화를 사용한 시험이다. 출처 고정을 프로젝트별 실행 버전 유지와 같은 것으로 가정하지 않았다.

## 관측과 판정

| 단계 | 기대 | 실제 |
| --- | --- | --- |
| A 단독 0.1.0 설치 | A 0.1.0 | 일치 |
| B 0.2.0 설치 | A 0.1.0, B 0.2.0 | 양쪽 설치 목록 0.2.0, 캐시 0.2.0만 남음 |
| A 0.3.0 갱신 | A 0.3.0, B 0.2.0 | 양쪽 0.3.0, 캐시 0.3.0만 남음 |
| 새 CLI 프로세스에서 조회 | 각 프로젝트 버전 유지 | 양쪽 0.3.0 유지 |
| A에서 plugin 제거 | B 0.2.0 유지 | B 설치 목록, 캐시도 비어 있음 |

원시 결과 기록의 설치/조회 명령 14개는 모두 종료 코드 0이다. 관측 수집기는 정상 종료했지만 **요구 기준은 FAIL**이며 판정 기록에 구분했다. 새로운 CLI 조회를 모델 세션 재개 시험으로 표시하지 않는다.

## 실제 skill 발견 대조

목록 표시만 잘못된 것인지 확인하기 위해 설치된 CLI에서 생성한 프로토콜 스키마 명령 기록과 `discovery/`의 복사본을 사용했다. 발견 확인 실행기 기록가 A 0.3.0 → B 0.2.0을 다시 설치하고 격리 `codex app-server --stdio`에 `initialize`와 `skills/list`만 요청했다. 모델 thread/turn은 생성하지 않았다.

A → B → A 순서의 새로고침 조회 모두 0.2.0의 `SKILL.md` 경로와 `Fixture release: 0.2.0` 본문을 발견했다. A의 선택은 0.3.0이므로 설치 목록 외에도 잘못된 버전 선택을 확인했다. 결과 기록, 원시 통신 기록을 보존했다. 실제 skill 사용, hook 실행 결과는 아니다.

## 보존, 정리와 한계

출처 내용과 보호 대상 파일의 해시는 동일했다. 별도 app-server는 종료 코드 0으로 끝났고 정리 기록에서 시험 plugin/cache 제거와 보호 대상 보존을 확인했다. 원본 입력, 출력, 임시 fixture는 남겼다. helper 실행 파일 생성을 `/tmp`에서 거부하는 경고는 원시 stderr에 보존했으며, 설치/조회, skill 발견이 실제로 수행된 것과 구별한다.

이 결과의 범위는 **CLI 0.167.0, 같은 plugin ID, 공유 상태, 프로젝트별 고정 로컬 출처**다. 다른 CLI 버전, 상태/ID를 분리한 배치, remote Git 인증, 실제 모델, hook 실행은 미검증이다. B의 성공이나 토큰 효과를 입증한 시험도 아니다. 공통 코드 외부 보관, 프로젝트별 버전 유지 요구는 낮추지 않고 [설치 설계 — 「B안과 요구사항의 관계」](../../../design/runtime/install.md)에서 B의 추가 구현/검증 부담을 비교한다. 현재 추천이며 미채택이다.

모든 근거 파일의 체크섬은 `SHA256SUMS`에 보존한다. 사용자 문서나 과거 시험 결과를 이번 결과에 맞춰 고치지 않았다.
