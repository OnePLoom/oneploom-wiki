# Windows 터미널 시작 시험

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 지정 작업일: 2026-11-18. ADR 0022의 전용 시작 명령을 실제 Windows 터미널에서 확인하기 위한 합성 시험이다.

## 현재 결과

**자동 검사와 미리보기는 통과했지만 첫 실제 시작은 실패했다.** 사용자가 Windows PowerShell에서 실행했고, 외부 WIKI 쓰기 경로를 추가할 수 없다는 오류 뒤 PowerShell로 돌아왔다. 종료 코드는 전달받지 못했다. 사용자 관측 기록을 도구가 수집한 프로세스 출력과 구분한다.

| 단계 | 확인 결과 | 아직 확인하지 못한 것 |
| --- | --- | --- |
| 최초 준비 | Windows Python 3.13.9, 자동 검사 11개, 시작/재개 미리보기 2개 통과. 모델과 Codex 실제 실행 0회 | 실제 터미널, 권한, 인증과 같은 세션 재개 |
| 사용자 첫 시작 | Codex 패키지 0.169.1, `--add-dir` 권한 오류 뒤 종료 | 입력 화면과 WIKI 접근. 실패를 단순 경고나 성공으로 처리하지 않음 |
| 선택 권한 인자 보완 | `--sandbox workspace-write`를 사용자가 지정할 때만 전달. 영향받은 기존 검사 4개와 신규 검사 2개 통과, 나머지 7개 재사용 | 수정 조건의 실제 시작은 사용자 관측 대기 |

원래 소스와 출력은 source 기록, checks 기록에 보존한다. 보완은 재검사 소스 기록과 retry 결과 기록에 구분한다. 미리보기에는 명령 배열만 출력되며 실제 Codex나 모델을 실행하지 않는다.

## 시험 범위와 흐름

시험 위치는 `<WORKSPACE_PATH>`다. `project`는 원격과 커밋이 없는 새 로컬 Git 폴더이고, 옆의 `wiki`에는 합성 문서 하나가 있다. 연결 파일 `.harness/local.json`은 `../wiki`를 지정하며 해당 로컬 영역은 시험 `.gitignore`에서 제외한다. 시험 AI 입력은 위 합성 문서로 한정한다.

시작 파일은 `로컬 연결 읽기 → 현재 PATH의 Codex npm 패키지 확인 → 공식 Node 진입 파일에 프로젝트/WIKI 경로 전달` 순서다. `.cmd`를 실행하지 않고 명령 배열을 전달한다. 버전, 모델, UUID와 인증 위치를 고정하지 않으며 자동 요청문이나 시간 제한을 넣지 않는다. stdin/stdout/stderr와 환경은 실행한 Windows 터미널을 이어받는다.

이번 파일은 start/resume과 미리보기, 명시적 workspace-write 선택만 다루는 시험용이다. 모든 Codex 옵션, 여러 설치 형식과 다른 프로젝트의 일반 경로를 지원하는 제품 실행기가 아니다. 인접 합성 WIKI만 허용하는 범위 검사도 제품 전체의 경로 제한으로 채택하지 않는다. Ctrl+C 처리의 단위 검사는 모의 프로세스 결과이며 실제 콘솔 동작의 증명이 아니다.

## 첫 시작 실패와 재시도 조건

`--add-dir`는 WIKI 위치를 전달해도 현재 권한이 쓰기 루트를 허용하지 않으면 시작을 보장하지 못한다. 기본 Windows 사용자 config의 좁은 읽기 확인에서는 명시적 sandbox/default_permissions와 시험 프로젝트의 신뢰 기록을 찾지 못했다. 다른 설정 계층과 사용자 터미널의 CODEX_HOME까지 전부 확인한 결과는 아니다.

Codex 0.169.1의 [기본 권한 선택 코드](https://github.com/openai/codex/blob/rust-v0.169.1/codex-rs/core/src/config/permissions.rs)에는 프로젝트 신뢰 상태가 정해지지 않은 경우 읽기 전용을 선택하는 조건이 있다. [디렉터리 추가 검사](https://github.com/openai/codex/blob/rust-v0.169.1/codex-rs/tui/src/additional_dirs.rs)와 이번 오류는 일치하지만, 전체 유효 설정을 조회한 것은 아니므로 최초 기본값의 원인은 유력한 설명으로 남긴다. [공식 승인/보안 안내](https://learn.chatgpt.com/docs/agent-approvals-security)도 신뢰 전 읽기 전용 시작과 명시적 workspace-write 실행을 구분한다.

재시도 후보는 사용자가 **이번 실행에만** workspace-write를 명시하는 것이다. 기본 옵션을 몰래 바꾸지 않으며 전역 config, 신뢰 기록, 승인 정책을 시험 코드가 수정하지 않는다. Codex 자체가 이후 신뢰/로그인을 요청하는 동작은 사용자 관측으로 따로 확인한다. 이 옵션의 성공으로 사용자의 임의 권한 설정을 덮어도 된다고 판단하지 않는다. 제품에서는 최초 준비 때 현재 권한과 선택 범위를 확인하고, 허용된 연결을 재사용하는 기존 계약을 구체화해야 한다.

## Windows에서 확인할 순서

현재 설계 세션은 그대로 둔다. 새 Windows PowerShell에서 시험 프로젝트로 이동한다. WSL 터미널이 아니다.

```powershell
cd <WORKSPACE_PATH>
py -3 -B .\start.py start --sandbox workspace-write
```

1. 위 쓰기 조건을 사용자가 선택한 경우에 실행한다. Codex 입력 화면과 시험 project 경로가 보이는지 확인하고 아직 AI 요청은 보내지 않는다. 오류나 로그인/신뢰 확인에서 멈추면 그 상태부터 전달한다.
2. 시작이 확인되면 짧은 요청으로 연결된 `wiki/note.md`의 표식을 읽는다. 그다음 상태 한 줄만 변경하고 실제 파일을 대조한다. 요청별 관측과 권한을 구분한다.
3. 시험 세션을 정상 종료한 뒤 `py -3 -B .\start.py resume --sandbox workspace-write`로 **그 시험 세션**을 선택한다. 같은 세션 ID, 이전 대화와 WIKI 변경 보존을 확인한다. 다른 최근 세션이나 현재 설계 세션을 자동 선택하지 않는다.

2~3은 아직 실행하지 않았다. 모델 요청을 자동 전송하거나 현재 설계 세션의 복구 성공으로 대체하지 않는다. 이후 실제 단축키, `/model`, 같은 세션 재개와 경로 변경을 확인한 뒤 MCP의 작은 비교와 원래 4단계 명세로 돌아간다. 완성된 모듈의 skill/hook, active/DB 또는 compact 복구를 이번 시험에서 검증한 것은 아니다.
