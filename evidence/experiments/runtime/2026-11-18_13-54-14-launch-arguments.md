# Windows 실행 경로와 인자 전달

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

- 사용자 작업일: 2026-11-18. 이 폴더의 시각은 최초 결과를 수집한 UTC 시각이며 추가 비교는 그 뒤 수행했다.
- 목적: 채택한 전용 시작 명령에서 사용자 인자와 현재 Codex 설치본을 보존할 호출 조건 확인.
- 환경: Windows Python 3.13.9, Node 22.12.0 계열 설치 위치, Codex 0.169.1 npm 설치본. 실제 경로/패키지 버전은 metadata 기록에 보존했다. Node 버전 명령은 이번에 별도 실행하지 않았다.
- 범위: 합성 인자 전달 32회, 설치된 Codex의 도움말/버전 6회, 알 수 없는 옵션의 오류 관측 2회. 모델 호출은 0회다.
- 입력: 독립 합성 프로젝트/WIKI, 자식 프로세스 전용 CODEX_HOME과 시험 환경변수. 제품에서는 실제 사용자 환경을 유지해야 하며 이 격리를 제품 동작으로 복사하지 않는다.

## 확인한 결과

| 경로 | 합성 인자의 원문 보존 | 해석 |
| --- | --- | --- |
| Python 실행 파일 직접 호출 | 8개 중 8개 | 비교 도구의 args/cwd 관측. Codex 기능 시험은 아님 |
| Node 실행 파일 직접 호출 | 8개 중 8개 | 셸 없이 실행 파일로 전달한 표본의 보존 |
| .cmd 호출, shell=False | 8개 중 7개 | `%HARNESS_PROBE_VALUE%`가 시험 변수 값으로 바뀜 |
| .cmd 호출, shell=True | 8개 중 7개 | 같은 변수 확장. 이 설정만으로 원문 보존이 해결되지 않음 |

한글/공백 경로, 빈 인자, 따옴표와 JSON 문자열, 끝 역슬래시, `&`, 파이프, `%...%`, `!...!`를 시험했다. 이 유한 표본을 모든 문자열/설치 형식의 안전성으로 확대하지 않는다. 전체 관측 기록과 각 stdout/stderr를 보존했다.

설치된 `codex.cmd`와 같은 설치본의 `package.json`에서 찾은 공식 JavaScript 진입을 Node로 실행했을 때 버전은 모두 0.169.1이었다. 시작 도움말, Node 경로의 재개/명시적 세션 ID 도움말도 종료 코드 0이다. 더미 UUID와 `--help`는 실제 세션을 재개하지 않았다.

합성 .cmd만의 문제인지 확인하기 위해 실제 Codex에 `--%HARNESS_PROBE_VALUE%`라는 존재하지 않는 옵션을 전달했다. 두 경로 모두 옵션 오류로 종료 코드 2를 반환했지만, `.cmd`의 오류에는 변환된 값, Node 직접 호출의 오류에는 원래 문자열이 남았다. 추가 관측 기록은 실제 전달 차이의 근거이며 의도한 음성 시험이다. 모델이나 실제 사용자 요청을 실행한 오류가 아니다.

## 설계에 반영할 것

제품 실행기는 모든 설치본을 `codex.cmd` 한 경로로 고정해 호출하지 않는다. 현재 npm 설치본에서는 공식 진입 파일을 Node로 직접 호출하는 안을 우선 검증한다. 이는 같은 설치본을 쓰는 실행 후보이며 우리 바이너리를 따로 설치하거나 Codex 버전을 고정하는 안이 아니다.

정확한 설치 형식/진입 파일과 사용자의 실행 환경을 확인하고 인자를 배열로 전달한다. 확인할 수 없는 중계 파일을 임의 해석하거나 문자열 명령으로 이어붙이지 않는다. npm 구조의 현 관측을 모든 설치 관리자/미래 버전의 고정 규칙으로 만들지 않는다. 제품의 발견/선택 코드, 터미널 입력/출력과 Ctrl+C, 실제 인증/모델 옵션/세션 재개는 아직이다.

[Python 공식 subprocess 주의사항](https://docs.python.org/3.13/library/subprocess.html#security-considerations)은 Windows batch가 OS 셸에서 처리될 수 있음을 설명한다. 이번에는 외부 코드를 복제하지 않고 설치된 Codex의 진입/메타데이터와 자체 합성 코드를 확인했다. 기록된 Codex 패키지 라이선스는 Apache-2.0이며 재배포 허가/의무 전체 감사로 확대하지 않는다.

## 재현과 한계

probe.py 기록은 최초 [실행 소스](../../methods.md)의 보존본이다. 새 Windows 출력 폴더를 인자로 받아 기존 자료를 덮지 않는다. option.py 기록은 첫 출력 폴더를 받아 추가 결과 폴더가 없을 때 두 오류 관측만 실행한다. 후속 비교 때문에 처음 38개 호출을 다시 실행하지 않았다.

첫 실행의 실제 준비 호출은 Windows `py -3 -B`로 수행했다. WSL 안의 최초 PowerShell 경로 조회는 샌드박스 interop 제한으로 실패했고, 승인된 읽기 호출로 현재 Windows 경로를 확인했다. `.cmd` 변수 확장과 이 실행 환경 제한은 다른 문제다. 정상 사용을 끊는 시험 timeout은 두지 않았다.

실제 TUI, AI의 WIKI 읽기/쓰기, 사용자 환경의 인증과 같은 세션 재개, Ctrl+C/비정상 종료, MCP, 토큰 절감은 검증하지 않았다. 한 번의 호출 시간은 성능 비교가 아니다. 제품/예비 도구, 실제 config와 Git/index를 수정하지 않았으며 이 시험 결과로 제품 실행기를 구현 완료 처리하지 않는다.

check.py 기록은 저장된 관측의 일치와 의도한 반례를 대조한다. check.json 기록의 PASS는 이 근거 검사에 한정한다. 원문 변환 후보는 부적합 관측으로 남는다. 실제 사용자 보호의 완료 조건은 [진입 수용 기준 — 「전용 시작 명령의 검증 입력」](../../../verification/acceptance.md)을 따른다.
