# 외부 고정 배포본과 프로젝트 갱신 시험

자료명은 관측에 사용한 근거를 식별한다. 개별 파일의 제공 범위는 [기록 기준](../../recording.md)을 따른다.

> 검토와 관측 기록. 검토 당시의 후보와 관측을 보존한다. 현재 채택 범위는 결정 목록에서 확인하며, 미실행 계획이나 예비 시험을 제품 검증 완료로 해석하지 않는다.

사용자 작업일 2026-11-10. 승인된 설치 B의 작은 시험 1~3을 Python 3.10.12, Git 2.34.1, WSL Linux 임시 디렉터리에서 수행했다. 한 번의 suite 실행에서 14개 검사가 기대 결과를 통과했다. 제품 설치기나 Codex 연결 구현의 완료 결과는 아니다.

## 입력과 실행

시험 Git 저장소에 공통 처리 코드, 템플릿을 commit하고, 전체 commit ID별 외부 디렉터리에 clone, checkout했다. 두 프로젝트는 이름, 검사 파일, WIKI 위치가 다르며 하나는 내부 문서, 다른 하나는 별도 Linux 폴더를 사용했다. 적용 기록이 고른 Python 코드를 자식 프로세스로 실행하고 해당 프로젝트의 작은 검사 프로그램을 호출했다. 실제 앱 테스트나 AI 호출은 아니다.

프로젝트에는 연결 파일과 입력, `.harness/`에는 공식 생성 기준본, 설치 기록, 반영 기록을 두었다. 호스트 연결은 시험 인자로 전달했다. 파일명, JSON 필드, commit은 제품의 확정 인터페이스, 출시 버전이 아니며, 일반 설치 도구의 패키징, 인증 대신 버전 선택과 보존 책임만 좁혀 구현했다.

## 결과

| 상황 | 관측 |
| --- | --- |
| 한 프로젝트 갱신 | 다른 프로젝트의 파일, 공통 배포본이 그대로였고 이전 코드를 계속 호출 |
| 재설치, 두 번 연속 갱신 | 중복 변경 없이 사용자 명령 옵션 유지. 공식 기준본에는 사용자 옵션을 섞지 않음 |
| 배포본 부재/변조, 기준본 누락/변조, 계획 후 변경 | 원문, 적용 버전을 바꾸지 않고 차단. 다른 배포본으로 대체하지 않음 |
| 같은 부분 수정 충돌 | 실제 `git merge-file`이 충돌을 반환했고 적용하지 않음 |
| 텍스트 병합 성공, 의미 불일치 | 기존 2회 × 10초/허용 60초에서 사용자 20초 변경과 공식 4회 변경은 각각 유효했지만, 병합 후 4회 × 20초가 60초를 초과. Git 종료 0 뒤 별도 검사로 적용 차단 |
| 첫, 두 번째 파일 반영 후 프로세스 종료 | 미완료 기록으로 실행을 보류하고 새 프로세스가 디스크의 이전/예정 내용을 대조해 복원 |
| 실패 후 사용자 추가 편집 | 편집을 유지하고 복구 판단이 필요한 상태로 남음. 자동 덮어쓰기나 정상 완료 처리 없음 |
| 연결 제거 | 수정 없는 소유 파일만 제거. 수정 파일, 다른 프로젝트, 공통 배포본, 기존 WIKI/지침 보존 |

충돌, 강제 종료, 복구 보류의 비정상 종료 코드는 의도한 입력의 관측이며 suite 실패가 아니다. 요약 기록, unittest 출력 기록, 전체 명령, 출력, 종료 코드 기록, 사례별 `attempt-1/observations/`를 함께 보관한다.

## 재현과 한계

- 사전 계획 기록: 실행 전 조건, 14개 사례, 환경, 소스 해시.
- 처리 코드 기록과 시험 코드 기록: 첫 실행 당시 소스.
- Git bundle 기록과 commit 목록 기록: 실제 사용한 입력 이력.

아직 존재하지 않는 결과 경로를 골라 실행한다. 새 실행의 commit ID, 시각은 달라질 수 있으며 원시 입력의 정확한 commit은 bundle에 보존했다.

```bash
python3 -B source/test_probe.py /tmp/harness-install-recheck
```

작은 JSON 계약과 보호 파일 byte 대조를 확인한 시험이다. 모든 문서의 의미나 실제 skill/hook의 발견, 신뢰, 호출을 검증한 것은 아니다. Windows 문서 반영, 동시 외부 편집, 전원 장애 내구성, 일반 downgrade, 악의적/손상된 journal, 원격 배포/인증은 미검증이다. 프로세스 종료 복원을 모든 장애의 무손실 보장으로 확대하지 않는다.

실험 코드를 제품에 그대로 복사하지 않는다. 다음 범위는 [최소 검증 — 「B안의 최소 검증」](../../../design/runtime/install.md) 4번의 실제 Codex 연결이다.
