## 확인한 근거

[11/18 조회 기록](../wiki-access/2026-11-18_17-52-34-host-query.md)의 스키마와 저장 응답을 다시 읽었다. `host-review.json`은 사용한 파일의 해시, 실제 필드와 읽기 범위를 남긴다. 당시 Codex 0.170.0의 관측이며 이번에 디스크에서 읽은 npm 메타데이터의 0.171.0을 실행한 결과가 아니다.

기존 config/read 응답에서 read-only 옵션을 준 뒤에도 default_permissions와 프로필 정의가 함께 있었다. 따라서 필드의 존재나 선택 목록만 보고 최종 실행 권한을 결정하면 안 된다. Config 스키마의 추가 필드에도 권한 정의가 있었고, 권한 목록은 id/description/allowed를 반환했다. 당시 조회는 layers를 포함하지 않았으며 관리 제한 응답은 null이었다. 관리 정책 전체나 실제 TUI와의 일치를 확인한 근거로 확대하지 않는다.

[공식 설정 문서](https://learn.chatgpt.com/docs/config-file/config-basic)는 명시 옵션과 설정 계층, 프로젝트 신뢰의 적용 관계를 설명한다. [권한 문서](https://learn.chatgpt.com/docs/permissions)는 프로필과 기존 sandbox 체계의 차이를, [App Server 문서](https://learn.chatgpt.com/docs/app-server)는 설정/관리 조건/프로필 목록의 조회 역할을 설명한다. 출처와 사용 범위, 조회 실패로 사용하지 않은 소스 주소는 `sources.json`에 구분했다. 외부 프로그램이나 생성 스키마를 새 배포물에 편입하지 않았다.

## 반영한 명세

[진입 설계의 판단 순서 — 「권한 선택 재사용의 판단 순서」](../../../design/runtime/entry.md)는 저장 옵션을 적용하기 전의 조건을 비교한다. 과거 쓰기 옵션을 먼저 적용해 사용자의 새 읽기 전용 선택을 가리는 문제를 피하려는 조건이다. 명시 입력을 보존한 기본 상속, 저장 선택 재사용과 미확인/거부를 구별한다.

[비교 형식 — 「재사용 조건의 비교 형식」](../../../design/runtime/entry.md)은 대상, 반복 옵션, 관련 설정/정책과 출처만 정규화하고 기존 launch.context에 해시를 저장하는 후보를 구체화했다. 모델/화면, WIKI 본문과 일반 Git 커밋 변화는 제외한다. 누락/null/false를 합치거나 권한 관련 추가 필드를 버리지 않는다. 비교 해시는 허가나 실제 접근 성공의 증거가 아니다.

추가할 검사 입력은 [수용 기준 — 「권한 선택 재사용의 검증 입력」](../../../verification/acceptance.md)이 소유한다. [설치 — 「지원 조건의 확인 순서」](../../../design/runtime/install.md), [개발 인계 — 「직접 접근 실행기의 개발 준비」](../../../development/migration.md)와 [다음 순서](../../../development/roadmap.md)를 함께 연결했다. 두 설치 지원, 직접 접근 우선과 전역 설정 비변경 결정을 바꾸거나 새 ADR을 추가한 작업은 아니다.

## 검증과 남은 조건

`review.json`은 본문 의미 대조를, `document-check.json`은 변경 문서의 링크/형식과 백업 범위 밖 자료, 제품/Git 보존의 대조 결과를 기록한다. 검사 입력과 코드는 `document-baseline.json`, `check_documents.py`다. 기존 JSON 예시는 변경 없이 직전 정적 PASS를 재사용한다. 모델 호출이나 이미 끝난 호스트 시험을 반복하지 않았다.

실제 조회/실행 옵션의 대응, 관리 정책과 실행 프로필, 업데이트 호환, 취소/종료, 지연과 부작용은 제품 Windows 시험에서 확인해야 한다. 현재 metadata나 과거 저장 응답을 읽은 것으로 이러한 조건을 통과 처리하지 않는다. 저장 선택을 적용하지 않는 정상 인계와 자동 재사용을 서로 다른 완료 조건으로 남긴다.

다음은 고유 제품/명령 이름과 프로젝트 안 설치 위치의 구체화다. 이후 기존 5단계 개발 준비로 인계하며 현재 기록이 제품 구현이나 저장소 생성 승인은 아니다.
