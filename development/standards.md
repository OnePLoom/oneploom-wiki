# 개발 기준

## 판단과 근거

제안을 자동으로 긍정하지 않고 요구, 대안, 실패 비용과 반례를 대조한다. 공식 문서, 1차 자료와 확인한 공개 구현을 우선하고 추정과 실제 관측을 구분한다. 자료의 기능 존재가 우리 환경의 성공을 증명하지는 않는다. 핵심 미확인은 해당 구현/완료 판단 전에 시험한다.

## 구조와 이름

처음 읽는 사람이 의도와 변경 위치를 파악할 수 있게 작성한다. 짧은 일회성 처리를 이유 없이 함수/래퍼/필드로 나누지 않는다. 책임 경계나 복잡한 조건이 더 분명해지는 분리는 사용한다. 역할이 읽히는 이름과 업계에서 통용되는 용어를 우선한다.

수정 차수만 나타내는 v1_field, v2_schema 같은 이름을 늘리지 않는다. 버전은 실제 릴리스/태그와 호환 계약에서 관리한다. 기존 표준 이름, ADR 번호와 실험의 실제 버전은 보존한다. SOLID는 교체할 책임과 의존성을 검토하는 기준이며 미래 기능의 불필요한 추상화를 강제하지 않는다.

## 변경과 검증

문제가 생기면 입력, 호출, 저장, 소비와 복구를 함께 살핀다. 해당 위치에 예외를 계속 붙이는 대신 관련 소유 경계를 확인해 유지보수 비용과 부작용이 작은 안을 선택한다. 요구와 필수 보호 검사를 단순화 명목으로 제거하지 않는다.

테스트는 정상, 경계, 제한, 오류, 취소/중단, 재시도와 기존 변경 보존을 다룬다. 테스트 개수나 커버리지의 근거 없는 보편 합격선을 만들지 않는다. 실패한 원래 검사와 영향받은 선행 PASS를 다시 확인하고 무관한 PASS는 근거가 유효할 때 재사용한다. 제품의 실제 지원 환경/명령/권한/사용자 상호작용을 맞춘 검증과 단위/모의 검사를 구분한다.

## 사용자 경험과 비용

사용자가 반드시 알아야 하거나 선택할 내용만 요구한다. 내부 기록/중간 파일/연결 절차를 수동으로 관리하게 만들지 않는다. 유효한 동일 승인과 경로는 재사용하되 실제 호스트 정책, 만료와 권한 변경을 무시하지 않는다.

토큰 최소량만으로 선택하지 않는다. 같은 품질에서 의미 있는 토큰/시간 차이와 반복 비용, 유효성, 호환성과 사용 편의를 함께 비교한다. 측정하지 않은 절감이나 속도를 성과로 표시하지 않는다. 기능 범위를 키우기 전에 필수 제공 목표와 검증 비용을 대조한다.

## 문서와 배포

한국어로 작성하고 전문용어가 필요하면 의미를 설명한다. 관계를 모호하게 만드는 가운뎃점 나열을 피하고 문장, 목록과 표로 표현한다. 오류/예외도 특별한 이유가 없으면 한국어로 안내한다. 주석은 필요한 이유와 경계를 설명할 때만 추가한다.

라이선스와 저작권은 외부 자료를 편입하기 전에 확인한다. 참고와 복제/수정/재배포, CLI 호출과 프로그램 동봉을 구분한다. 공개 저장소라는 이유만으로 재배포 권한을 추정하지 않는다. 실제 자격증명과 개인키는 문서, 예시, 로그와 Git에 남기지 않는다.

개발 준비와 부분 시험을 제품 완성으로 표시하지 않는다. 필수 기능, 설치/갱신/복구와 실제 안내를 검증한 뒤 릴리스하며 Git 운영의 상세는 코드 저장소 CONTRIBUTING이 소유한다.
