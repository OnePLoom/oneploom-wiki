# 개발 순서와 완료 상태

## 현재 위치

현재 진행 중인 단위는 [프로젝트별 WIKI 연결과 Codex 시작](https://github.com/OnePLoom/oneploom/issues/8)이다. 첫 변경 묶음에서 등록된 WIKI와 위치표의 읽기 전용 확인을 구현하고 Windows 전체 검사 96개를 통과했다. 연결 저장과 실제 Codex 실행은 후속이며, [첫 단계의 관측과 한계](../evidence/experiments/runtime/2026-11-28_16-53-13-wiki-connect.md)를 구분한다.

후속 묶음에서는 연결 저장에 필요한 기존 SQLite DB의 열기와 짧은 트랜잭션을 구현했다. 새 23개를 포함한 Windows 전체 119개가 통과했으며 [기록 보호의 확인 범위](../evidence/experiments/recovery/2026-11-28_17-57-33-state-connection.md)를 남겼다. 최초 DB 생성, 변경 계획/승인과 실제 설정 파일 반영은 아직 연결 전이다.

다음 준비 묶음은 기존 파일의 Windows 보호 읽기다. 새 21개를 포함한 전체 140개가 통과했으며 [배타적 접근과 새 하드 링크의 한계](../evidence/experiments/recovery/2026-11-28_20-15-24-file-protection.md)를 확인했다. 이 함수는 읽기 전용이며, 실제 쓰기 전에 파일 반영 방식의 경합 조건을 재검토한다. DB 생성/계획/확인 기록과 Codex 실행의 미완료 범위는 그대로 남는다.

독립 코드/WIKI의 준비와 MIT 적용 뒤 첫 발견 기능을 구현하고, 2026-11-27 양쪽 PR의 main 반영과 작업 마감까지 확인한 단계다. 명령, 대상 선택과 설정 읽기의 Windows 자동 검사 59개는 구현 당시의 통과 결과이며, 병합된 코드와 검사 입력의 동일성을 확인해 재사용했다. 실제 WIKI/권한 연결, Codex 실행, 설치 패키지와 릴리스는 아직이다. [첫 구현 기록의 「병합과 작업 마감」](../evidence/experiments/runtime/2026-11-25_16-13-58-project-discovery.md)에서 실제 PR과 최종 커밋을 확인한다. 첫 기능의 main 반영과 제품 전체의 배포 완료를 구분한다.

## 순서

| 단계 | 작업과 완료 조건 | 현재 상태 |
| --- | --- | --- |
| 설계 | 필수 범위, 조건부 탐색/검증, 상태/복구, 설치와 보존의 책임/계약 | 채택 원칙과 상세 명세 있음. 미확정 인터페이스는 해당 문서에 표시 |
| 개발 준비 | 두 저장소, 문서 범위와 Git 규칙, 첫 준비 커밋 | 초기 준비 커밋, MIT 적용과 원격 main 공유 완료 |
| 첫 실행 | 입력/도움말, 프로젝트 발견, 설치본 식별, WIKI 연결과 현재 Codex로 시작 | 발견/읽기 전용 확인의 main 반영 완료. 기존 Windows 자동 검사 59개 결과를 재사용. 실행 인계와 WIKI/호스트 연결은 후속 |
| 설치/관리 | 공식 자료, 계정별 명령 준비, 프로젝트 설치, 중단 후 인계와 정리 | 미구현 |
| 조건부 작업 | 필요한 지침/검사 선택, 원래 실패 재시도, 세션 문맥과 실행 재개 | 명세와 예비 검사는 있으나 제품 미구현 |
| 지식 복원 | 코드/이력 분석, 상세 후보, 근거/관계, 재실행과 사용자 변경 보존 | 미구현 |
| 원격 연계 | 코드/WIKI PR 생성/재사용/연결/상태, 부분 실패와 CI | 제품 자동화 미구현 |
| 이식/배포 | 실제 Windows 설치/사용, 기본/선택 기능, 갱신/복구, README와 라이선스 | 미검증 |

최소 실행 경계가 생기면 이름과 구조가 다른 사례에 조기 적용한다. 전체 구현이 끝날 때까지 이식 시험을 미루지 않는다. 문서가 풍부한 사례의 연결과 빈 문서의 역공학을 별도로 검증한다.

## 다음 구현 단위

제품 연결 확장의 선행 작업인 [개발 검증 CI](ci.md#main-병합과-검사)는 2026-11-28 양쪽 main 반영과 병합 후 검사까지 완료했다. 코드 69개, WIKI 27개와 전체 내부 링크 검사가 통과했고, 양쪽 main의 필수 검사도 유지되고 있다. 기존 실패와 수정 근거는 CI 기록에 보존한다. 개발 CI의 완료를 제품의 조건부 검증/원격 연계 기능 완료로 계산하지 않는다.

발견 단위의 main 반영은 완료했고, 다음 제품 구현에서는 WIKI 연결 조건과 실제 호스트 실행을 연결한다. 기존 발견 결과는 준비 입력이며 실행 허가가 아니다. 설정 전체의 소비, 설치 소유/호환과 실제 실행 직전 대상 확인을 생략하지 않는다. 기기 파일/PATH를 변경하는 기능은 기록/복구 없이 먼저 제공하지 않는다. 상세 입력은 [실행 설계](../design/runtime/entry.md), [개발 대응](migration.md), [수용 기준](../verification/acceptance.md)을 따른다. 현재 결과와 남은 관문은 [첫 구현 기록](../evidence/experiments/runtime/2026-11-25_16-13-58-project-discovery.md)을 참조한다.

## 후속 범위

MCP, 로컬 AI, 다른 플랫폼/호스트, WSL/Linux 제품 지원과 커밋 보조는 후속 검토다. 필요한 상세 WIKI 복원과 첫 선택 문서 확장, 최소 PR 연계는 첫 제공의 필수 범위에서 임의로 빼지 않는다. 토큰/시간/품질은 실제 같은 조건에서 비교하고 추가 기능 때문에 필수 검증을 줄이지 않는다.
