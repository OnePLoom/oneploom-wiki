# ADR 0006: 로컬 AI의 첫 적용 범위

- 작성: 2026-10-27
- 설계 상태: `proposed` — 연결 흐름의 검증 방향은 2026-11-11 수용했지만, 로컬 AI의 실제 도입은 품질/전체 비용 비교 뒤 결정한다. 첫 배포의 필수 기능이 아니다.
- 구현 및 검증: 구현과 측정 모두 미완료
- 범위: 학습에서 도출한 첫 비교 실험 방향. 설치, 구조 변경, 실험 실행을 승인한 결정이 아니다.

첫 배포 범위는 [ADR 0007](../architecture/0007-release-scope.md)을 따른다. 이 ADR의 B는 선택 실험이며 기본 검증, 복구와 이식의 필수 의존성으로 두지 않는다.

## 후속 요구 명확화

10/30 시스템 날짜의 질문은 로컬 도입 확정이 아니다. 사용자는 도입한다면 기본 클라우드 메인 직접 처리와 로컬 보조 사용을 간단히 선택하고, 기존 WIKI, 검증, 복구를 유지해야 한다고 다시 강조했다. 이를 중요한 실행 요구로 유지하며 '선택 기능'을 우선순위가 낮거나 삭제해도 된다는 뜻으로 쓰지 않는다.

ADR 0014 최초 표의 '협업'은 native Codex 서브에이전트만 뜻했다. [후속 경계 비교 — 「후속 협의: 문서 확장과 작업 위임」](../knowledge/0014-features.md)와 [분업 구분 — 「서브에이전트와 로컬 보조」](../../design/integration/local-ai.md)으로 연결하고, 문서 확장 설치와 보조 사용 모드를 분리한다. 로컬 장비, 품질, 효과, 첫 배포 포함 여부는 계속 미확정이다. 기존 비교 실험 전제를 사용자 답변 없이 바꾸거나 로컬 구현부터 시작하지 않는다.

11/08 후속: 사용자는 상세 WIKI 복원의 품질 차이가 작을 때 로컬로 클라우드 사용량을 줄이고, 의미 있는 품질 차이가 있으면 품질을 우선한다고 재확인했다. WIKI의 상용 단독/로컬 단독/혼합 비교와 판정은 [품질 비교 — 「품질 비교 방법」](../../discussions/knowledge/reconstruction.md)가 소유한다. 기존 로그 정리 후보를 WIKI 비교의 선행 조건으로 강제하지 않으며 둘을 한 실험의 효과로 합산하지 않는다. 작성자 장비가 아닌 검증한 사용자 환경, 작업 조합으로 판단한다. 품질 우선은 사용자 조건이고 로컬 도입, 실험 실행은 계속 미채택이다.

11/11 후속: 테스트 실행 비용 질문에 이어 [검증 비용의 로컬 보조 — 「검증 비용을 줄이는 로컬 보조」](../../design/integration/local-ai.md)에서 Microsoft, Meta와 Continue, Goose, Aider의 공개 근거를 비교했다. 코드 전처리 후 긴 실패 기록의 해석 후보만 로컬에 맡기는 B 비교를 유지하며, 필수 검사, 완료/재사용 판정과 원문은 공통 경로에 남긴다. 여러 모델 사용 자체를 절감으로 계산하지 않고 메인 재조회, 재작업과 사용자별 자원 비용을 포함한다.

이어진 질문에는 가상 실패 예시, 역할 이유와 [WIKI 교차 검토 — 「로컬 AI 교차 검토」](../../design/integration/local-ai.md)를 보강해 비용 절감과 오류 발견을 별도 평가하도록 했다. 사용자는 도입 시 [Ollama — 「Ollama 연결 후보」](../../design/integration/local-ai.md)를 고려하며 실행기와 실제 모델, 품질 채택을 구별한다. 도입, 실험 실행, 첫 배포 포함을 채택한 것은 아니며 부모의 검증 기록/재사용 계약 협의를 이어간다.

11/11 입력 전달 보충: 사용자는 로컬을 도입한다면 필요한 추가 자료를 요청하고 답을 받아 작업을 이어갈 수 있어야 한다고 확인했다. [코드와 WIKI 접근](../../design/integration/local-ai.md)에 메인이 넘길 대상/질문, 일반 프로그램의 파일 읽기/API 전달, 추가 요청과 미완료 처리를 통합했다. 이어 사용자는 이 흐름으로 진행하되 실제 구현 가능성과 문제 여부를 확인해 판단하는 방향을 수용했다. 연결 방향은 다시 선택받지 않으며 [실행, 효과 검증 — 「효과를 확인할 조건」](../../design/integration/local-ai.md) 뒤 보완, 도입 여부를 판단한다. 자유 파일 탐색 도구, 최종 로컬 도입, 첫 배포 포함, 구체 모델/입력/예산, 실험 실행까지 승인된 것은 아니다.

## 배경

사용자는 로컬 AI를 학습한 뒤 현재 조건부 하네스에 적합한 사용 방법을 판단하려 한다. 목표는 품질, 검증, 복구를 유지하며 전체 클라우드 사용량을 줄이는 것이다. 이식성과 코드, 이력 기반 문서 복원은 로컬 도입 여부와 독립된 필수 목표다.

GPU, VRAM, RAM, 실제 작업별 사용량, 로컬 모델 품질은 아직 확인되지 않았다. 기존 감사의 검증 상태, retry 문제는 로컬 모델로 해결할 수 있는 문제가 아니며 별도 계약 설계가 필요하다.

## 대안

| 안 | 쉬운 설명 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 코드로 정리 | 파서, 검색, 필터가 자료를 추리고 Codex가 해석 | 단순하고 검사하기 쉬움. 모델 운영 불필요 | 표현이 다른 오류, 문서의 의미 정리는 메인 부담 |
| B. 선택적 로컬 보조 | A로 처리한 뒤 필요한 자료의 의미 정리만 로컬에 요청 | 메인 책임을 유지하며 일부 입력 처리를 옮겨 비교 가능 | 누락, 왜곡, 추가 검토, 장비 운영 비용 |
| C. 로컬 메인 | 로컬이 초기 판단, 작업을 맡고 필요 시 클라우드 호출 | 로컬에서 완료하는 작업의 외부 호출 감소 가능 | 잘못된 성공 판단과 호출 분기, 전체 규칙, 검증, 복구 품질 평가 필요 |

## 추천과 이유

**첫 비교 실험은 B를 추천하되, A를 비교 기준으로 두고 실제 도입은 보류한다.** 현행 흐름도 별도 기준선으로 보존한다. 코드 개선으로 생긴 절감을 로컬 AI의 효과로 계산하지 않는다.

첫 작업 후보는 실패 로그의 근거, 해석 후보 정리다. 입력을 고정하고 원문과 대조할 수 있으며, 보조 없이도 기존 경로로 복귀할 수 있기 때문이다. 실제 로그 처리 비중이 작거나 A가 충분하면 B를 채택하지 않는다. 이후 문서 근거 추출을 이식 설계와 함께 검토한다.

작업 후보 5개의 설명, 장단점, 현재 흐름과의 비교는 [학습 문서 10~11절](../../explanations/local-ai.md)에 둔다. 이 ADR 때문에 기존 [역할 분해 초안](../../design/integration/local-ai.md)의 모든 역할을 구현하거나 후보별 agent를 만들지 않는다.

## 책임과 실패 처리

- 코드는 실행 사실, 실패 검사 식별자, 원문을 보존한다. 로컬 모델은 근거 위치와 해석 후보를 반환한다.
- 초기 보조에는 파일 변경, 임의 명령 실행, gate 변경, PASS 선언을 맡기지 않는다. 메인이 필요한 원문과 의미를 검토한다.
- 시간 초과, 메모리 부족, 잘못된 형식, 불충분한 근거는 원문 확인 경로로 돌아간다. 로컬 실패 때문에 원래 검증 실패를 잃지 않는다.
- 협업 선택은 공통 검증, 복구 흐름 안의 분기로 검토한다. 메인 provider 전체 전환과 별개이며 모드별 파이프라인 복제를 피한다.
- 프로젝트 전용 경로, 모듈, 검사는 명시된 입력으로 전달한다. boot 접근 제한 예외는 현재 프로젝트에만 적용한다.

## 채택 전에 확인할 것

1. 장비 조건과 실제 작업 비용을 확인하고 검증, 복구 계약을 먼저 협의한다.
2. 현행 / 코드만 정리 / 코드와 로컬 보조를 같은 입력, 완료 조건으로 비교한다.
3. 근거 누락, 허위 주장, 실패 복구, 전체 클라우드 사용량, 완료 및 사람 검토 시간, 장비 부담을 기록한다.
4. 일반 코드 기준선보다 추가 이득이 없거나 필수 동작을 훼손하면 보류한다. 수치 기준은 기준선 확인 뒤 합의한다.

상세 평가 방식은 [학습 문서 12절](../../explanations/local-ai.md)에 둔다. 이번에는 문서만 작성했으며 모델 호출, 설치, 개발 자산 변경은 하지 않았다.

## 근거

OpenAI는 전통적 코드로 충분한 작업에서 LLM을 기본 선택하지 말라고 설명하고, Anthropic은 단순한 구성에서 시작해 필요할 때 복잡성을 늘릴 것을 권한다. 이 자료는 B의 효과를 입증하지 않으며 A와 비교하고 범위를 좁혀야 한다는 설계 근거다. [OpenAI 지연 최적화](https://developers.openai.com/api/docs/guides/latency-optimization), [Anthropic agent 설계](https://www.anthropic.com/research/building-effective-agents)

현재 구조에 대한 제약은 [구조 감사](../../discussions/architecture/baseline-audit.md), [검증 계약 초안](../../design/workflow/verification.md), [이식성 ADR 0004](../architecture/0004-portability.md)를 따른다. 모두 상세 설계, 검증이 끝났다는 의미는 아니다.
