# ADR 0015: AI 도구 지원 범위

- 날짜: 2026-11-02
- 설계 상태: `accepted` — 2026-11-02 B의 공통 책임 분리, Codex 우선 검증 원칙 채택
- 구현 및 검증: 공식 문서, 로컬 설치 메타데이터 확인만. 경로 이전, 설치, 새 세션 호환성 시험은 하지 않음
- 상세와 출처: [AI 도구, WIKI 검토 — 「AI 도구 호환성」](../../discussions/integration/ai-tools.md)

## 문제

사용자는 Codex 외 Claude, Gemini와 향후 로컬 AI까지 확장 가능한 구조를 원한다. 현재 `.codex` 경로와 도구 전용 hook을 그대로 공통 규격으로 보면 이식 시 발견, 권한, 이벤트, 재개가 어긋날 수 있다. 반대로 모든 도구를 첫 배포부터 지원하려면 현재 일정, 사용량 안에서 검증할 범위가 크게 늘어난다.

공식 문서에서 Codex/Gemini의 `.agents/skills`와 Claude Code의 `.claude/skills`, 도구별 hook 설정과 이벤트 차이를 확인했다. 공통 Agent Skills 형식과 모든 도구의 기능 호환은 다르다. 현재 세션에 `.codex/skills`가 제공된 관측만으로 다른 버전의 자동 발견을 보장하지 않는다.

## 대안

| 안 | 쉬운 설명 | 장점 | 단점 |
| --- | --- | --- | --- |
| A | Codex 전용으로 먼저 완성하고 필요해질 때 구조 분리 | 첫 구현이 작고 현재 도구에 집중하기 쉬움 | 전용 경로, 상태, 명령 결합을 남기면 다음 도구를 넣을 때 다시 손볼 범위가 커짐 |
| B | 공통 규칙, 데이터와 도구 연결을 구분하고 Codex부터 검증 | 재사용 목표를 보존하면서 초기 시험 범위를 제한 | 초기 경계 설계가 필요하고 두 번째 도구를 시험하기 전에는 공통성도 가설이 남음 |
| C | 처음부터 Codex, Claude Code, Gemini CLI와 로컬 실행을 모두 구현 | 여러 도구의 차이를 일찍 확인 | 설치, 권한, 실패, 복구, 모델 품질 조합이 늘어 첫 배포와 백엔드 적용을 지연할 위험 |

## 추천

B를 추천한다. 규칙, 프로젝트 지식, 검증/재개 기록은 공통 계약으로 유지하고 경로, 호출, hook, 권한의 차이를 작은 연결부가 맡게 한다. 첫 실제 지원은 기존 환경의 Codex로 제한하고 추가 도구는 같은 핵심 시나리오를 통과한 뒤 지원한다. 아직 필요 없는 범용 실행기, 모델 자동 전환기, 상주 서버를 새로 만들지 않는다.

`.agents/skills`는 공통 형식의 skill을 배치할 유력한 후보지만 `.codex` 전체를 그 이름으로 바꾸거나 Claude 지원까지 완료했다고 선언하지 않는다. 공통 원본은 한 곳에서 관리하고 필요한 배치/연결만 도구별로 적용하는 수단을 후속 설치 설계에서 비교한다.

## 채택 — 2026-11-02

사용자는 남은 기한과 난이도를 고려해 B안으로 진행하는 데 동의했고, 같은 이유로 B를 채택했다. 공통 계약과 도구별 연결을 구분하되 첫 구현, 검증은 Codex에 집중한다. 정확한 경로, 버전, 설치 수단, 다른 도구의 지원 시점, 로컬 AI 도입은 이번 채택에 포함하지 않는다. 구현 순서는 기존 진행표를 유지한다.

11/09 사용자는 첫 필수 배포를 우선하더라도 특정 플랫폼, 모델, 구조에 갇히지 않고 SOLID를 적용해 확장하기 쉬운 경계를 항상 유지하도록 재확인했다. [확장을 위한 경계](../../design/architecture.md)에 공통 정책, 연결부, 프로젝트 입력의 책임과 교체 검증 기준을 통합했다. 첫 지원 제한을 나중에 전부 분리해도 된다는 A안으로 되돌리지 않으며 미사용 연동의 선행 구현으로 확대하지 않는다.

## 남은 조건과 구현 순서

- 11/02 채택 전의 조건부 질문에서는 구현 순서만 재확인했고, 이후 명시적 진행 동의로 위 원칙을 채택했다. 도구 연결부부터 먼저 구현하지 않는다. 남은 저장, WIKI, 원문 보존 요구를 검토하고 진행표의 검증/복구 계약, 파일별 변경 명세에 반영한 뒤 개발 준비와 작은 실행 흐름 구현으로 이어간다. 실제 시험에서 새 제약을 발견하면 영향 범위의 설계를 다시 확인하되, 재수정이 전혀 없다고 보장하지 않는다.
- B의 원칙과 Codex 우선 검증 범위는 채택했다. 정확한 경로, 도구 버전, 설치 수단, 추가 도구 순서는 아직 확정하지 않는다.
- 도구 지원 확대와 로컬 AI 보조, 로컬 메인 전환, 동시 다중 작성자 기능을 각각 구분한다.
- 필수 기능이 없는 도구는 미지원 또는 승인한 제한 기능으로 표시한다. 명령을 호출할 수 있다는 이유로 같은 복구, 품질을 보장하지 않는다.
- 도구/버전, 환경, 기능별 지원 근거, 원문 보존과 중복 실행 방지, 실패 검사, 재개 상태의 보존을 확인한다.
- 도구 지원 원칙의 채택이 실행 환경, WIKI 범위를 대신하지 않는다. 현재 범위와 후속 합의는 [ADR 0020](../runtime/0020-windows.md), 0014, [0016](../knowledge/0016-storage.md)을 따른다. 11/02 당시 미합의였던 항목을 이후에도 모두 미합의로 고정하지 않으며 개인 대화 export는 별도 기술 검토 작업이다.

이 ADR의 채택만으로 로컬 모델 도입, 새 구독/과금, 제품 파일 변경을 승인한 것으로 해석하지 않는다.
