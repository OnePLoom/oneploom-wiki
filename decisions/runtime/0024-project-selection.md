# ADR 0024: 현재 프로젝트 우선과 실행별 프로젝트 선택

- 날짜: 2026-11-23
- 설계 상태: `accepted` — 사용자가 현재 프로젝트 안에서는 바로 시작하고 밖에서는 목록에서 선택하는 추천안을 채택했다.
- 구현 및 검증: 선택 정책에 이어 명령, 목록 파일/소유와 오류 형식을 명세했다. 제품의 목록 저장, 선택 화면, 동시 실행과 Windows 검증은 미완료다.
- 관계: [표준 명령 등록](0023-command-registration.md)과 [프로젝트 내 실행](0019-project-install.md)을 유지하고, 등록된 프로젝트를 선택하는 흐름을 추가한다.
- 상세: [여러 프로젝트의 선택과 실행](../../design/runtime/entry.md), [명령과 사용자별 목록](../../design/runtime/project-selection.md), [수용 입력 — 「여러 프로젝트 선택의 검증 입력」](../../verification/acceptance.md).

## 문제와 근거

기존 설계는 A/B 프로젝트를 각각 사용할 수 있지만 프로젝트 밖에서는 경로를 명시해야 했다. 사용자는 여러 프로젝트를 번갈아 또는 서로 다른 창에서 작업하므로, 어느 위치에서든 등록된 프로젝트 중 하나를 선택하는 편의도 원한다. 프로젝트별 하네스와 WIKI를 하나의 전역 연결로 합치는 요구는 아니다.

[zoxide의 공개 사용법](https://github.com/ajeetdsouza/zoxide#getting-started)은 경로 지정과 대화형 선택을 함께 제공한다. [Docker contexts](https://docs.docker.com/engine/manage-resources/contexts/#use-a-different-context)는 저장된 기본 대상과 명령별 대상 지정을 구분한다. 이는 동작이 존재하는 참고 사례이며 OnepLoom의 Windows 호환/무손실을 증명하지 않는다. 코드나 의존성을 복사/편입하지 않았고 자동 빈도 선택이나 전역 활성 대상 전환도 가져오지 않는다.

## 대안과 결정

| 대안 | 이점 | 비용과 판단 |
| --- | --- | --- |
| 현재 위치 또는 명시 경로만 사용 | 별도 목록 관리 없이 대상이 분명함 | 기존안. 프로젝트 밖에서 경로 입력/이동이 필요 |
| 언제나 등록 목록에서 선택 | 같은 화면으로 모든 프로젝트에 접근 | 이미 프로젝트 안에 있어도 반복 선택. 자동 실행과 입력 대기의 구분 필요 |
| 현재 프로젝트 우선, 밖에서는 선택, 명시 선택도 제공 | 평소 빠른 시작과 위치 독립적인 선택을 함께 제공 | **채택**. 사용자별 목록, 이동/삭제/손상과 동시 등록 처리가 추가됨 |
| 마지막으로 선택한 프로젝트를 PC 기본값으로 사용 | 입력을 줄일 수 있음 | 다른 창/프로젝트가 뜻하지 않은 대상을 사용할 수 있어 채택하지 않음 |

목록은 프로젝트 루트를 찾는 보조 자료로 두고, 선택한 프로젝트의 설정을 다시 확인한다. 선택 결과는 해당 실행에만 전달하며 전역 활성 프로젝트나 기본 WIKI를 변경하지 않는다. 미설치/손상된 현재 프로젝트, 잘못된 명시 대상과 대상 밖의 실행을 구별한다. 한 요청에 여러 프로젝트를 일괄 실행하거나 기존 대화의 프로젝트를 바꾸는 기능은 추가하지 않는다.

## 비용과 보호 조건

- 사용자별 로컬 목록을 보관하지만 프로젝트 Git과 Codex 전역 설정에는 넣지 않는다. WIKI/권한/진행 DB/세션 정보를 복제하지 않는다. 후속 명세에서 사용자 로컬 앱 데이터의 `OnepLoom/projects.json`에 루트 문자열 배열만 두고 목록 관리 명령, 실패와 중단 처리로 연결했다. 실제 저장 성공을 확인한 것은 아니다.
- 삭제/이동된 경로, 동명 clone/worktree, 선택 중 목록 변경, 저장 중단/동시 갱신을 처리해야 한다. 목록이 실행 허가나 설치 상태의 증명은 아니다.
- 현재 위치/명시 경로 시작은 목록에 의존하지 않는다. 목록 제거는 프로젝트나 WIKI 삭제가 아니며 목록 오류로 설치를 초기화하지 않는다.
- 선택은 일반 코드가 수행한다. AI 호출이 필요하지 않지만 실제 시작 시간과 유지보수 비용은 미측정이다.

## 확인할 조건

A/B를 서로 다른 창에서 열어 각 프로젝트와 WIKI가 유지되는지, 대상 밖/명시 선택/잘못된 대상/미설치/비대화형 실행의 분기가 맞는지 확인한다. 목록의 실패와 변경이 정상 프로젝트 실행을 막거나 다른 대상을 선택하지 않는지도 검증한다. 같은 WIKI를 공유하는 경우 기존 동시 편집 보호가 별도로 적용돼야 한다. 설계 채택과 정적 문서 검사를 실제 Windows 동작의 성공으로 보고하지 않는다.
