# ADR 0008: 배포에 필요한 문서 범위

- 날짜: 2026-10-27
- 채택: 2026-10-29, 사용자 확인
- 설계 상태: `accepted` — B의 최소 역할, 프로젝트별 연결 원칙
- 구현 및 검증: 구현과 검증 모두 미완료
- 상세: [모듈 경계 검토](../../design/README.md)

## 문제와 근거

현재 문서 트리는 애플리케이션의 계약, 설명, 학습, 작업 기록 관례를 함께 담는다. 이를 모두 복사하면 재사용 도구가 특정 프로젝트의 문서 체계까지 강제한다. 반대로 `guides`, `contract`를 불필요한 폴더로 보고 그대로 삭제하면 유효한 계약, 근거가 사라질 수 있다.

[기준 구현의 관측 (docs 분류)](../../discussions/architecture/baseline-audit.md)와 [기준 구현의 관측 (guides 기준)](../../discussions/architecture/baseline-audit.md)을 확인했고, 구현 검증, 거버넌스, 복구 자동화의 고정 경로 의존도 확인했다. 실제 의존 관계와 파일별 처리 후보는 상세 문서에 둔다. 경량화는 기본 읽기, 유지 부담 감소를 목표로 하며 폴더 감소만으로 토큰 절감을 확정하지 않는다.

## 대안

| 안 | 설명 | 장점 | 단점 |
| --- | --- | --- | --- |
| A | 현재 문서 트리를 공통 템플릿으로 유지 | 이전 비용이 적고 익숙한 경로 | 불필요한 문서, 갱신 규칙과 제품 지식까지 전파 |
| B | 최소 정보 역할과 프로젝트별 경로 연결 | 기존 계약 보존, 가벼운 도입, 문서 구조 선택 가능 | 분석, 매핑, 누락 판정 필요 |
| C | 지침과 WIKI를 소수 파일로 통합 | 초기 이해, 설정이 쉬움 | 정책, 상태 혼합, 전체 읽기, 충돌 비용 증가 가능 |

## 채택과 비용

B를 2026-10-29에 채택했다. 사용자는 전체 구조 복사와 소수 파일 통합보다 최소 역할을 제공하고 프로젝트별로 필요한 기능을 사용하는 방향에 동의했다. 공통 모듈에는 필요한 코드, 연결부, 최소 템플릿을 두고, 프로젝트가 이미 가진 요구사항, 계약, 결정, 복구 자료를 연결한다. 특정 폴더명이나 frontend/backend/shared 문서 세트를 공통 의무로 삼지 않는다. 빈 폴더, 문서를 일괄 생성하지 않는다.

이번 채택은 구조 원칙에 한정한다. 상세 구성표의 모든 항목, 필수 기능 목록, 저장소 운영, 설치 수단, 지원 환경까지 일괄 승인한 것으로 해석하지 않는다. 최초 선택과 이후 사용자 요청에 따른 기능 추가 요구는 [모듈의 기능 선택 — 「기능 선택과 추가」](../../design/module.md)에 기록하고, 배포 수단은 별도 [ADR 0010](../runtime/0010-distribution.md)의 11/11 채택 범위를 따른다.

`explainers`, 현재 `platform.md`, `contract`, `guides`, `learn`의 기존 내용은 기본 배포 대상에서 제외하는 방향이다. **각 역할이 불필요하거나 현재 앱에서 삭제해도 된다는 결론은 아니다.** 계약, 요구사항, 결정, 복구 기능은 실제 사용처와 게이트까지 보존, 대체해야 한다. 모듈 자체의 사용, 기여 문서는 설치 대상 프로젝트에 복사할 WIKI와 구분한다.

10/30 시스템 날짜의 후속 명확화: 사용자는 `explainers`, `learn` 등의 역할을 처음/나중에 선택 추가하고 기존 안내, 절차에 연결하려는 뜻이라고 설명했다. 기본 제외는 후속 확장 금지가 아니며 기존 문서를 공통 템플릿으로 복사하는 뜻도 아니다. 확장과 실행 선택의 구분은 [ADR 0014 — 「후속 협의: 문서 확장과 작업 위임」](0014-features.md), 상세는 [모듈 — 「선택 확장과 실행 방식」](../../design/module.md)을 따른다. 이 ADR의 기존 채택 원칙은 유지한다.

경로 유연성은 매핑을 확인하는 비용을 만든다. 기존 문서, 도구 설정에서 찾고 필요한 보정만 받으며, 모든 값을 새 설정에 복제하거나 작은 역할마다 모듈을 만들지 않는다.

## 문서 내용 분할의 후속 후보

11/08 상세 복원과 품질 우선 조건을 확인한 뒤 내용 구성, 템플릿, 라우팅을 비교했다. [문서 구성](../../design/knowledge/documents.md)은 한 문서 중심 / 색인과 기능별 상세 / 코드 디렉토리별 분할 중 **짧은 공통 요구, 색인과 기능/흐름별 상세**를 추천한다. 기존 문서 구조를 존중하고 공통 계약, ADR 원본을 연결해 상세함과 조건부 읽기를 함께 유지하려는 안이다. 문서 수 증가와 연결 관리 비용이 남는다.

11/08 당시에는 미채택이었으나, 11/09 [ADR 0014의 채택 범위 — 「이번에 확인할 범위」](0014-features.md)에서 공통 요구/색인, 기능별 상세와 분할 상세 복원, 완료 기준을 채택했다. 이 ADR의 기존 최소 역할 원칙은 유지한다. 상세 템플릿, 고정 경로/필드, 제품 구현과 기존 파일 이동까지 승인한 것은 아니다.

## 채택 후 확인

- 유지할 정보 역할과 선택 자료를 합의하고 파일별 사용처, 대체 연결을 작성한다.
- 문서 경로가 다른 프로젝트에서도 필요한 검증, 복구가 빠지지 않아야 한다.
- 기존 편집, 근거 보존과 빈 프로젝트 초기화를 각각 시험한다.
- 실제 탐색, 읽기, 갱신 부담과 토큰 변화는 측정 전 성과로 주장하지 않는다.

이 ADR은 저장소 분리 수단을 확정하지 않는다. [ADR 0009](../architecture/0009-repositories.md)와 함께 논의하되 독립적으로 채택한다. 기존 개발 자산의 삭제, 수정은 아직 승인되지 않았다.

후속 [모듈, 설치](../../design/README.md)은 `discussions`, `decisions` 등의 유지 역할, 기본 제외 자원과 프로젝트별 참조, 함께 바꿀 skill/config/hook 소비 지점을 표로 정리한다. 기존 문서 내용은 배포 템플릿에 복사하지 않는다.
