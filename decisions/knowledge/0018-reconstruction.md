# ADR 0018: WIKI 분석의 실행 방식

- 날짜: 2026-11-08
- 설계 상태: `accepted` — 2026-11-08 B 기본 진입, 목록 선택, 범위 미리보기, 분할 원칙 채택. 11/23 완료 후 재실행의 상태별 보완 채택. 구현 상세와 로컬 도입은 별도
- 구현 및 검증: 공식 자료, 기존 설계, Codex 0.167.0 도움말과 오프라인 schema 확인. 실제 목록 조회, 제품 구현, 모델 실행, 품질/토큰, 조회 지연 비교 미실행
- 상세: [WIKI 생성과 보강](../../discussions/knowledge/reconstruction.md)

## 문제

코드, 기록에서 WIKI 후보를 만들려면 AI 분석과 범위, 원문 보존, 재개를 연결해야 한다. 사용자는 설치한 기능을 명시적으로 실행하고 정해진 절차를 재사용하려는 것이며, 매번 자연어로 작업 절차를 구성하는 사용성을 원하는 것이 아니다. 설치 script만으로 의미 분석이 끝나지는 않지만 실행 코드는 AI를 호출해 전체 작업을 관리할 수 있다. 처음부터 모든 실행기를 지원하면 첫 배포와 검증 부담이 커진다.

## 대안

| 안 | 구성 | 장점 | 단점 |
| --- | --- | --- | --- |
| A | 설치한 skill의 명시 호출 + 공통 실행 코드, 현재 Codex가 분석 진행 | 현재 모델, 인증, 도구 활용, 별도 AI 프로세스 불필요 | 대화/도구 순서에 의존, 필수 검사, 상태 전환은 코드로 제한해야 함 |
| B | 설치한 실행 명령이 단계, 검사, 저장, 재개를 관리하고 Codex 호출 | 대화 밖에서도 같은 절차, 진행, 실패를 직접 검사 가능 | 버전별 인자, 인증, 프로세스, 권한, 취소 처리 증가 |
| C | 모델 API 직접 실행 | 모델, 도구, 작업 진행 제어 자유도 | 별도 이용 조건, 도구 루프, 실패 처리 부담 |

수동 자료 전달, 로컬 직접 연결, UI/MCP까지 [실행 비교 — 「실행 방식」](../../discussions/knowledge/reconstruction.md)에서 함께 검토했다. 로컬/클라우드 배치는 진입점과 별도 선택이며 A를 로컬 지원 배제로 해석하지 않는다.

같은 기능을 문서로 만드는 실제 흐름은 [A, B, C 예시 — 「같은 작업으로 비교하는 A안, B안, C안」](../../discussions/knowledge/reconstruction.md), 제품의 실행 책임은 [설치한 작업 실행](../../discussions/knowledge/reconstruction.md)에서 설명한다. Codex SDK처럼 기존 에이전트를 제어하는 수단은 B 계열이며 SDK를 모두 C로 분류하지 않는다. 상시 서버, 대기열은 별도 선택이다.

## 채택 범위와 비용

**B를 첫 분석 경로로 채택한다.** 사용자의 진행 동의와 조회 주체에 대한 재확인 뒤, 일반 실행 명령을 기본 입구로 두는 범위를 확정했다. 일반 코드가 모델 목록을 조회해 사용자에게 선택을 받고, 경로와 작업 범위를 미리 보여준다. 모델 선택과 실행 범위 확인을 모두 마친 뒤 Codex를 비대화형으로 호출한다. 첫 연결은 Codex exec로 설계하되 정확한 명령, 언어, 지원 버전, 권한, 상태 schema는 구현 전에 구체화한다. 기존 WIKI의 최종 쓰기, 원문 대조, 검토 계약도 후속 명세 대상이다. CLI 호출 하나를 감싼 것만으로 품질, 보존, 복구가 해결되지는 않는다.

11/08 최초 A 추천은 첫 구현 부담을 줄이려는 판단이었으나 설치형 작업의 제어 책임을 충분히 구체화하지 못했다. 사용자 지적을 반영해 추천을 보정했으며 채택, 구현한 A를 번복하는 상황은 아니다. A도 script를 가진 자동화가 될 수 있다. B의 명령을 호출하는 skill을 붙인다면 같은 실행 코드의 선택 입구로 두고 별도 분석 절차를 복제하지 않는다. 첫 지원 여부는 협의한다.

B에서 사용하는 분석 지침/skill과 현재 AI CLI에서 B를 시작하는 skill은 [역할 구분 — 「B에서 skill이 맡는 역할」](../../discussions/knowledge/reconstruction.md)을 따른다. 시작 입구 추가를 A의 별도 분석 경로 구현으로 해석하지 않는다. B 내부의 기존 workflow 재사용도 파일별 연결로 확인해야 한다.

최종 모델, 프로젝트별 경로를 공통 코드에 고정하지 않는다. 실행기/모델을 바꿔도 범위, 출처, 후보, 검사, 적용 상태가 이어져야 한다. 저장된 Codex 설정을 사용하되 별도 실행에 현재 대화의 일시적인 모델 선택이 자동 승계된다고 가정하지 않는다. 실제 실행 조건, 지원 조합은 후속 검증에서 정한다. 로컬 도입과 협업은 [ADR 0006](../integration/0006-local-assist.md)의 미확정 상태를 유지한다.

11/08 [공식 목록 자동 조회 — 「모델 목록 조회」](../../discussions/knowledge/reconstruction.md)와 실행 호환, 품질 상태를 결합하고 자유 입력 없이 선택하는 원칙을 채택했다. 새 모델은 작은 시험, 품질 확인을 거쳐 사용하며 정확한 평가 기준, 예산은 후속 협의한다. 조회, 선택에 AI를 호출하지 않고 분석 시작과 분리한다. skill로 B를 시작하는 입구는 선택 후보이며, 그때 메인 AI가 요청을 해석하는 사용량까지 없어진다고 주장하지 않는다. 개발자의 모델명 수동 갱신은 줄지만 항상 최신, 실행 성공, 품질 동등성을 보장하지는 않는다. [B의 남은 부담 — 「B의 남은 부담과 확인」](../../discussions/knowledge/reconstruction.md)은 해결 완료가 아니다.

[복수 경로와 Enter 미리보기 — 「범위 선택」](../../discussions/knowledge/reconstruction.md), [기능별 분할 — 「분할과 문맥」](../../discussions/knowledge/reconstruction.md)의 방향도 채택했다. 공백은 현재 작업 폴더를 범위 후보로 정하며 전체 분석의 즉시 실행 허가가 아니다. 로컬도 [비대화형 실행 경로 — 「로컬의 자동 실행」](../../discussions/knowledge/reconstruction.md)가 가능하지만 도입, 품질, 기본 모델은 미확정이다. 이번 채택은 제품 구현이나 실제 모델 시험을 시작하라는 허가가 아니다.

## 완료 후 재실행

2026-11-23 사용자가 기존 요구/설계에 어긋나지 않는 조건으로 진행을 승인했다. 조건부 진입, 상세 복원/범위별 완료, 원문 보존, 검사 재사용, 로컬 기록/정리와 승인 경계를 대조한 뒤 **현재 상태 확인 후 필요한 범위만 보완하는 방식**을 채택했다. 상세 처리와 대안은 [완료 후 다시 실행하는 흐름](../../discussions/knowledge/reconstruction.md)이 소유한다.

재실행 차단은 보완을 막고 매번 전체 재생성은 유효 자료와 사용자 편집의 위험을 키운다. 채택안은 상태/근거 대조와 보관 비용을 감수해 기존 결과를 유지한다. 변경이 없고 재사용 조건이 충족되면 새 분석을 생략하되, 같은 입력의 명시적인 추가 검토도 허용한다. 중단 작업의 재개와 새 검토를 구분하고, 사람이 편집한 원문과 중요한 내용 모순을 임의 해결하지 않는다.

WIKI 결과 재사용을 자체 테스트 PASS 캐시로 확대하지 않으며 필요한 검사는 ADR 0002의 계약을 유지한다. 기존 코드/문서가 바뀌었으면 이전 후보 적용을 멈추고 영향받는 후보와 검증을 다시 확인한다. 별도 DB/상주 서비스, 매 개발 요청의 복원 절차나 자동 전체 덮어쓰기를 추가하는 결정이 아니다.

[설계 대조 — 「기존 설계와의 연결」](../../discussions/knowledge/reconstruction.md)와 [미실행 검증 입력 — 「완료 후 재실행의 검증 입력」](../../verification/acceptance.md)을 연결했다. 명령/필드와 실제 Windows 반영, AI 품질/비용, 중단 재개는 아직 구현/검증 전이다. 이전 공개 도구의 구현 사례나 문서 검사 PASS를 제품의 무충돌 보장으로 사용하지 않는다.

## 확인 조건

- 명시적 작업 호출만으로 합의한 절차가 실행되고, 준비, 분석, 검사, 적용 상태를 실행 코드가 구분한다. AI의 완료 문구, 정상 종료만으로 다음 상태를 허용하지 않는다.
- 코드 관측, 채택 요구, 당시 이유, 미확인을 구별하고 허용 밖 원문을 변경하지 않는다.
- 같은 범위에서 품질, 누락, 보존, 재개와 전체 비용을 평가한다. 연결/JSON 형식 PASS를 문서 품질 PASS로 대체하지 않는다.
- 한도, 네트워크, 사용자 중단, 세션 소실, 동시 원문 변경에도 미완료와 보호 대상을 복구한다. provider 세션 ID만 저장하지 않는다.
- 범위/비용, 새 공급자, 자동 채택을 임의 확대하지 않는다. 한도 알림, 자동 모델 변경을 복구 전제로 두지 않는다.
- 목록 조회 실패, 계정/버전 변경, 사라진 모델, 미검증 모델을 실행/품질 성공으로 표시하지 않는다. 조회만 하는 경로와 사용량이 발생하는 실행 시험을 분리한다.
- 여러 입력의 중복, 제외, 프로젝트 밖 의존과 Enter의 후보 범위를 보여준다. 단위별 완료와 전체 연결 검사를 구별하고 중단된 단계부터 입력 대조 후 재개한다.
