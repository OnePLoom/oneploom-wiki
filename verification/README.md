# 제품 검증 계획

이 문서는 구현 후 확인할 수용 기준이다. **아래 사례는 아직 제품에서 실행하지 않았으며 PASS가 아니다.** 문서와 로컬 Git의 준비 상태는 제품 기능 검증과 구분한다.

## 우선순위와 완료 기준

첫 구현은 입력 해석과 프로젝트 발견, 연결 및 직접 시작부터 진행한다. 이어 공식 배포 자료, 사용자별 명령 등록, 프로젝트 설치, WIKI 처리, 복구와 최소 PR 연계를 연결한다. 첫 실행 흐름 하나가 동작하더라도 필수 기능이 빠진 상태를 정식 첫 배포 완료로 표시하지 않는다.

| 영역 | 필요한 사례 | 판정 기준 |
| --- | --- | --- |
| 명령 해석 | 옵션 누락, 오타, 상충 옵션, help/version, 경로의 공백과 한글 | 잘못된 입력에서 쓰기나 Codex 실행 없음. 실행 경로를 임의 보정하지 않음 |
| 프로젝트 선택 | 루트/하위 경로, 프로젝트 밖, 여러 후보, 이동/삭제, 손상 목록, 동시 목록 변경 | 실행에 사용할 프로젝트가 하나로 명확하고 다른 프로젝트 파일과 설정을 변경하지 않음 |
| 실행본 인계 | 기본/지정 모듈 경로, 손상 공유 설정, 다른 Python, 호환 불가 코드 | 검증한 프로젝트 실행본에 인자와 콘솔을 전달하고 종료 상태 보존 |
| Codex 발견 | npm과 공식 Windows 설치, 둘 다 존재, PATH 변경, 업데이트 | 현재 사용자 설치본을 확인하고 전역 설정, 모델, 인증을 임의 변경하지 않음 |
| WIKI 연결 | 최초/팀원 연결, 경로 변경, 같은 ID의 다른 clone, 권한 부재, 다른 프로젝트 | 연결 설정과 실제 권한을 구별하고 저장된 범위를 안전하게 재사용 |
| 명령 등록 | 최초 등록, 재등록, 기존 명령 충돌, 다른 프로젝트에서 재사용, 등록 도중 중단, 제거 | 한 프로젝트 삭제가 계정의 공통 명령을 없애지 않으며 소유하지 않은 파일/PATH 보존 |
| 프로젝트 설치 | 기존 AGENTS/skill/script, 맞춤 경로, 준비물 부재, 중단 후 재실행 | 기존 자산을 덮지 않고 완료 단위의 유효성을 확인해 이어감 |
| WIKI 상세 복원 | 문서 없는/있는 프로젝트, 코드와 이력의 상충, 미확인 결정, 큰 범위 분할 | 실제 근거와 추론을 구분하고 처리되지 않은 범위를 완료로 표시하지 않음 |
| WIKI 재실행 | 같은 입력, 변경된 이력/코드, 사용자 문서 수정, 재분석 결과 상충 | 유효한 결과를 재사용하고 필요한 보강만 제안. 최신 AI 답으로 기존 사실을 덮지 않음 |
| 문서 연결 | 이동/이름 변경, 깨진 링크/제목, 역할 중복, 모호한 map | 필요한 경로를 찾고 무관한 문서를 강제로 전부 읽지 않음. 모호함을 누락 성공으로 숨기지 않음 |
| 검증 재시도 | 부분 실패, 공통 의존 변경, 원문 로그 정리, 결과 도착 지연 | 실패 검사와 영향을 받은 PASS만 다시 실행. 근거 없는 PASS 재사용 차단 |
| 세션 복구 | 문맥 압축, 중단, 오래된 active, 기록 없는 정상 단발 요청 | 실제 작업과 대조해 이어가며 정상 작업에서 전체 복구를 강제하지 않음 |
| DB와 외부 효과 | 기록 전후 종료, 잠금, DB 손상, 공간 부족, 파일 반영 후 기록 실패 | 상태를 성공 또는 빈 작업으로 꾸미지 않고 실제 효과를 대조 |
| 최초 DB 인계 | 원본/대상 확인, 수신 후 종료, 활성화 중단, 이전 사본 정리 | 한 활성 DB의 동일 이력을 이어 쓰며 관계없는 DB와 병합하지 않음 |
| 업데이트 | 공식 변경과 사용자 변경의 겹침, 일부 반영 실패, 재시도, 이전 구성 선택 | 사용자 편집 보존. 이전 구성 선택 시 이번 업데이트 전체 복원과 사용 가능 여부 확인 |
| 정리 | 현재 의존 자료, 완료 로그, 중도 실패, 반복 실행, 승낙한 목록과 실제 파일 변화 | 보호 자료 삭제 없음. 승인한 대상만 정리하고 이력과 정리 사실 보존 |
| Git/PR | 한쪽만 성공, 재실행, 새 커밋, 권한 부족, 병합 후 상태 | 중복/누락을 감추지 않고 실제 두 저장소의 조합과 상태로 판정 |

## 실제 실행 기록

실행할 때 날짜, 코드 버전, OS와 도구 버전, 선택 모델 및 설정, 입력 범위, 명령, 원문 결과, 판정과 한계를 남긴다. 실제 모델 요청 횟수와 내부 호출 수를 구분한다. 시간과 토큰 수치는 같은 비교 조건 및 반복 수를 함께 제시한다.

일부 도구 시험, 합성 입력 또는 다른 OS의 단위 검사만 통과했으면 해당 범위만 기록한다. 실패를 위해 넣은 조건과 제품 기본 조건을 구분한다. 기록을 작성하지 않은 제품 실행을 과거 실험에서 추정하지 않는다.

## 배포 전 남은 결정

정확한 최소 지원 버전, 최종 패키지 이름과 배포 자산, 저장 스키마와 마이그레이션, 라이선스와 고지, 원격 저장소의 공개 정책 및 CI 강제 조건을 확정하고 검사한다. 이 목록은 이미 채택한 첫 제공 기능을 다시 미채택으로 돌리는 뜻이 아니다.

실제 사용할 수 있는 명령이 준비되면 코드 저장소 README에 준비물, 설치, 첫 연결과 일상 사용, 중단 시 다음 행동을 짧게 제공한다. 깊은 구현 설명은 설계 문서에 둔다.

## 상세 입력과 예비 관측

[상세 수용 기준](acceptance.md)에는 시나리오별 입력, 중단 지점, 기대 결과와 미완료를 보존한다. [실제 관측](../evidence/README.md)은 그중 수행한 부분만 보여주며 제품 전체 PASS로 대신하지 않는다. 기록 의미와 SQL 제약은 [기록](../design/workflow/records.md), [저장](../design/workflow/storage.md), [유지 관리](../design/workflow/maintenance.md)에 연결한다.
